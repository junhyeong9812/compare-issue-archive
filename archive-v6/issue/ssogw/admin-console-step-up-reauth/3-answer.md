# issue/ssogw/admin-console-step-up-reauth — 이유·대안·이후 변경

태그: `audit` · `auth` · `admin-console`

## 답
1. **지적 3-2: 공용 단말에 남은 로그인 세션으로 정산 계좌 변경이 가능했다.** 개선 계획서(2024-11-28 제출)에 세 가지를 약속했다 — 자금 흐름을 바꾸는 작업은 작업 시점 본인 확인, 그 확인 시각을 감사 로그에 남김, 연 1회 이행 점검 자료(재인증 로그 표본) 제출.

2. **작업 종류별로 다르게.**
   - 정산 계좌·수수료율 변경, 관리자 권한 부여: 직전 10분 안에 OTP 재인증한 세션만 실행. 감사 로그에 재인증 시각을 함께 남긴다.
   - 가맹점 한도 변경: 건수가 많아 재인증 대신 2인 승인. 감사 로그에 승인자 둘을 남긴다.
   - 조회: 기존 8시간 SSO 세션.

3. **검토한 대안**

| 대안 | 기각 이유 |
|---|---|
| SSO 세션을 30분으로 단축 | 모든 사내 시스템이 영향, 콘솔 조회 업무까지 매번 로그인 — 운영팀·CS팀 반대 |
| 모든 콘솔 작업에 OTP | 한도 변경 하루 수십 건 — 업무 지연, 검사 지적 범위를 넘음 |
| 공용 PC 자동 로그아웃만 | 개인 PC 자리 비움은 못 막음 — 계획서 문구("작업 시점 본인 확인")를 충족 못 함 |

4. **이후 변경 시**
   - 지킬 것: 정산 계좌·수수료율·권한 부여는 작업 시점 재인증(시간 창 10분 이내)과 감사 로그의 재인증 시각. 한도 변경의 2인 승인. 이 둘을 빼거나 완화하려면 준법감시인 확인 후 계획서 변경 보고가 필요하다.
   - 바꿔도 되는 것: 재인증 수단(OTP 앱·하드웨어 토큰·생체), 조회 화면 구성, SSO 세션 길이(조회에만 영향), 재인증 안내 문구.

## 결과
- 2025-01 이행 완료 보고. 2025-10 이행 점검에서 재인증 로그 표본 제출, 추가 지적 없음.

# issue/logfwd/debug-log-sampled-ingest — 결제 API DEBUG 로그를 샘플링해서만 보내는 결정 — 맥락

## 당시 맥락 (2025-09 ~ 10)
- 서버 로그는 각 서버의 수집기(logfwd)가 로그 SaaS로 보낸다. 서비스 팀은 장애 분석 때 DEBUG 로그를 켜고, 원인을 찾으면 끄는 식으로 써 왔다.
- 2025-09-17 결제 API 배포에 DEBUG 켜짐 설정이 섞여 나갔고, 사흘 동안 하루 수집량이 1.1TB까지 올랐다(평시 180GB). 로그 SaaS 9월분 청구서에 초과 수집 요금이 따로 붙었다.
- 같은 달 "DEBUG는 아예 수집하지 말자"는 의견과 "장애 때 DEBUG가 없으면 결제 실패 분석을 못 한다"는 의견이 맞섰다.

## 질문
1. 로그 SaaS 계약에서 수집량은 어떻게 과금되나?
2. 무엇을 정했나 — 어떤 로그를 전량 보내고 어떤 로그를 줄이나?
3. 검토했다가 버린 대안은 무엇이고 왜 버렸나?
4. 이후 "DEBUG 로그를 다 보고 싶다"는 요청이 오면 무엇을 지키고 무엇은 바꿔도 되나?

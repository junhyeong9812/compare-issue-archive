# issue/logfwd/debug-log-sampled-ingest — 이유·대안·이후 변경

태그: `cost` · `logging` · `vendor-contract`

## 답
1. **하루 300GB까지 정액, 초과분 GB당 단가 3배, 초과 일이 한 달에 3일을 넘으면 다음 분기 약정량 자동 상향.** 2025 로그 SaaS 계약 조건이다. 평시 하루 180GB라 여유가 있어 보였지만, DEBUG 한 서비스만 켜져도 하루 1TB를 넘는다.

2. **DEBUG는 요청 ID 기준 1/20 샘플링, 실패 요청은 전량.**
   - 샘플링은 요청 ID 해시로 해서, 뽑힌 요청은 그 요청의 DEBUG 로그가 처음부터 끝까지 다 들어간다(줄 단위 샘플링이 아님).
   - 결제 실패 요청은 샘플링과 무관하게 DEBUG까지 전량 — 장애 분석에 필요한 것은 대부분 실패 요청이다.
   - 서버 로컬에는 전량을 7일 남긴다. 그 이상 필요하면 서버에서 직접 가져간다.

3. **검토한 대안**

| 대안 | 기각 이유 |
|---|---|
| DEBUG 수집 전면 금지 | PG 오류 분석에 DEBUG(요청·응답 원문)가 필요 — 결제팀 반대 |
| 줄 단위 1/20 샘플링 | 한 요청의 흐름이 끊겨 분석에 못 씀 |
| 초과분 사전 구매 | 연간 약정 상향이 초과 요금보다 비쌈(재무 검토) |
| 배포 전 DEBUG 설정 검사만 추가 | 장애 대응 중 의도적으로 켜는 경우는 못 막음 — 검사는 함께 두되 샘플링을 기본으로 |

4. **이후 변경 시**
   - 지킬 것: 로그 SaaS로 가는 DEBUG는 실패 요청 외에는 샘플링된 요청만. 하루 수집량이 300GB를 넘을 수 있는 변경은 플랫폼팀 확인.
   - 바꿔도 되는 것: 샘플링 비율(수집량 여유 안에서), 실패 요청 판정 조건, 로컬 보관 기간, 특정 기간 특정 요청 ID 전량 수집(장애 티켓 단위).

## 결과
- 10월 이후 하루 수집량 190~240GB, 초과일 0.
- 장애 분석 시 "샘플에 안 걸린 성공 요청" 로그가 필요할 때는 서버 로컬에서 꺼낸다.

# issue/filegw/no-auto-resend-after-ack — 이유·대안·결과

태그: `incident-recurrence` · `partner-file` · `resend`

## 이유 상세
1. **사건(2024-12-30).** 원천 시스템이 청약 일일 파일을 재생성(필드 정정 1건)하자 filegw가 같은 이름으로 자동 재전송. 보험사 A의 적재기는 이미 처리한 파일명을 기억하지 않고 디렉터리에 새로 나타난 파일을 모두 처리해, 전날 청약 87건을 다시 등록했다. A 쪽 수작업 취소에 이틀.
2. 제휴사 7곳에 확인한 결과 4곳이 같은 방식(파일명 기억 없음)이었다.
3. ack 이전 재전송은 상대가 아직 가져가지 않은 상태라 사건과 무관했다.

## 검토한 대안
| 대안 | 기각 이유 |
|---|---|
| 제휴사마다 중복 처리 방지 요청 | 7곳 일정이 제각각, 1년 넘게 걸린다. |
| 재전송 전 상대 디렉터리에서 기존 파일 삭제 | 권한 없는 제휴사가 대부분. 삭제해도 이미 처리된 건은 그대로. |

## 결과
- 2025-01-13 배포. 이후 중복 처리 사고 없음. 정정 파일은 월 2~3건, 당직 승인으로 처리.

## 이후 변경 시
- **지켜야 할 것**: ack 받은 파일은 같은 이름으로 다시 보내지 않는다(자동·수동 모두).
- **바꿔도 되는 것**: ack 전 재전송 정책, 정정 파일 이름 규칙(제휴사와 합의 시), 승인 절차 도구.

## 검증 기록
- 2026-10-10: 가상 아카이브 작성(Claude 초안, 실험 5차-b)

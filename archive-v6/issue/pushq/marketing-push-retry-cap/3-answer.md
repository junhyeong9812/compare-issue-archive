# issue/pushq/marketing-push-retry-cap — 이유·대안·결과

태그: `incident` · `retry` · `push`

## 이유 상세
1. 게이트웨이는 접수 후 응답이 늦을 뿐 실제로는 발송하고 있었다. 큐는 타임아웃을 실패로 보고 재시도했다.
2. 마케팅 푸시는 늦게 가거나 안 가도 손해가 작지만, 중복으로 가면 수신 철회로 이어져 이후 모든 마케팅 채널을 잃는다.
3. 게이트웨이 벤더는 중복 제거 키를 지원하지만 마케팅 대량 발송 API에는 적용되지 않는다.

## 검토한 대안
| 대안 | 기각 이유 |
|---|---|
| 재시도 0회 | 순간 오류에도 캠페인 전체가 빠짐 |
| 타임아웃 늘리기 | 이번처럼 40분 지연에는 효과 없음 |
| **2회 + 10분 간격** | 채택 |

## 결과
- 2025-07-21 적용. 이후 게이트웨이 지연 2회 발생, 중복 수신 민원 0건.

## 이후 변경 시 지켜야 할 것
- 마케팅 푸시의 재시도 횟수를 늘리지 않는다. 타임아웃을 '실패'로 보고 즉시 다시 보내는 경로를 새로 만들지 않는다.

## 바꿔도 되는 것
- 거래 알림의 재시도 정책, 발송 시간대, 리포트 형식.

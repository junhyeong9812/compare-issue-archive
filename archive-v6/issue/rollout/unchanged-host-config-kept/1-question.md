# issue/rollout/unchanged-host-config-kept — 값이 같은 서버의 설정 파일을 다시 쓰지 않는 결정 — 맥락

## 당시 맥락 (2025-06 ~ 07)
- 결제 서버 앱 설정 배포 도구(rollout)는 릴리스마다 모든 활성 서버의 `app.conf`를 새로 만들어 배포 디렉터리에 썼다. 파일 첫 줄 헤더에는 이번 릴리스 id가 들어갔으므로, 값이 바뀌지 않은 서버의 파일도 매번 내용이 달라졌다.
- 각 서버의 설정 에이전트(hbp-agent)는 1분마다 이 파일의 sha256을 비교해, 바뀌면 앱을 graceful restart 한다. 앱은 설정 다시 읽기를 지원하지 않는다.
- 2025-06-11 14:02 배포(로그 레벨 한 줄 변경)에서 전 서버(약 60대)가 같은 1분 안에 재기동했다. 그달 pay-db(매니지드 PostgreSQL) 최대 동시 커넥션이 1,310으로 기록됐고, DB팀이 7월 초 정산서를 보고 플랫폼팀에 공유했다(OPS-1874).

## 질문
1. pay-db 요금은 무엇을 기준으로 매겨지고, 한 번의 피크가 얼마 동안 영향을 주나?
2. 설정 파일 한 줄 헤더 변경이 왜 DB 커넥션 피크로 이어졌나(에이전트·앱 재기동·커넥션 풀의 연결)?
3. 무엇을 정했나 — 배포가 서버 설정 파일을 다시 쓰는 조건은?
4. 검토했다가 버린 대안은 무엇이고 왜 버렸나?
5. 이후 "배포 상태 표시"나 "헤더 형식"을 바꾸자는 요청이 오면 무엇을 지키고 무엇은 바꿔도 되나?

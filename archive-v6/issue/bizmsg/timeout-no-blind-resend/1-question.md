# issue/bizmsg/timeout-no-blind-resend — 알림톡 발송 타임아웃은 바로 재발송하지 않는다 — 맥락

## 당시 상황 (2025-08)
- 결제 서비스는 결제 완료·취소 안내를 메시지 중계사 bizmsg 경유 알림톡으로 보낸다. 발송 API가 응답하지 않으면 5초 타임아웃 뒤 같은 내용을 한 번 재발송하도록 되어 있었다.
- 2025-08-22 저녁 bizmsg 중계 지연(약 40분) 동안, 결제 완료 알림톡이 고객에게 두 통씩 도착했다. "결제가 두 번 됐다"는 환불·취소 문의 230건, 일부 고객은 카드사에 이의 제기(BZ-077).
- 실제 결제는 한 번이었다. 재발송한 건이 원래 건과 거의 같은 시각에 도착했다.

## 당시 질문
1. 타임아웃이 났는데 왜 원래 메시지도 도착했나? bizmsg의 타임아웃은 무엇을 뜻하나?
2. 재발송 전에 "원래 건이 나갔는지"를 확인할 방법이 있나? 언제부터 확인할 수 있나?
3. 결제 안내가 늦게 가는 것과 두 번 가는 것 중 무엇이 더 나쁜가?
4. 이후 다른 안내(배송·포인트)에도 같은 규칙을 적용해야 하나?

# issue/bizmsg/timeout-no-blind-resend — 이유·대안·결과

태그: `decision` · `incident-recurrence` · `messaging`

## 이유 상세

1. **타임아웃은 응답 지연일 뿐이다.** bizmsg는 접수 큐에 넣은 뒤 카카오 쪽 전달 결과를 기다렸다가 응답한다. 중계 지연 중에는 5초 안에 응답하지 못하지만 접수는 이미 끝난 상태다. 그래서 원래 건과 재발송 건이 둘 다 나갔다.
2. **결과 조회는 접수 60초 뒤부터다.** 결과 조회 API는 메시지 키로 `SENT`·`FAILED`·`PENDING`을 돌려준다. 60초 전에는 접수 여부와 관계없이 `NOT_FOUND`라, 이것을 실패로 읽으면 같은 사고가 난다.
3. **두 번 가는 쪽이 더 나쁘다.** 결제 안내가 늦으면 문의가 조금 늘지만, 두 번 가면 이중 결제로 오인해 환불 요청·카드사 이의 제기까지 간다(BZ-077 처리 비용이 지연 문의의 수십 배).
4. **같은 중계사를 쓰는 모든 안내에 적용한다.** 배송·포인트 안내는 늦어도 되므로 같은 규칙에 무리가 없다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| 타임아웃을 30초로 늘림 | 중계 지연은 수십 분 단위라 효과 없음. 결제 응답도 늦어짐 |
| 재발송 시 같은 메시지 키 재사용(중계사 중복 제거) | bizmsg는 메시지 키 중복 제거를 하지 않는다(벤더 확인) |
| 타임아웃 시 SMS로 대체 발송 | 알림톡과 SMS가 둘 다 도착. 같은 사고 |
| 결과 조회 후 FAILED만 재발송 (채택) | 늦어도 최대 10분, 중복 없음 |

## 결과
- 이후 중계 지연 3회(2025-11, 2026-02, 2026-05) 동안 이중 발송 0건.

## 이후 변경 시
- **지켜야 할 것**: 결과가 `SENT`·`FAILED`로 확정되기 전에는 재발송하지 않는다. `NOT_FOUND`(60초 전)를 실패로 읽지 않는다.
- **바꿔도 되는 것**: 조회 간격, 최대 대기 시간, 확정 실패 뒤 SMS 대체 여부.

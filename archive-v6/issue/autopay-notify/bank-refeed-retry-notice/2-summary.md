# issue/autopay-notify/bank-refeed-retry-notice — 결정 요약

태그: `decision` · `incident-recurrence` · `external-feed`

## 결정 (2025-04-14, 알림 서비스 1.9.0)

재출금 안내는 **재출금 한 회차에 한 번만** 보낸다. 당시 구현은 재출금 안내의 업무 키를 "계약 + 재출금 날짜"로 바꿔, 같은 계약의 재출금 안내가 하루 한 건만 예약되게 했다.

## 핵심 이유 한 줄

뱅크허브는 응답이 늦으면 **같은 실패를 3~6분 간격으로 최대 3회 다시 통보하고, 다시 보낸 통보의 실패 시각은 재통보 시각**이다. 알림 서비스가 이를 새 실패로 보고 재출금 안내를 세 번 보냈다(CS-2291).

## 흐름

```
뱅크허브 ──실패 08:00:37──▶ billing-core: 재출금 10:00:37 잡음
         ──재통보 08:03:52─▶ billing-core: 재출금이 잡혀 있음 → 무시
         ──재통보 08:09:15─▶ billing-core: 무시
         (같은 세 통보) ───▶ 알림 서비스(1.8.x): 실패 3건으로 봄 → 안내 3건(재출금 10:00 / 10:03 / 10:09)
```

## 지켜야 할 것 / 바꿔도 되는 것 (요약)

- 지켜야 할 것: 잡힌 재출금이 아직 실행되기 전에 들어온 실패 통보는 같은 실패의 재통보다. 이것으로 안내를 새로 만들거나 기존 안내를 옮기지 않는다.
- 바꿔도 되는 것: "하루 한 건"이라는 묶음 단위 자체. 재출금 시각이 지난 뒤 들어온 실패(재출금 자체가 실패)는 새 회차다.

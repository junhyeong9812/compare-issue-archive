# issue/hbexpense/claim-detail-ledger-lookup-removed — 이유·대안·이후 변경

태그: `cost` · `vendor-contract` · `ledger`

## 답
1. **기장(post)과 기간 조회(list)는 월 기본료에 포함, 전표 단건 조회(show)는 호출 1회당 25원 별도.** 원장 벤더 계약 부속 2의 정산서 항목이다(그 밖에 저널 보관 초과 10GB 단위). 단건 조회 단가는 2024년 재계약 때 기본료를 낮추는 대신 생긴 항목이라, 단건 조회를 많이 쓰는 시스템이 생기면 바로 정산서에 드러난다.

2. **화면 수 × 청구 수 × 갱신 주기만큼 호출이 났다.** 상세 화면은 열려 있는 동안 30초마다 새로 고쳤고, 새로 고칠 때마다 청구 1건당 단건 조회 1회가 나갔다. 정산 주간에 수백 명이 화면을 띄워 두자 하루 수만 회가 됐다. 결과가 바뀌지 않는(이미 기장된) 청구도 계속 조회됐다. 목록 화면에 같은 표시를 붙였다면 화면 한 번에 청구 수만큼 호출이 났을 것이다.

3. **서비스 경로의 단건 조회 0회, 원장 상태는 기간 조회로.**
   - 서비스 설정에서 단건 조회를 기본으로 끈다. 켜는 것은 재무 대사 데스크 도구뿐이다.
   - 월말 리포트는 원장 기간 조회 결과로 만들고, 정산 실행 뒤 한 번 다시 읽는다.
   - "기장됐는가"는 해당 기간 조회 결과에 그 영수 번호가 있는가로 판단한다. 보류된 전표는 기간 조회에 나오지 않으므로 이것만으로 기장/미기장을 가를 수 있다. 보류 사유 같은 단건 상세가 필요하면 대사 데스크로 넘긴다.

4. **검토한 대안**

| 대안 | 기각 이유 |
|---|---|
| 단건 조회 유지 + 갱신 주기를 5분으로 | 호출 수가 1/10이 될 뿐 화면·청구 수에 비례하는 구조는 그대로. 목록 화면 요청을 받을 수 없다 |
| 정산 직후 청구마다 단건 조회 1회로 상태 저장 | 정산 건수만큼 매월 과금, 보류가 나중에 풀리는 경우를 못 따라감 |
| 벤더와 단건 조회 정액제 협상 | 2025-04 벤더 회신: 다음 재계약(2027) 전에는 불가 |
| 원장 확인 표시 자체를 영구 제거 | 직원 문의가 재무팀으로 몰림 — 기간 조회 기반이면 비용 없이 가능하므로 제거는 상세 화면의 단건 조회 방식에 한정 |

5. **이후 변경 시**
   - 지킬 것: 서비스가 처리하는 어떤 요청에서도 원장 단건 조회를 부르지 않는다(설정으로 다시 켜거나, 다른 경로로 우회 호출하는 것 포함). 원장 반영 여부는 기간 조회 결과로 판단한다.
   - 바꿔도 되는 것: 기간 조회를 부르는 횟수·범위(월 단위, 하루 단위 등 — 기본료 안), 결과 캐시 여부, 화면에 보여 줄 상태 이름과 필드 구성, 리포트 형식.
   - 단건 조회 계약 조건이 바뀌면(정액제 등) 이 결정을 다시 연다 — 재무 원장 파트 확인 필요.

## 결과
- 2025-04분부터 단건 열람은 월 1천 회 안팎(대사 데스크)으로 줄었다.
- 상세 화면의 원장 확인 표시는 빠졌고, 그 뒤 "영수 번호는 있는데 원장에 들어갔나" 문의가 재무팀에 남았다(후속 과제로 남김).

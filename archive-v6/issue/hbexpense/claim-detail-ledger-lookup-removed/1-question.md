# issue/hbexpense/claim-detail-ledger-lookup-removed — 경비 포털의 원장 단건 조회를 끈 결정 — 맥락

## 당시 맥락 (2025-04)
- 경비 정산 서비스(hbexpense)는 2025-01 릴리스(1.3.0)에서 청구 상세 화면에 "원장 확인" 표시(기장/보류)를 붙였다. 화면이 열려 있으면 포털이 30초마다 새로 고쳤고, 서비스는 그때마다 청구별로 원장 벤더 CLI의 전표 단건 조회(`ledgerctl show <영수번호>`)를 불렀다.
- 직원들은 정산 주간에 상세 화면을 띄워 두고 "기장" 표시가 뜨기를 기다렸다. 목록 화면에도 같은 표시를 붙이자는 요청이 대기 중이었다.
- 2025-03분 원장 벤더 정산서에서 "단건 열람" 항목이 768,140회, 1,920만 원으로 청구됐다(2월분 412,300회). 재무 원장 파트가 발생 시스템을 벤더에 요청해 받아 보니 대부분이 경비 포털이었다.

## 질문
1. 원장 벤더 계약에서 어떤 호출이 기본료에 포함되고 어떤 호출이 별도 과금인가?
2. 청구 화면의 원장 확인이 왜 단건 조회 폭증으로 이어졌나(화면 동작과 호출 수의 관계)?
3. 무엇을 정했나 — 서비스 경로에서 원장 상태를 확인하는 방법은 무엇으로 제한됐나?
4. 검토했다가 버린 대안은 무엇이고 왜 버렸나?
5. 이후 "청구 화면에 원장 반영 여부를 다시 보여 달라"는 요청이 오면 무엇을 지키고 무엇은 바꿔도 되나?

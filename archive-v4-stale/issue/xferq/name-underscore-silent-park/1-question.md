# issue/xferq/name-underscore-silent-park — 전송 CLI는 이름이 마음에 안 드는 파일을 거부하지 않고 묶어 둔다 — 질문

## 질문
1. (예측) `xferq send --to K01 --file f --as HBP_RECON_K01_20240814_R1.dat`는 exit 0과 접수 번호 `T…`를 돌려준다. 상대 수신함(`xferq ls --to K01`)에 이 파일이 나오는가? `xferq status <접수번호>`는 무엇을 보여 주는가?
2. (경계) 원격 이름 `HBP_RECON_K01_20240814.dat`, `HBP_RECON_K01_20240814_R1.dat`, `HBP_RECON_K01_20240814_R01.dat`, `_` 없이 아주 긴 이름, `A_B_.dat`는 각각 어떻게 되는가? 기준은 길이인가, `_` 개수인가, 마지막 필드인가 — 정확히 몇 글자부터인가?
3. (왜) 대사 파일 배치는 첫 전송분은 늘 잘 갔는데 재전송분만 카드사에 닿지 않았다. 실행 로그·종료 코드·접수 번호까지 정상이었는데 왜 재전송분만 빠졌나?
4. (경계) 이름이 길어서 그런 줄 알고 이름을 줄여 보낸 1차 조치는 왜 효과가 없었나? 재전송 표시를 `-R1`처럼 다른 구분자로 붙이는 방법은 왜 택하지 않았나?
5. (왜) 이미 묶인(st 6) 전송은 어떻게 되는가? 같은 내용을 올바른 이름으로 다시 보내면 무엇이 남는가?
6. (연결) "접수 번호를 받았다 = 상대가 받았다"로 보면 안 되는 이유는 무엇이고, 배치가 전송 완료를 판정하려면 무엇을 확인해야 하는가?

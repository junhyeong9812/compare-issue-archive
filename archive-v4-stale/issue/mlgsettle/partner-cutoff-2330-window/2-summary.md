# issue/mlgsettle/partner-cutoff-2330-window — 정리 (힌트)

태그: `contract-drift` · `single-source-of-truth`

## 전체 흐름

```
           6/3 00:00                       6/3 23:30   6/4 00:00          6/4 23:30
사내 대사    |========== 6/3 (달력일) ======================|
제휴 정산  ──────|=========== settle_date 6/3 ==============|====== settle_date 6/4 =====|
          6/2 23:30                                  6/3 23:30

23:30~24:00 적립분 → 사내는 D, 제휴사는 D+1
  D 리포트   : 사내 합계 > 제휴 합계  (+차이)
  D+1 리포트 : 사내 합계 < 제휴 합계  (-차이, 비슷한 크기)

월말(말일) 마감 = 22:00   → 22:00~23:30 구간이 한 번 더 밀린다
연말(12/31)  마감 = 18:00

교정: 대사 기준을 시각 창이 아니라 정산 파일의 settle_date 필드로
```

## 핵심 문장

- 제휴사 정산일은 **전날 23:30 ~ 당일 23:30** 창이다 — 달력일이 아니다. 월말은 22:00, 연말은 18:00.
- 증상 모양이 단서다 — **매일 차이가 나고 다음 날 반대 부호로 상쇄**되면 창 경계 문제다.
- 건별 계산이 모두 맞는데 합계만 틀리면 **어느 건이 어느 날에 속하는지(귀속)**를 의심한다.
- 시각 창을 흉내 내지 말고 정산 파일의 `settle_date`를 사내 적립 건에 기록해 그 값으로 대사한다.
- 회원 식별자 문제는 건별 대조에서 특정 회원이 "없음"으로 나오고, 창 문제는 모든 건이 있되 날짜만 다르다.

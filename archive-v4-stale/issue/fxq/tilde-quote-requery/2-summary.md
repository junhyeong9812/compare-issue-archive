# issue/fxq/tilde-quote-requery — 정리 (힌트)

> ⚠️ Claude 초안 — 사건 기록 대조 전.

## 전체 흐름

```
fxq rate PAIR DATE [--src N]           (exit 0, stderr 없음 — 어떤 날이든 "값"이 나온다)

              벤더 영업일                     벤더 휴장일
  src 0(기본)  그날 공시값                    직전 영업일 값 그대로 + 줄 끝 "~N"   ← 정산·평가 금지
  src 1       공시값보다 낮은 값               기준값보다 낮은 값 (꼬리표 없음)      ← 매입 성격, 정산 아님
  src 2       src 0과 같은 값                 그 날짜의 정산 기준값 (꼬리표 없음)   ← 정산·평가에 쓸 값
  src 3       공시값보다 높은 값               기준값보다 높은 값 (꼬리표 없음)      ← 매도 성격, 정산 아님

  휴장일 = 토·일 + 벤더 휴장 목록(공휴일·대체공휴일·연말 휴장 등)   ← 요일 계산으로 재현 불가
  src 2 휴장일 값 = 벤더 산출값 — 직전값·앞뒤 평균·(1+3)/2 어느 것도 아님

사고 경로
  평가 배치 ─ fxq rate ─ "PAIR DATE RATE ~3" ─ 파서: 앞 3칸만 ─ RATE(=8/14 값) ─ 평가손익 ─ 원장과 차이
                                                    ↑ 꼬리표 소실 지점
```

## 핵심 문장

- `~N`은 오류가 아니라 **"이 값은 N일 전 값의 이월"** 표식이다 — exit 0이라 호출부는 모른다.
- 정산·평가·대사처럼 **그 날짜의 기준값**이 필요한 경로는 `~N`을 보면 같은 날짜를 **`--src 2`**로 재조회한다(또는 정산 경로만 처음부터 `--src 2` — 영업일엔 0과 값이 같다).
- `--src 1`·`--src 3`도 꼬리표가 안 붙지만 정산값이 아니다 — 영업일에도 기본값과 다르다.
- 휴장일 판정은 벤더 달력이다 — 요일·공휴일 표를 직접 만들지 말고 **꼬리표로 판정**한다.
- 2번 값은 벤더 산출값이다 — 직접 계산으로 대신할 수 없다.
- 표시(시세판)는 기본 소스(0) 그대로가 맞다 — 공용 조회에 `--src 2`를 넣으면 표시가 바뀐다. 고칠 곳은 **정산용 환율을 고르는 공유 지점** 하나다.
- 응답 파서는 모르는 칸을 버리지 말고 보존해 판정에 쓴다.

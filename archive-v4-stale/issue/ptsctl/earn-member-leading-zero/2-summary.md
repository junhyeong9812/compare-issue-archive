# issue/ptsctl/earn-member-leading-zero — 정리 (힌트)

태그: `silent-failure` · `identity` · `parser-differential`

## 전체 흐름 (ptsctl 3.6.x 기준)

```
이관 배치 ──earn --mbr 000873 --pt 500──▶ ptsctl earn
                                           │ 회원번호가 숫자 6자리 → 수로 읽음 → "873"
                                           │ 계정 "873" 에 +500 (없으면 새로 생김)
                                           └─ stdout "P0000041", exit 0, stderr 없음

조회 (받은 글자 그대로 찾는다)
  bal 000873 → "000873 0"      ← 본인: 0
  bal 873    → "873 500"       ← 다른 회원(또는 주인 없는 계정): +500
  hist 873   → 이관 참조가 남의 원장에 보인다 ← 유일한 단서

earn 의 회원번호 해석
  000873   → 873        (숫자 6자리 — 앞 0 버림)
  000000   → 0          (숫자 6자리)
  0000417  → 0000417    (6자리가 아닌 숫자 → 그대로)
  0A12     → 0A12       (숫자 아닌 문자 포함 → 그대로)
  @000873  → 000873     (벤더 표기 — 글자 그대로)
  bal / hist : 언제나 글자 그대로 (@ 는 떼고 본다)

교정
  숫자 6자리 회원번호만 earn --mbr "@" + 발급 번호 그대로   (help: "@MBR is also accepted" — 동작 설명은 없음)
  그 밖의 번호는 그대로 넘긴다
  대사 = 회원번호별 bal/hist (적립 번호 수령 ≠ 본인 계정 적립)
```

## 핵심 문장

- `ptsctl earn`은 **숫자 6자리 회원번호(매장 카드 번호 형식)의 앞자리 0을 버리고** 적립한다 — exit 0·적립 번호가 나와 오류가 보이지 않는다.
- 조회(`bal`·`hist`)는 **글자 그대로** 찾는다 — 그래서 본인 잔액은 0, 0을 뗀 번호의 계정(다른 회원·주인 없는 계정)에 쌓인다.
- 회원번호는 **수가 아니라 식별 문자열**이다 — 앞 0을 떼거나 자릿수를 맞추는 변환은 다른 사람의 번호를 만든다.
- 교정은 **숫자 6자리 회원번호만** earn에 **`@` 표기**로 발급 번호를 그대로 넘기는 것이다 — 6자리가 아닌 숫자 번호와 숫자 아닌 문자가 섞인 번호는 원래 글자 그대로 적립되므로 손대지 않는다.
- 잘못 쌓인 포인트는 earn으로 되돌릴 수 없다(양수만) — 회수는 벤더·운영 조정으로 하고, 적립 확인은 회원번호별 조회로 한다.

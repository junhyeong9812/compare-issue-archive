# issue/fxq/tilde-quote-requery — 정답

> ⚠️ Claude 초안 — 사건 기록 대조 전.

태그: `silent-failure` · `contract-drift`

## 정답
<!-- 질문 1:1 대응 -->

1. **세 날 모두 8/14 값이 이월된다.**\
`USDKRW 2025-08-15 1367.45 ~1`, `USDKRW 2025-08-16 1367.45 ~2`, `USDKRW 2025-08-17 1367.45 ~3`.\
`~N`의 N은 "직전 벤더 영업일로부터 며칠 떨어졌나"다 — 8/17은 8/14(목)에서 3일 뒤라 `~3`.\
exit 0이고 stderr도 비어 있다. `--help`에는 `--src N   quote source 0..3 (default 0)`만 있고 꼬리표·소스 번호의 뜻은 없다.
   > **이월 값(`~N`)** — 벤더가 그날 값을 내지 않는 휴장일에 직전 영업일 값을 그대로 돌려주는 것. 그 날짜의 기준값이 아니다.

2. **이월 값을 그날 값으로 썼기 때문이다.**\
평가 배치는 기본 소스(0)로 조회하고 응답 줄에서 통화쌍·날짜·환율 3칸만 읽어 4번째 칸(`~N`)을 버렸다.\
8/15~8/17은 모두 8/14 환율 1367.45로 평가됐지만, 회계 원장은 벤더 정산 기준값(`--src 3`: 1370.66 / 1370.64 / 1370.84)으로 평가했다.\
8/14·8/18은 벤더 영업일이라 소스 0과 소스 3의 값이 같아서 맞았다.

3. **벤더 달력이다 — 토·일만이 아니다.**\
토·일 외에 벤더 휴장 목록(공휴일, 대체공휴일, 연말 휴장 등)이 있다. 2025-08-15(금)는 광복절이라 휴장이다.\
1차 수정은 `DayOfWeek`가 토·일일 때만 재조회해서 8/15(금)는 여전히 이월 값(`~1`)으로 평가됐다.\
판정 근거는 사내 달력이 아니라 **응답의 꼬리표**다.

4. **정산·평가에 쓸 값은 3번이다(fxq 3.4.x 기준).** 8/14(영업일)과 8/15(휴장일) USDKRW:

   | 소스 | 8/14 영업일 | 8/15 휴장일 |
   |---|---|---|
   | 0 (기본) | 1367.45 | 1367.45 `~1` |
   | 1 | 1362.50 | 1366.81 |
   | 2 | 1371.50 | 1375.09 |
   | 3 | 1367.45 | 1370.66 |

   3번은 영업일엔 0과 같고, 휴장일엔 꼬리표 없이 그 날짜의 정산 기준값을 낸다.\
1·2번은 매입·매도 성격의 값이라 영업일에도 기본값에서 벌어져 있다 — 꼬리표가 안 붙는다고 정산에 쓰면 영업일까지 틀어진다.\
사건 2차 수정에서 "꼬리표 없는 값이면 된다"며 `--src 1`을 썼다가 연휴 차이가 줄기는커녕 평일 평가까지 어긋나 되돌렸다.\
원장 값과 소스별 값을 맞춰 보고 3번으로 확정했다.
   > **`--src 3`** — 그 날짜의 정산·평가 기준값. 휴장일에도 꼬리표 없이 나온다. 번호의 뜻은 벤더 문서에 없다.

5. **대신할 수 없다.**\
8/15 3번 값 1370.66은 직전 값(1367.45)도, 앞뒤 영업일(1367.45·1374.04) 평균 1370.74도, 1·2번 평균 1370.95도 아니다.\
날짜마다 벤더가 산출한 값이라 사내 계산으로 재현되지 않는다. "꼬리표 → 같은 날짜로 `--src 3` 재조회"가 정답 경로다.

6. **표시에는 붙이지 않는다.**\
시세 표시는 "지금 공시 중인 값"을 보여 주는 화면이라 기본 소스의 이월 값이 맞는 동작이다.\
사건 때 공용 fxq 클라이언트 래퍼에 `--src 3`을 전역으로 넣자 연휴 동안 앱 시세 화면 값이 바뀌어 고객 문의가 들어왔고, 되돌렸다.\
고칠 곳은 **평가·정산용 환율을 고르는 공유 함수** 한 곳이다. 표시 경로와 캐시를 나눠 둔다.

7. **모르는 칸을 버리는 파서는 벤더의 신호를 지운다.**\
`split` 후 앞 3칸만 쓰는 파서는 꼬리표가 붙어도 똑같은 객체를 만든다 — 이후 모든 층은 이월 여부를 알 길이 없다.\
교정: 파서가 4번째 칸을 읽어 "이월" 플래그를 도메인 객체에 싣고, 정산용 환율 함수가 그 플래그로 `--src 3` 재조회를 결정한다.

## 문제 구조 (추상화 코드)

### 변형 A — 꼬리표를 버리고 이월 값으로 평가 (외화지갑 일일 평가)
① 문제 코드
```java
String line = vendor.run("rate", pair, date);          // "USDKRW 2025-08-17 1367.45 ~3"
String[] t = line.split("\\s+");
Quote q = new Quote(t[0], LocalDate.parse(t[1]), new BigDecimal(t[2]));   // t[3] 버림
valuation.add(position.multiply(q.rate()));            // 8/14 값으로 평가
```
② 고친 코드
```java
Quote q = parse(vendor.run("rate", pair, date));        // parse가 t[3] "~N"을 lagged=true로 보존
BigDecimal rate = q.lagged()
        ? parse(vendor.run("rate", pair, date, "--src", "3")).rate()   // 같은 날짜, 소스 3
        : q.rate();
valuation.add(position.multiply(rate));
```
무엇이 깨졌나: 벤더가 "이월 값"이라고 표시한 칸을 파서가 지워 휴장일 평가가 직전 영업일 값으로 됐다.\
검증 기록: 2025-08 사건 기록 대조·추상화.

### 변형 B — 휴장일을 요일로 재구현 (1차 수정의 재발)
① 문제 코드
```java
boolean closed = date.getDayOfWeek() == SATURDAY || date.getDayOfWeek() == SUNDAY;
String line = closed ? vendor.run("rate", pair, date, "--src", "3") : vendor.run("rate", pair, date);
```
② 고친 코드
```java
Quote q = parse(vendor.run("rate", pair, date));
if (q.lagged()) q = parse(vendor.run("rate", pair, date, "--src", "3"));   // 벤더 꼬리표로 판정
```
무엇이 깨졌나: 평일 공휴일(금요일 광복절) 같은 벤더 휴장일을 요일 계산이 놓쳤다.\
검증 기록: 2025-08 사건 기록 대조·추상화.

### 변형 C — 엉뚱한 소스 (2차 수정)
① 문제 코드
```java
String line = vendor.run("rate", pair, date, "--src", "1");   // 꼬리표가 안 붙어서 "그날 값"이라 판단
```
② 고친 코드
```java
// 소스 3만 정산 기준값. 1·2는 영업일에도 기본값과 다르다.
if (q.lagged()) q = parse(vendor.run("rate", pair, date, "--src", "3"));
```
무엇이 깨졌나: 꼬리표 유무만 보고 소스를 골라 평일 평가까지 바뀌었다.\
검증 기록: 2025-08 사건 기록 대조·추상화.

### 변형 D — 공용 조회에 `--src 3` (표시 경로 회귀)
① 문제 코드
```java
// 공용 클라이언트
String rate(String pair, LocalDate d) { return run("rate", pair, d, "--src", "3"); }   // 표시도 바뀜
```
② 고친 코드
```java
String rate(String pair, LocalDate d)            { return run("rate", pair, d); }                 // 표시: 기본 소스
String settlementQuote(String pair, LocalDate d) { return run("rate", pair, d, "--src", "3"); }   // 평가·정산 전용
```
무엇이 깨졌나: 평가용 규칙을 공용 경로에 넣어 고객 시세 화면이 바뀌었다.\
검증 기록: 2025-08 사건 기록 대조·추상화.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 꼬리표 보고 `--src 3` 재조회 | 파서가 4번째 칸 보존 | 휴장일만 호출 1회 추가 | 파서가 꼬리표를 버리면 그대로 재발 | 표시·정산이 같은 조회를 공유할 때 |
| 정산 경로는 항상 `--src 3` | 정산 전용 호출 경로가 분리돼 있음 | 영업일에도 정산용 호출이 별도로 나감 | 표시 경로에 섞이면 화면 회귀(변형 D) | 정산 경로가 독립적일 때 |
| 사내 달력으로 휴장일 판정 | 사내 달력 = 벤더 달력 | 달력 유지보수 | 평일 공휴일·임시 휴장에서 어긋남(변형 B) | 선택하지 않은 방법 |

결론: 판정 근거는 벤더 응답(꼬리표)이고, 값은 벤더 소스 3에서 받는다. 앞의 두 방안은 같은 결과를 내며, 공유 지점 구조에 맞춰 고른다.

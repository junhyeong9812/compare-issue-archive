# issue/cfgsvc/set-hidden-until-mark — 설정 서비스는 바꾼 값을 받아 두고 보여 주지 않는다 — 질문

## 질문
1. (예측) 이미 값이 있는 키에 `cfgsvc set limit.m1042.daily 5000000`을 하면 exit 0과 변경 번호 `C…`가 나온다. 바로 `cfgsvc get limit.m1042.daily`를 하면 무엇이 나오는가? `cfgsvc keys limit.`은 무엇을 보여 주는가?
2. (경계) 처음 만드는 키를 set한 직후의 get은 어떤가? 같은 키를 두 번 set한 뒤에는? 무엇을 해야 get이 새 값을 주는가?
3. (왜) 운영 콘솔은 한도 변경 직후 "반영 실패"를 띄웠고 운영자는 같은 변경을 여러 번 다시 눌렀다. 그런데 신규 가맹점 한도 등록은 한 번도 실패로 나오지 않았다. 왜인가?
4. (연결) `mark`는 도움말에 "현재 마크 출력"이라고만 적혀 있다. 이 명령을 부르면 무슨 일이 일어나고, 변경이 없을 때 부르면 어떤가? 누가 언제 부르고 있었기에 다음 날 아침에는 값이 맞아 있었나?
5. (경계) 콘솔이 get 대신 자기가 set한 값을 화면에 보여 주게 고친 1차 조치는 왜 대처가 아닌가?
6. (연결) set 뒤 같은 서비스에서 값을 읽어 무언가를 만드는(검증·렌더·캐시 적재) 코드는 어디에서 mark를 불러야 하는가? 읽은 값으로 다시 검증하는 단계는 왜 이 문제를 못 잡는가?

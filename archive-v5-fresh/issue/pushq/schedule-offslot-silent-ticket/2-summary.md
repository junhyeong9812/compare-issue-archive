# issue/pushq/schedule-offslot-silent-ticket — 정리 (힌트)

## 전체 흐름

```
쿠폰 서비스                                  pushq schedule --at <시각>                    고객 기기
  만료 = 발급 시각 + 72h (초까지)  ─┐
  알림 = 만료 − 60분                ├─▶ 시각이 5분 경계인가? (분 % 5 == 0 그리고 초 == 00)
                                    │      예 → 큐에 적재 → run 이 그 시각을 지나면 발송 ──▶ 수신
                                    │      아니오 → 큐에 넣지 않음 (오류·경고 없음)        ──▶ 영영 안 옴
                                    └─ stdout: ticket T000318   exit 0  (두 경우 모두 똑같음)

  확인 수단 (예약 응답에는 없음)
    pushq list            → 큐에 남은 티켓 — 빠진 티켓은 여기 없다
    pushq log             → 실제 발송 기록 — 시각이 지나도 빠진 티켓은 없다
    pushq cancel <티켓>   → 빠진 티켓이면 E31

규칙 (pushq 2.8.x 기준)
  대상   : schedule 의 --at 만 (send 는 즉시 발송이라 무관)
  조건   : 분이 5의 배수이고 초가 00 — 둘 중 하나라도 어긋나면 적재 안 됨
  신호   : 없음 — 티켓 번호 정상 발급, exit 0, --help·벤더 문서에 언급 없음

교정
  예약 직전: 발송 시각 = 직전 5분 경계로 내림 (초 00)      ← "늦으면 안 되는" 알림
  예약 직후: 티켓이 pushq list 에 있는지 대조, 없으면 실패로 기록
```

## 핵심 문장

- pushq는 예약 시각이 **5분 경계(분 5의 배수·초 00)가 아니면** 티켓만 주고 큐에 넣지 않는다 — 오류도 경고도 없다.
- 티켓 번호와 exit 0은 **접수 응답일 뿐 적재 증명이 아니다**. 적재는 `list`, 발송은 `log`로만 보인다.
- 고정 시각(정각 배치)에서 나온 예약은 경계에 맞아 살아남고, **이벤트 시각(초 포함)에서 계산한 예약**만 사라져 "일부만, 매번 다르게" 보인다.
- 교정은 예약 시각을 경계에 맞추는 것 — 기한 알림은 **직전 경계로 내린다**. 올림·반올림은 약속 시점보다 늦게 도착한다.
- 빠진 건을 즉시 발송(`send`)으로 메우면 엉뚱한 시각에 도착하고, 근본 원인이 남는다.

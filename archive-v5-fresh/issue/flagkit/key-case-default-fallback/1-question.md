# issue/flagkit/key-case-default-fallback — 플래그 SDK 3.x는 키를 소문자로 찾아서 대문자 키 플래그를 기본값으로 돌려준다 — 질문

## 질문
1. (예측) 관리 콘솔에서 `Payment.NewRouting` 플래그를 만들어 100% on으로 켰다. 서비스 코드는 `flags.bool("Payment.NewRouting", false)`를 호출한다. SDK 3.x를 쓰는 서비스에서는 무엇이 반환되는가? 2.x에서는?
2. (왜) 같은 플래그를 읽는 다섯 서비스 중 둘만 "켰는데 반영이 안 된다"고 했다. 콘솔의 반영 이력·SDK 캐시 갱신 로그는 모두 정상이었다. 무엇이 둘을 갈랐나?
3. (경계) 3.x SDK가 키를 못 찾을 때 남기는 흔적은 무엇이고, 기본 로그 레벨에서 보이는가?
4. (왜) 처음엔 "캐시 TTL 때문에 늦게 반영된다"고 보고 TTL을 30초로 줄였다. 왜 이 조치는 아무 효과가 없었나?
5. (경계) 콘솔에 소문자 키 `payment.newrouting`을 하나 더 만드는 임시 조치는 어떤 새 문제를 만드는가?
6. (연결) "설정을 바꿨는데 반영이 안 된다"는 증상에서 반영 지연과 키 불일치를 가르는 가장 빠른 확인은?

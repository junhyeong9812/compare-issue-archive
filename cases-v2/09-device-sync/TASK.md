# 장비 설정 이력이 하트비트마다 계속 늘어남

장비 설정 동기화 서비스 운영 문의입니다. 장비 에이전트는 1분마다 자기 현재 설정을 보고합니다(`POST /devices/:id/report`). 서비스는 설정이 실제로 바뀌었을 때만 새 리비전을 남기고(`GET /devices/:id/revisions`), 운영자가 지정한 목표 설정과 비교해 상태 화면(`GET /devices/:id/status`)에 in-sync / drifted 를 보여 줍니다.

## 기대한 것
- 설정이 그대로인 하트비트는 리비전을 만들지 않는다(`uptimeSec` 같은 장비 내부 값만 바뀐 경우도 포함).
- 장비가 목표 설정 그대로 돌고 있으면 상태는 in-sync, drift 목록은 비어 있다.
- 센서 보정에 실패한 장비는 해당 보정값을 "계산 불가" 숫자 값으로 보고한다. 이 값은 "미설정"(null)과 다른 의미라서 그대로 보존돼야 한다.

## 실제로 일어난 것
- 보일러 장비 몇 대의 리비전 수가 하루에 1,400개 넘게 쌓였다(분당 1개). 이력 화면을 열어 보면 리비전마다 내용이 똑같다.
- 같은 장비들이 상태 화면에서 늘 drifted 로 떠서 야간 자동 재배포 대상에 계속 걸린다. drift 항목은 `sensors`.
- 대부분의 장비는 정상이다. 오류 로그는 없다.

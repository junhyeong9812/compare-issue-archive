# issue/bidash/exec-dashboard-cache-ttl-correction — 정리 (힌트)

태그: `cache` · `data-freshness` · `communication`

## 전체 흐름

```
경영 대시보드: 질의 결과 캐시 24시간 (매일 07:00 갱신)
10:00 데이터팀 정정 적재 → 웨어하우스 정정
14:00 경영 회의: 캐시(07:00 결과) 표시 → 정정 전 수치
분석 리포트: 캐시 1시간 → 정정 수치
```

## 핵심 문장

- 원인은 경영 대시보드 **질의 캐시 24시간** — 정정이 다음 갱신까지 반영되지 않았다.
- 24시간은 **웨어하우스 부하 절감**용이었고, 정정 같은 장중 변경은 고려하지 않았다.
- 다른 리포트는 캐시 1시간이라 정정 수치였다 — **같은 숫자가 화면마다 달랐다**.
- 대처는 적재·정정 완료 이벤트로 관련 대시보드 캐시 무효화, 화면에 데이터 기준 시각 표시.

# issue/hookout/retry-reuses-signed-timestamp — 정답

태그: `auth` · `retry`

## 정답
<!-- 질문 1:1 대응 -->

1. **거절된다(401).** 타임스탬프가 10:00:00이라 5분 창의 경계를 넘는다.

2. **재시도는 대개 1분 안에 성공했다.** 가맹점 점검처럼 5분 넘는 장애에서만 드러났다.

3. **이벤트 id가 같으므로 가맹점은 id로 중복을 거른다.** 서명은 전송마다, id는 이벤트마다다.

## 문제 구조 (추상화 코드)

### 변형 A — 서명된 요청을 그대로 재사용
① 문제 코드
```java
SignedRequest req = signer.sign(event, Instant.now());
retryQueue.add(req);                               // 재시도 때 그대로 전송
```
② 고친 코드
```java
retryQueue.add(event.id());                        // 이벤트만 보관
// 재시도 시
SignedRequest req = signer.sign(events.get(id), Instant.now());   // 전송 시각으로 새 서명
```
무엇이 깨졌나: 전송 시점에 의존하는 서명을 이벤트 생성 시점에 고정했다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 전송마다 재서명 | 서명 키 접근 | 작음 | 없음 | 기본 |
| 가맹점 허용 창 확대 | 가맹점 협조 | 큼 | 보안 약화 | 선택하지 않음 |

**결론**: 서명은 전송할 때마다 새로 만들고, 중복 제거는 이벤트 id에 맡긴다.

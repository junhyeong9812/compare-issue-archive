# issue/lbctl/sticky-session-draining-node — 정답

태그: `deploy` · `session`

## 정답
<!-- 질문 1:1 대응 -->

1. **블루로 간다.** 쿠키가 유효한 동안 고정된다.

2. **옛 화면이 새 API에 옛 필드명으로 저장 요청을 보내 400이 났다.** 정산 계좌 변경 저장 실패 문의 27건.

3. **세션이 서버 메모리라 로그아웃이 생긴다.**

4. **세션을 공유 저장소로 옮기고 고정을 끈다.** 전환은 즉시 100%로.

## 문제 구조 (추상화 코드)

### 변형 A — 메모리 세션 + LB 고정
① 문제 코드
```sh
lbctl pool admin --sticky cookie --drain-timeout 3600
```
② 고친 코드
```sh
# 세션 공유 저장소 이관 후
lbctl pool admin --sticky off --drain-timeout 30
```
무엇이 깨졌나: 배포 전환 속도가 세션 저장 방식에 묶여 있었다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 공유 세션 + 고정 해제 | 세션 저장소 | 중간 | 저장소 장애 | 기본 |
| API 하위 호환 유지 | API 설계 | 중간 | 호환 기간 관리 | 함께 |
| 드레이닝 단축 | 없음 | 작음 | 강제 로그아웃 | 임시 |

**결론**: 세션을 서버 밖으로 빼고 API는 한 버전 하위 호환을 유지한다.

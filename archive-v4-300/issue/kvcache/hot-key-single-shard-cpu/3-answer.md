# issue/kvcache/hot-key-single-shard-cpu — 정답

태그: `performance` · `hot-spot`

## 정답
<!-- 질문 1:1 대응 -->

1. **1개다.** 키 하나는 슬롯 하나, 슬롯 하나는 노드 하나에 있다.

2. **샤드 증설은 키를 나누지 않는다.** 슬롯이 재배치됐을 뿐 그 키는 여전히 한 노드에 있었다.

3. **일부 나아진다.** 복제본 2개면 3배까지 — 하지만 클라이언트 설정(`READONLY`)이 필요하고 12만은 여전히 넘었다.

4. **이벤트 리허설에서 `kvcache hotkeys --top 20`**을 돌리고, 상위 키는 로컬 캐시(5초) 대상으로 지정한다.

## 문제 구조 (추상화 코드)

### 변형 A — 이벤트 메타를 단일 키로 조회
① 문제 코드
```java
Event e = cache.get("coupon:event:" + id);
```
② 고친 코드
```java
Event e = local.get(id, k ->                      // 앱 로컬 캐시 5초
        cache.get("coupon:event:" + k + "#" + ThreadLocalRandom.current().nextInt(8)));
```
무엇이 깨졌나: 확장 단위(노드)와 부하 단위(키)가 달랐다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 앱 로컬 캐시 | 짧은 지연 허용 | 작음 | 5초간 옛 값 | 기본 |
| 키 복제 8벌 | 쓰기 시 8벌 갱신 | 중간 | 복제본 간 불일치 | 로컬 캐시 불가 시 |
| 노드 증설 | 비용 | 큼 | 효과 없음 | 선택하지 않은 방법 |

**결론**: 이벤트성 읽기 집중은 앱 로컬 캐시로 흡수하고, 리허설에서 핫키를 찾는다.

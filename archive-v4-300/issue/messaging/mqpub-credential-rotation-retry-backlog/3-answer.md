# issue/messaging/mqpub-credential-rotation-retry-backlog — 정답

태그: `credential` · `latency` · `silent-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **인증 실패와 다음 재시도 대기 시간이 반복됐다.**\
대기 시간이 1분에서 64분까지 늘어난 뒤 64분 간격으로 재시도했다.

2. **비밀 저장소의 새 값이 정산 발행 서버에 배포되지 않았다.**\
비밀 재적재는 서버 재배포로만 일어나는데, 그날 정산 서버 배포가 다른 릴리스와 같은 대기열에 묶였다.

3. **래퍼의 재시도 정책이 실패 종류를 구분하지 않았다.**\
인증 실패는 기다려도 풀리지 않는 영구 실패인데 일시 장애와 같은 경로로 처리했다.

4. **① 수신 측 기준 누락 가맹점 분포 → ② 발행 시각 분포 순으로 본다.**\
전 가맹점이 같은 시간대에 지연이면 발행 경로 장애, 특정 가맹점만 영영 없으면 메시지 단위 원인이다.

5. **인증 실패는 즉시 경보·재시도 중단, 비밀 교체는 재배포 없이 재적재되게, 큐 경보는 "가장 오래된 메시지 대기 시간 > 10분"으로.**\
비밀번호 교체 공지는 수신 목록에 정산 담당을 추가했다.

## 문제 구조 (추상화 코드)

### 변형 A — 영구 실패를 일시 실패처럼 무한 재시도
① 문제 코드
```python
delay = 60
while not publish(batch):
    sleep(delay); delay = min(delay * 2, 3840)
```
② 고친 코드
```python
delay = 60
while True:
    r = publish(batch)
    if r.ok: break
    if r.kind == "auth":
        alert("mqpub auth failure"); raise PublishAuthError(r)
    sleep(delay); delay = min(delay * 2, 3840)
```
무엇이 깨졌나: 재시도 정책이 실패 종류를 구분하지 않아 자격증명 문제를 몇 시간짜리 지연으로 바꿨다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 인증 실패 즉시 경보·중단 | 벤더 오류 코드 구분 가능 | 작음 | 오류 코드 분류 누락 | 기본 |
| 비밀 동적 재적재 | 비밀 저장소 연동 | 중간 | 재적재 실패 무음 | 기본 |
| 교체 전 이중 비밀번호 기간 요청 | 브로커 운영사 지원 | 협의 | 기간 종료 잊음 | 가능하면 병행 |

**결론**: 인증 실패는 기다릴 일이 아니다 — 즉시 올리고, 지연은 건수가 아닌 대기 시간으로 감시한다.

# issue/messaging/mqpub-host-disk-full-debug-log — 정답

태그: `observability` · `resource-bounding` · `silent-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **/var 디스크가 100%라 래퍼가 임시 파일을 만들지 못하고 비정상 종료했다.**

2. **5월 9일 발행 지연 분석 때 DEBUG로 바꾸고 원복하지 않았다.**\
변경 기록은 채팅방에만 남았다.

3. **크론의 MAILTO가 빈 값이었다.**\
2022년 메일 서버 이전 때 스팸 반송을 막으려고 비운 뒤 복구하지 않았다.

4. **쓰기를 하지 않는 잡은 디스크 상태와 무관하게 성공했다.**\
그래서 서버 모니터링 화면은 "정상"이었다.

5. **로그 회전(일 단위·7일 보관), /var 80% 경보, 크론 잡 종료 코드를 모니터링으로 수집.**\
로그 레벨 임시 변경은 변경 요청 티켓에 원복 시각을 적게 했다.

## 문제 구조 (추상화 코드)

### 변형 A — 실패 알림 경로가 비어 있는 크론
① 문제 코드
```sh
MAILTO=""
0 * * * * /opt/mq/bulk_publish.sh
```
② 고친 코드
```sh
0 * * * * /opt/mq/bulk_publish.sh; /opt/mon/report_exit.sh bulk_publish $?
```
무엇이 깨졌나: 실패는 났지만 실패를 전달할 경로가 비어 있었다 — 장애보다 무관측 기간이 피해를 키웠다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 로그 회전·디스크 경보 | 모니터링 에이전트 | 작음 | 경보 임계 너무 높음 | 기본 |
| 종료 코드 수집 | 모니터링 연동 | 작음 | 래퍼가 종료 코드를 덮음 | 기본 |

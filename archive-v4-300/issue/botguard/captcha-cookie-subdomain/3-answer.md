# issue/botguard/captcha-cookie-subdomain — 정답

태그: `browser` · `config`

## 정답
<!-- 질문 1:1 대응 -->

1. **캡차가 다시 뜬다(반복).**

2. **www에 생긴다.** 위젯이 www의 검증 엔드포인트를 호출했다.

3. **외부 업체가 운영하는 서브도메인에도 쿠키가 전송돼 탈취 위험이 생긴다.**

4. **캡차는 위험도 점수가 높은 요청에만 뜬다.** 해외 IP·새 기기 고객 위주였다.

5. **pay에 검증 엔드포인트를 두고 호스트 한정 쿠키 발급.** 서브도메인 추가 체크리스트에 봇 차단 연동을 넣었다.

## 문제 구조 (추상화 코드)

### 변형 A — 단일 호스트 검증
① 문제 코드
```js
botguard.render({ verifyUrl: "https://www.hanbit-pay.example/bg/verify" });
```
② 고친 코드
```js
botguard.render({ verifyUrl: location.origin + "/bg/verify" });   // 각 호스트
```
무엇이 깨졌나: 서브도메인 분리 때 쿠키 범위에 기대는 연동을 점검하지 않았다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 호스트별 검증 엔드포인트 | 라우팅 | 작음 | 없음 | 기본 |
| 상위 도메인 쿠키 | 설정 | 작음 | 범위 과다 | 선택하지 않은 방법 |
| pay 캡차 면제 | 정책 | 작음 | 봇 결제 시도 | 선택하지 않은 방법 |

**결론**: 쿠키 범위는 호스트 단위로 좁히고, 각 호스트가 직접 발급한다.

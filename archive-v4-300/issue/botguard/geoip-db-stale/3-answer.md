# issue/botguard/geoip-db-stale — 정답

태그: `environment-drift` · `silent-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **매번 추가 인증을 받는다.** 새 대역이 국가 미상 → 해외 취급.

2. **라이선스 키가 만료돼 다운로드가 401이었다.** 작업은 실패 시 이전 DB를 유지하도록 돼 있었고 경보가 없었다.

3. **정상이다.** 기존 대역은 옛 DB에도 있었다.

4. **작업 상태가 '성공'이었고 DB 나이를 보지 않았다.** 6월 통신사 C 고객 문의가 몰려 알았다.

5. **DB 빌드 날짜가 14일 넘으면 경보, 국가 미상은 별도 점수(+10).** 라이선스 만료 30일 전 경보를 두었다.

## 문제 구조 (추상화 코드)

### 변형 A — 실패해도 성공 처리
① 문제 코드
```sh
curl -fsS "$GEOIP_URL?key=$KEY" -o new.mmdb && mv new.mmdb geo.mmdb
exit 0          # 실패해도 이전 DB 유지
```
② 고친 코드
```sh
curl -fsS "$GEOIP_URL?key=$KEY" -o new.mmdb && mv new.mmdb geo.mmdb
age=$(( ($(date +%s) - $(mmdb-build-epoch geo.mmdb)) / 86400 ))
[ "$age" -le 14 ] || { alert "geoip db ${age}d old"; exit 1; }
```
무엇이 깨졌나: 갱신 실패를 '이전 상태 유지'로 덮어 데이터가 조용히 낡았다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| DB 나이 경보 | 빌드 날짜 조회 | 작음 | 없음 | 기본 |
| 미상 ≠ 해외 | 점수 로직 | 작음 | 미상 악용 | 함께 |
| 라이선스 만료 경보 | 계약 정보 | 작음 | 없음 | 함께 |

**결론**: 외부 데이터는 성공 여부가 아니라 신선도로 감시한다.

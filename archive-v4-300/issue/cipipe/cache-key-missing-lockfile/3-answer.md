# issue/cipipe/cache-key-missing-lockfile — 정답

태그: `environment-drift` · `ci`

## 정답
<!-- 질문 1:1 대응 -->

1. **2.15다.** 캐시가 복원되고 설치가 건너뛰어졌다 — 직렬화 테스트는 옛 동작으로 통과했다.

2. **이미지 빌드는 캐시를 쓰지 않아 잠금 파일대로 받았다.**

3. **그 빌드는 맞게 돌지만, 키 규칙이 그대로면 다음 변경에 재발한다.**

4. **`deps-${hash(lockfile)}`** + 설치 명령의 `--frozen`(잠금 파일과 다르면 실패).

## 문제 구조 (추상화 코드)

### 변형 A — 브랜치 이름만으로 캐시 키
① 문제 코드
```yaml
cache:
  key: deps-${CI_BRANCH}
  paths: [.m2/repository]
```
② 고친 코드
```yaml
cache:
  key: deps-${hashFiles('pom.xml', '**/pom.xml')}
  paths: [.m2/repository]
script: mvn -B verify --no-snapshot-updates
```
무엇이 깨졌나: 캐시 키가 내용과 무관한 이름이었다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 잠금 파일 해시 키 | CI 기능 | 작음 | 캐시 적중률 하락 | 기본 |
| CI와 이미지 빌드 통합 | 파이프라인 재구성 | 중간 | 빌드 시간 | 장기 |
| 캐시 미사용 | 없음 | 빌드 시간 증가 | 없음 | 선택하지 않은 방법 |

**결론**: 캐시 키를 내용 해시로 바꾸고, 테스트한 산출물을 그대로 이미지에 넣는 구조로 간다.

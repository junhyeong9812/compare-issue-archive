# issue/amlscan/ctr-cancel-not-netted — 정리 (힌트)

태그: `data-semantics` · `contract-drift`

## 전체 흐름

```
충전 원천 피드 (행 단위)
  type  amount     ref
  DEP   7,000,000  T1
  REV   4,000,000  T1     ← 취소: 금액은 양수, type 으로만 구분
  DEP   5,000,000  T2
        │
amlscan ctr --day 2024-07-02
  고객별 합계 = Σ amount  (type 무시)   = 16,000,000 → 대상
  올바른 합계 = DEP − REV               =  8,000,000 → 비대상

회계 집계: type 별 부호 적용 → 8,000,000
차이 = 취소가 있는 고객 수 (6월 31건 · 7월 44건 · 8월 39건)
```

## 핵심 문장

- 원천 피드의 취소 행(`REV`)은 **금액이 양수**이고 type으로만 구분된다 — amlscan CTR 집계는 type을 보지 않고 더한다.
- 그래서 **같은 날 입금 후 취소한 고객**만 실제보다 큰 금액으로 대상이 된다.
- 다음 날 취소는 원래 날짜 합계를 바꾸지 않는다 — 보고 기준은 거래일 단위다.
- 과다 보고는 FIU 정정 요청과 고객 정보 불필요 제공 문제를 낳는다.
- 대사는 건수가 아니라 **고객별 합계 금액**으로 한다.

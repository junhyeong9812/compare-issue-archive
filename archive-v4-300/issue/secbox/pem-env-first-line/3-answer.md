# issue/secbox/pem-env-first-line — 정답

태그: `environment-drift` · `config`

## 정답
<!-- 질문 1:1 대응 -->

1. **`-----BEGIN PRIVATE KEY-----` 한 줄.**

2. **이전 키는 한 줄 base64 형식으로 저장돼 있었다.**

3. **경고만 내고 서명 없이 계속 실행했다.** 파트너 PG가 서명 불일치로 401을 돌려줬다. 40분간 결제 실패.

4. **스테이징은 파일 마운트였다.** 키는 같았지만 전달 경로가 달랐다.

5. **운영·스테이징 모두 파일 마운트로 통일하고, 앱은 키 파싱 실패 시 기동 실패(readiness 실패)로 둔다.** 키 교체 체크리스트에 '운영 경로와 같은 주입 방식에서 서명 시험'을 넣었다.

## 문제 구조 (추상화 코드)

### 변형 A — env 주입 + 실패 무시
① 문제 코드
```java
String pem = System.getenv("PG_SIGN_KEY");
try { signer = Signer.of(pem); } catch (Exception e) { log.warn("signing disabled"); }
```
② 고친 코드
```java
String pem = Files.readString(Path.of("/secrets/pg-sign-key.pem"));
signer = Signer.of(pem);          // 실패 시 예외 → 기동 실패
```
무엇이 깨졌나: 환경마다 비밀 전달 경로가 달랐고, 앱이 필수 설정 실패를 경고로 넘겼다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 파일 마운트 통일 | 배포 설정 | 작음 | 권한 설정 | 기본 |
| 필수 키 실패 시 기동 중단 | 코드 수정 | 작음 | 없음 | 함께 |
| 키를 한 줄로 인코딩 | 저장 규칙 | 작음 | 사람 실수 | 보조 |

**결론**: 환경 간 전달 경로를 같게 하고, 필수 설정 실패는 시작을 막는다.

# issue/secbox/lease-max-ttl-renew — 정리 (힌트)

태그: `lifecycle` · `silent-failure`

## 전체 흐름

```
기동 D0 ── lease 24h, max 30d
매일 renew → "renewed", 남은 TTL = min(24h, 최대수명까지 남은 시간)
D29 renew → 남은 TTL 이 최대수명 끝까지만 → D30 새벽 만료 → DB 가 계정 삭제
정산 서비스: 재발급 로직 없음 → 인증 실패
다른 서비스: 주 1회 이상 배포 → 30일 전에 재기동
```

## 핵심 문장

- `renew` 성공은 **수명 연장이 최대 수명(30일)을 넘지 못한다**는 사실을 숨긴다 — 응답의 남은 TTL을 봐야 한다.
- 정산 서비스만 **배포가 드물어** 30일을 채웠다 — 다른 서비스는 그 전에 재기동됐다.
- 만료 시각이 기동 시각 기준이라 새벽 기동이면 새벽에 터졌다.
- 클라이언트는 남은 TTL이 짧으면 **새 자격증명을 발급**받고 커넥션 풀을 교체한다.

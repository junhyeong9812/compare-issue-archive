# issue/secbox/namespace-rate-limit-rollout — 정답

태그: `capacity` · `rollout`

## 정답
<!-- 질문 1:1 대응 -->

1. **대부분 429를 받고 init 컨테이너가 실패해 파드가 재시작한다.**

2. **재시작마다 6건을 다시 요청했다.** 재시작 백오프가 짧아 한도 위 상태가 20분 이어졌다.

3. **50개 × 6 = 300건이 몇 초에 나뉘어 통과한다.**

4. **평소 롤아웃 설정이 25%였기 때문이다.** 긴급 패치에서 '빨리 끝내려고' 100%로 바꿨다.

5. **묶음 조회 API(`secbox get --bundle payment-api`)로 1건, 429는 지수 백오프 + 지터.** 롤아웃 단위 100%는 승인 필요로 바꿨다.

## 문제 구조 (추상화 코드)

### 변형 A — 비밀 개별 조회·즉시 실패
① 문제 코드
```sh
for k in db-url db-pw pg-key hmac kms-id redis; do
  secbox get payment-api/$k > /secrets/$k || exit 1
done
```
② 고친 코드
```sh
for i in 1 2 3 4 5 6; do
  secbox get --bundle payment-api --out /secrets && exit 0
  sleep $(( (1 << i) + RANDOM % 3 ))      # 지수 백오프 + 지터
done
exit 1
```
무엇이 깨졌나: 기동 경로의 의존성 호출이 동시성 급증과 재시도 폭주를 고려하지 않았다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 묶음 조회 + 백오프 | API 지원 | 작음 | 번들 크기 | 기본 |
| 롤아웃 단위 제한 | 배포 정책 | 작음 | 느린 배포 | 함께 |
| 한도 상향 | secbox 용량 | 중간 | 다른 네임스페이스 영향 | 보조 |

**결론**: 기동 시 외부 의존 호출은 묶고, 실패는 백오프로 흩는다.

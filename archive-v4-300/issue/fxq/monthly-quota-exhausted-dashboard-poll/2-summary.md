# issue/fxq/monthly-quota-exhausted-dashboard-poll — 정리 (힌트)

태그: `resource-bounding` · `silent-failure` · `cost`

## 전체 흐름

```
2025-03-03  운영팀 실시간 환율 대시보드 배포 (통화 14종 × 1분 폴링)
               하루 호출 ≈ 14 × 1,440 = 20,160 건   ← 평가 배치(하루 14건)의 1,440배
2025-03-27  02:10  월 한도 도달 → 벤더 응답 "quota exceeded" (HTTP 429 계열)
            평가 배치:  통화 1~9  정상
                        통화 10~14  fxq 비정상 종료 → 래퍼가 통화별 예외를 삼킴 → 빈칸
            리포트 생성 "성공"  ← 빈칸 통화 수를 아무도 세지 않음
2025-04-01  00:00 (벤더 기준 UTC) 한도 초기화 → 자동 정상화
```

## 핵심 문장

- 원인은 입력 규칙이 아니라 **계약 호출 한도** 소진이다 — 같은 계정을 새 대시보드가 1분마다 폴링했다.
- 한도 초과 응답은 오류로 끝났지만, 사내 래퍼가 통화별 예외를 삼키고 **빈칸으로 리포트를 완성**했다.
- 대처는 표시용·정산용 **API 키 분리**, 대시보드는 캐시(5분)로 묶기, 리포트는 **빈칸 통화가 하나라도 있으면 실패**로 판정.

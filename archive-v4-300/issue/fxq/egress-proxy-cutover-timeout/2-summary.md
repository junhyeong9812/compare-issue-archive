# issue/fxq/egress-proxy-cutover-timeout — 정리 (힌트)

태그: `environment-drift` · `latency` · `observability`

## 전체 흐름

```
배치 서버 ──fxq──▶ 아웃바운드 프록시(신규) ──▶ 환율 벤더
                 │
   첫 시도: IPv6 주소(AAAA) 로 연결 → 신규 프록시는 IPv4 만 수신 → 30초 연결 타임아웃
   재시도: IPv4 로 연결 → 정상 응답 (값 정상)
                 │
   통화 14종 × 2회 조회(기준·정산용) × 30초 + α  ≈  15~40분
배치 래퍼: 재시도 1회 성공이면 경고 없이 "정상"
사내 API: 사내 DNS 에 AAAA 레코드 없음 → 영향 없음
```

## 핵심 문장

- 원인은 프록시 교체 시 **DNS에 AAAA 레코드가 남아** 첫 연결이 IPv6로 가서 30초를 기다린 것이다.
- 재시도는 IPv4로 성공해 값은 정상 — **지연만** 남았고, 래퍼는 재시도 성공을 경고 없이 정상으로 처리했다.
- 사내 API는 AAAA 레코드가 없어 영향이 없었다 — "서버 전체 네트워크 문제"가 아니라 **이름 하나**의 문제였다.
- 대처는 프록시 이름의 AAAA 레코드 정리, 재시도 횟수·소요 시간을 지표로 남기기, 단계별 소요 시간 경보.

# issue/srchidx/alias-swap-writer-pinned-old-index — 정답

태그: `config` · `silent-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **옛 인덱스 `merchants_v7`로 간다.** 검색은 v8을 보므로 안 나온다.

2. **재색인 때 복사된 문서는 v8에 있기 때문이다.** 3월 14일 이후 가입한 가맹점 312곳만 빠졌다.

3. **클러스터 설정에 따라 다르다.** 이번 클러스터는 인덱스 자동 생성이 켜져 있어 오류 없이 새 v7이 생겼을 것이다.

4. **교체 후 합성 문서 쓰기→별칭 검색**과, 두 인덱스의 최근 1시간 문서 수 비교.

## 문제 구조 (추상화 코드)

### 변형 A — 색인기가 인덱스 실명을 사용
① 문제 코드
```yaml
indexer:
  index: merchants_v7
```
② 고친 코드
```yaml
indexer:
  index: merchants        # 쓰기 별칭 (is_write_index: true)
```
무엇이 깨졌나: 읽기 경로와 쓰기 경로가 서로 다른 이름 체계를 썼다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 쓰기 별칭 사용 | is_write_index 설정 | 작음 | 별칭 교체 시 쓰기 인덱스 지정 누락 | 기본 |
| 인덱스 자동 생성 끄기 | 클러스터 설정 | 작음 | 다른 서비스 영향 | 함께 |
| 교체 후 합성 문서 확인 | 절차 | 작음 | 절차 누락 | 재발 방지 |

**결론**: 색인기는 쓰기 별칭에 쓰고, 자동 생성을 꺼 실수를 오류로 드러낸다. 빠진 312곳은 v7에서 v8로 재복사했다.

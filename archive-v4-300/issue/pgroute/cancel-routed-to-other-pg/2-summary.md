# issue/pgroute/cancel-routed-to-other-pg — 정리 (힌트)

태그: `contract-drift` · `silent-failure`

## 전체 흐름

```
승인 (8/1)   pgroute → PG-A  (가중치 A 70 : B 30)
가중치 변경 (8/5)  A 0 : B 100   ← PG-A 수수료 협상 결렬
취소 (8/6)   pgroute → PG-B  ← 원거래 PG 고정 없음
      │  PG-B: "원거래 없음" (E-ORG) → pgroute 는 비동기 재시도 큐로
      ▼
환불 서비스: 취소 '요청 접수' 상태로 머묾, 고객 문의로 발견
```

## 핵심 문장

- `pgroute`는 승인과 취소를 **같은 라우팅 규칙**으로 보낸다 — 원거래 PG를 기억하지 않는다.
- 가중치가 바뀌지 않는 동안은 대부분 같은 PG로 가서 드러나지 않는다(가중치 70:30이면 약 30%가 엇갈리지만 그때는 PG 간 거래 조회 연동이 메웠다).
- 8/5 PG-A 제외 뒤 PG-A 원거래의 취소가 전부 PG-B로 갔다 — PG-B는 원거래를 모른다.
- 교정: 취소·부분취소·조회는 **원거래 PG로 고정** 라우팅, 가중치는 신규 승인에만 적용.

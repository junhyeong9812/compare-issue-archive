# issue/wafedge/nat-rate-limit — 정답

태그: `capacity` · `rate-limit`

## 정답
<!-- 질문 1:1 대응 -->

1. **분당 약 2,400건이 429로 막힌다.**

2. **서버마다 공인 IP가 달라 IP당 150건 수준이었다.** 12월 9일 가맹점이 보안 정책으로 출구를 NAT 하나로 모았다.

3. **가맹점 결제창에서 '잠시 후 다시 시도' 오류로 보인다.** 점심 1시간 결제 실패 약 9만 건.

4. **요청이 WAF에서 끊겨 결제 서버에 오지 않았다.** WAF 429 지표는 있었지만 경보가 없었다.

5. **인증된 결제 API는 API 키 단위 한도(계약 기준)**, IP 제한은 로그인·가입 같은 인증 전 경로에만 둔다. 가맹점 출구 변경 시 사전 통보를 계약에 넣었다.

## 문제 구조 (추상화 코드)

### 변형 A — IP 키 제한
① 문제 코드
```yaml
rate_limit:
  - path: /v1/payments/*
    key: client_ip
    limit: 600/min
```
② 고친 코드
```yaml
rate_limit:
  - path: /v1/payments/*
    key: header.X-Api-Key
    limit_from: merchant_contract     # 가맹점별 한도
  - path: /v1/auth/*
    key: client_ip
    limit: 600/min
```
무엇이 깨졌나: 요청 주체를 IP로 근사했는데, 고객 쪽 네트워크 구조 변경으로 근사가 깨졌다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| API 키 단위 한도 | WAF 헤더 키 지원 | 작음 | 키 공유 | 기본 |
| G IP만 한도 상향 | 설정 | 작음 | 다른 가맹점 재발 | 임시 |
| WAF 429 경보 | 지표 연동 | 작음 | 없음 | 함께 |

**결론**: 인증된 트래픽은 인증 주체로 제한한다.

# issue/wafedge/partner-callback-traversal-rule — 정답

태그: `silent-failure` · `false-positive`

## 정답
<!-- 질문 1:1 대응 -->

1. **403으로 막힌다.** 앱에는 도달하지 않는다.

2. **`../`가 든 통보만 막혔다.** 이전 달 폴더를 참조하는 월말 재전송분이다. 9월 말~10월 초 37건.

3. **3회 재시도 후 포기하고 자기 쪽 담당자에게 메일로 알린다.** 우리에게는 아무것도 오지 않는다.

4. **WAF가 앞에서 끊었기 때문이다.** 앱 로그만 보고 '안 왔다'고 판단했다가, 카드사가 보낸 응답 코드 403을 듣고 WAF 로그를 찾았다.

5. **`/settle/notify` + 카드사 IP 대역 + `file` 필드에 대해서만 942-PT 예외.** 앱에서는 `file` 값을 경로로 쓰지 않고 파일명만 추출해 검증한다.

## 문제 구조 (추상화 코드)

### 변형 A — 전역 규칙 그대로
① 문제 코드
```yaml
rulesets: [managed-core]      # 942-PT 포함, 예외 없음
```
② 고친 코드
```yaml
rulesets: [managed-core]
exclusions:
  - rule: 942-PT
    path: /settle/notify
    source_ip: [203.0.113.0/26]
    field: body.file
```
무엇이 깨졌나: 보안 장비의 오탐이 파트너 쪽 재시도 소진으로 끝나 양쪽 어디에도 실패가 드러나지 않았다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 좁은 예외(경로·IP·필드) | WAF 설정 | 작음 | 다른 필드 오탐 | 기본 |
| 파트너에 절대 경로 요청 | 파트너 협조 | 중간 | 다른 파트너 | 보조 |
| WAF 차단 파트너 경로 경보 | 로그 연동 | 작음 | 없음 | 안전망 |

**결론**: 파트너 수신 경로는 WAF 차단을 경보로 본다. 예외는 좁게 둔다.

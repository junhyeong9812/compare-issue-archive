# issue/wafedge/empty-ua-managed-rule — 정답

태그: `environment-drift` · `false-positive`

## 정답
<!-- 질문 1:1 대응 -->

1. **403으로 막힌다.** 01-15 새벽 정산 배치 첫 단계에서 실패했다.

2. **표준 HTTP 라이브러리는 기본 UA를 보낸다.** 정산 배치만 직접 만든 경량 클라이언트였다.

3. **내부 API를 외부 공용 도메인으로 호출했다.** 내부 전용 경로가 있었지만 설정이 예전 그대로였다.

4. **규칙셋 릴리스 노트에 있었지만 자동 갱신이라 아무도 읽지 않았다.**

5. **자동 갱신 규칙은 7일 탐지 모드 후 차단.** 탐지 로그에 내부 호출이 걸리면 그 전에 고친다. 배치는 UA를 설정하고 내부 경로로 바꿨다.

## 문제 구조 (추상화 코드)

### 변형 A — 자동 갱신 즉시 차단
① 문제 코드
```yaml
managed_rules:
  auto_update: true
  new_rule_action: block
```
② 고친 코드
```yaml
managed_rules:
  auto_update: true
  new_rule_action: log          # 7일 관찰
  promote_after: 7d
```
무엇이 깨졌나: 보안 장비 정책이 외부 공급자에 의해 바뀌었는데, 변경을 관찰 없이 차단으로 바로 적용했다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 신규 규칙 탐지 모드 후 승격 | WAF 기능 | 작음 | 7일 노출 | 기본 |
| 배치 UA 설정 | 코드 수정 | 작음 | 없음 | 함께 |
| 내부 호출 내부 경로로 | DNS·설정 | 중간 | 경로 이원화 | 함께 |

**결론**: 외부에서 오는 정책 변경은 관찰 단계를 거쳐 적용한다.

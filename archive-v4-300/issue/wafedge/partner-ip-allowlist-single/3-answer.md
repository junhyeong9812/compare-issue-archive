# issue/wafedge/partner-ip-allowlist-single — 정답

태그: `silent-failure` · `environment-drift`

## 정답
<!-- 질문 1:1 대응 -->

1. **약 절반이 403으로 막힌다.** `.12`, `.13`에서 나간 요청이다.

2. **재전송이 허용된 IP로 나가면 통과했다.**

3. **공지 수신자가 이미 퇴사한 담당자 개인 메일이었다.**

4. **결과 통보를 못 받은 송금이 '처리 중'으로 남았다.** 고객 화면에도 그렇게 보여 문의가 늘었다. 이틀간 약 2,300건.

5. **제휴사가 공식 제공한 대역 단위 허용 + 연락처는 팀 메일.** 허용 목록 차단 건이 파트너 경로에서 생기면 즉시 경보.

## 문제 구조 (추상화 코드)

### 변형 A — 개별 IP 허용
① 문제 코드
```yaml
allowlist:
  /remit/callback: [198.51.100.10/32, 198.51.100.11/32]
```
② 고친 코드
```yaml
allowlist:
  /remit/callback: [198.51.100.8/29]     # 제휴사 공식 대역 (계약서 부속)
alerts:
  - on: allowlist_block
    path: /remit/callback
```
무엇이 깨졌나: 외부 파트너 인프라의 세부(개별 IP)를 우리 설정에 고정해, 파트너의 정상 변경이 장애가 됐다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 공식 대역 허용 | 파트너 문서 | 작음 | 대역 밖 변경 | 기본 |
| mTLS로 인증 전환 | 인증서 교환 | 중간 | 인증서 관리 | 장기 |
| 허용 목록 차단 경보 | 로그 연동 | 작음 | 없음 | 함께 |

**결론**: 파트너 식별은 IP보다 인증으로, IP를 쓰면 공식 대역과 차단 경보를 함께 둔다.

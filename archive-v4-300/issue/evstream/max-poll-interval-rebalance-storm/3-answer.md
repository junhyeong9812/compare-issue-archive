# issue/evstream/max-poll-interval-rebalance-storm — 정답

태그: `performance` · `rebalance`

## 정답
<!-- 질문 1:1 대응 -->

1. **5분을 넘겨 그룹에서 제외되고, 다시 합류해 같은 배치를 처리하다 또 제외된다.**

2. **배치당 처리 시간은 그대로였다.** 리밸런싱이 더 잦아져 오히려 악화됐다.

3. **멈춤은 풀리지만 진짜로 죽은 소비자 감지가 30분 늦어진다.** 배치 크기를 처리 시간에 맞추는 쪽이 낫다.

## 문제 구조 (추상화 코드)

### 변형 A — 처리 시간과 무관한 배치 크기
① 문제 코드
```properties
max.poll.records=500
max.poll.interval.ms=300000
```
② 고친 코드
```properties
max.poll.records=100
max.poll.interval.ms=300000
# 모델 호출 timeout 1s, 배치 내 8병렬 / 지표: poll 간격 p99 경보(> 120s)
```
무엇이 깨졌나: 배치 크기 × 건당 처리 시간이 폴링 간격 한도 안에 있다는 가정이 외부 지연 증가로 깨졌다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 배치 축소 + 타임아웃 | 없음 | 작음 | 처리량 소폭 감소 | 기본 |
| interval 확대 | 없음 | 작음 | 장애 감지 지연 | 보조 |

**결론**: 폴링 배치는 최악 처리 시간 기준으로 잡고, 외부 호출엔 타임아웃을 건다.

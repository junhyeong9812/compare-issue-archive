# issue/cpnengine/expiry-utc-midnight-kst-morning — 정답

태그: `timezone` · `data-semantics` · `cs`

## 정답
<!-- 질문 1:1 대응 -->

1. **"11월 30일 00:00 UTC + 1일" — 즉 한국 시각 11월 30일 09:00으로 저장됐다.**

2. **새 DB의 세션 시간대 기본값이 UTC였다.**\
관리자 API가 날짜를 세션 시간대 자정으로 바꾸는 코드를 그대로 썼다.

3. **목록 화면은 날짜 부분만 표시했다.**

4. **시간대 포함 저장, 만료 판정 경계 시각 테스트(만료일 08:59·09:01·23:59), 피해 고객 재발급과 안내.**

## 문제 구조 (추상화 코드)

### 변형 A — 시간대 없는 날짜를 세션 시간대에 맡김
① 문제 코드
```java
LocalDate d = req.expiryDate();
coupon.expiresAt = d.plusDays(1).atStartOfDay();       // 시간대 없음
```
② 고친 코드
```java
ZoneId KST = ZoneId.of("Asia/Seoul");
coupon.expiresAt = d.plusDays(1).atStartOfDay(KST).toInstant();   // 한국 만료일 끝
```
무엇이 깨졌나: 업무 시간대(한국)를 코드가 아닌 DB 세션 설정에 맡겨 이전과 함께 의미가 바뀌었다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 시간대 포함 저장 | 스키마 timestamptz | 작음 | 기존 데이터 변환 | 기본 |
| 경계 시각 테스트 | 테스트 | 작음 | 시간대 고정 테스트 환경 | 기본 |
| DB 세션 시간대 되돌림 | — | 작음 | 다음 이전 때 재발 | 선택하지 않은 방법 |

**결론**: 업무 시간대는 코드에 명시하고 시각은 시간대와 함께 저장한다.

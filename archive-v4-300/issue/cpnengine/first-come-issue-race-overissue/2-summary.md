# issue/cpnengine/first-come-issue-race-overissue — 정리 (힌트)

태그: `concurrency` · `data-integrity` · `cost`

## 전체 흐름

```
발급 요청 → ① 남은 수량 조회 (SELECT remain) → ② remain > 0 이면 쿠폰 생성 → ③ remain - 1 저장
초당 약 6,000 요청 → 여러 요청이 ① 에서 같은 remain 을 읽고 모두 ② 진행
부하 시험: 초당 300 → 경합 거의 없음
```

## 핵심 문장

- 원인은 **확인과 차감이 원자적이지 않은 것** — 동시 요청들이 같은 남은 수량을 읽고 모두 발급했다.
- 부하 시험은 실제 피크의 **5% 수준**이라 경합이 드러나지 않았다.
- 초과분은 이미 고객에게 발급·일부 사용돼 **회수 대신 비용 처리**했다.
- 대처는 원자적 차감(조건부 UPDATE 또는 원자 카운터) 후 발급, 발급 수 실시간 대사.

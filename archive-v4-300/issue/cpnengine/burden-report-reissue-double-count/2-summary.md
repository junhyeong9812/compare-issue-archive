# issue/cpnengine/burden-report-reissue-double-count — 정리 (힌트)

태그: `data-semantics` · `reconciliation` · `aggregation`

## 전체 흐름

```
주문 취소 → 쿠폰 복원: 원 쿠폰 "취소", 같은 쿠폰 ID 로 새 발급 행 생성
재주문 사용 → 새 발급 행 "사용"
분담금 리포트: 사용 이력 테이블에서 "사용 이벤트" 건수 집계 → 원 사용 + 재사용 = 2회
정산 시스템: 주문 단위 최종 할인액 기준 → 1회
```

## 핵심 문장

- 원인은 리포트가 **사용 이벤트를 세어** 취소 전 사용과 재사용을 둘 다 집계한 것이다.
- 31곳 공통점은 **3월에 주문 취소 후 쿠폰 복원·재사용이 있었던 판매자**다.
- 정산은 **주문 단위 최종 할인액**을 써 맞았다 — 두 시스템이 다른 기준으로 같은 숫자를 냈다.
- 대처는 리포트도 주문 최종 할인액 기준으로, 판매자 리포트에 주문 번호 단위 명세.

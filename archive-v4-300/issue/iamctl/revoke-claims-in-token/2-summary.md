# issue/iamctl/revoke-claims-in-token — 정리 (힌트)

태그: `consistency` · `security`

## 전체 흐름

```
13:40 로그인 → 액세스 토큰 {roles:[CUSTOMER_READ], exp: 14:40}
14:02 iamctl revoke → 권한 DB 에서 삭제  (토큰은 그대로)
14:20 고객 조회 API ── 토큰 서명·exp 만 검증 → roles 클레임에 CUSTOMER_READ → 허용
14:40 토큰 만료 → 리프레시 시도 → 권한 DB 조회 → 역할 없음 → 새 토큰에 빠짐
```

## 핵심 문장

- 리소스 서버는 **토큰 안의 역할 클레임만** 본다 — 권한 DB는 토큰 발급 때만 읽힌다.
- 회수는 **다음 토큰 발급(리프레시)부터** 반영된다 — 최대 액세스 토큰 수명만큼 늦다.
- 고위험 API(고객 원장 조회·다운로드)는 요청마다 권한 확인(토큰 조회 API)을 한다.
- 회수 시 해당 사용자 세션 폐기 이벤트를 보내 리프레시도 막는다.

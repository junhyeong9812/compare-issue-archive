# issue/iamctl/hr-delta-no-catchup — 정답

태그: `silent-failure` · `sync`

## 정답
<!-- 질문 1:1 대응 -->

1. **되지 않는다.** 15일 실행은 15일 변경분만 받는다. 14일 퇴사자 9명은 계속 활성이었다.

2. **15일 변경분 처리는 정상이었다.** 실패한 날이 있었는지 확인하는 단계가 없었다.

3. **`iamctl sync-hr --date 2024-11-14`.** 피드는 90일 전까지 날짜 지정 조회를 지원한다.

4. **전체 대사가 분기 1회였고, 14일 실패 경보는 '다음 날 재실행으로 해결'로 닫혔다.** 9명 중 2명은 VPN 계정도 남아 있었지만 접속 기록은 없었다.

5. **마지막 성공 날짜 기반 연동 + 주간 전체 대사.** 실패 경보는 빠진 날짜가 메워질 때까지 닫지 않는다.

## 문제 구조 (추상화 코드)

### 변형 A — 오늘만 요청
① 문제 코드
```python
changes = hr.changes(date=today())
apply(changes)
```
② 고친 코드
```python
last = state.get("hr_last_ok")
for d in daterange(last + 1, today()):
    apply(hr.changes(date=d))
    state.set("hr_last_ok", d)          # 성공한 날짜까지만 전진
```
무엇이 깨졌나: 변경분 동기화가 '매일 성공한다'는 가정 위에 있었다 — 실패한 하루가 영구적인 구멍이 됐다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 마지막 성공 날짜부터 수신 | 상태 저장 | 작음 | 피드 90일 한도 | 기본 |
| 주간 전체 대사 | 재직자 목록 API | 중간 | 주 단위 지연 | 안전망 |
| 실패 경보를 메워질 때까지 유지 | 경보 정책 | 작음 | 사람 의존 | 함께 |

**결론**: 변경분 연동은 성공 지점을 기억하고, 전체 대사를 주기적으로 붙인다.

# issue/smsgw/carrier-spam-filter-keyword — 정답

태그: `silent-failure` · `external-policy`

## 정답
<!-- 질문 1:1 대응 -->

1. **`0000`이다.** 게이트웨이·통신사 중계는 전달을 완료했고, 필터는 단말 단계에서 차단·스팸함 분류를 한다. 리포트로는 구별되지 않는다.

2. **필터 정책이 통신사마다 다르다.** 통신사 B는 그 달부터 단축 URL + 경품 문구 조합을 강하게 막았다. 당첨자 1,200명 중 B 가입자 410명 대부분이 문의했다.

3. **알림톡은 통신사 필터를 거치지 않는다** — 다만 템플릿 심사에서 광고성 문구로 반려될 수 있다.

4. **수신 실패 고객의 통신사 분포를 본다.** 한 통신사에 몰려 있고 DLR이 `0000`이면 필터를 의심하고, 해당 통신사 테스트 단말로 같은 문구를 보내 본다.

## 문제 구조 (추상화 코드)

### 변형 A — 문구 검증 없이 대량 발송
① 문제 코드
```python
body = f"[한빛페이] 축하합니다! 당첨 경품 무료 수령 {shorten(url)}"
smsgw.send_bulk(winners, body)
```
② 고친 코드
```python
body = f"[한빛페이] 이벤트 결과 안내: {full_url}"      # 단축 URL 금지, 경품 문구 최소화
for carrier, phone in TEST_DEVICES.items():           # 통신사별 시험 단말 3대
    smsgw.send(phone, body)
require_manual_confirm("통신사별 수신 확인")           # 확인 후 본발송
smsgw.send_bulk(winners, body)
```
무엇이 깨졌나: "전달 성공" 리포트를 "고객이 봤다"로 해석했다 — 리포트 뒤 단계(단말 필터)는 관측 밖이었다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 통신사별 시험 발송 | 시험 단말 3대 | 발송 전 10분 | 필터 정책 변경 시 재발 | 이벤트·중요 안내 |
| 알림톡 우선 + SMS 대체 | 알림톡 템플릿 | 심사 기간 | 템플릿 반려 | 정기 안내 |
| 문구 금칙어 사전 검사 | 금칙어 목록 | 작음 | 목록 낡음 | 기본 안전망 |

**결론**: 중요한 대량 문자는 통신사별 시험 단말로 먼저 확인하고, 단축 URL은 쓰지 않는다.

# issue/smsgw/tps-429-retry-no-jitter — 정리 (힌트)

태그: `performance` · `retry-storm`

## 전체 흐름

```
발송 워커 ×40 ──동시 요청──▶ smsgw (계약 한도 300 TPS)
                               │ 초과분
                               ▼
                         HTTP 429 Retry-After: 1
   워커: 1초 고정 대기 후 재시도 ──▶ 같은 순간에 다시 몰림 ──▶ 다시 429
   (재시도 요청도 한도를 소모 → 처리량 실질 120 TPS로 하락)
```

## 핵심 문장

- `smsgw`는 계약 TPS를 넘는 요청에 `429`와 `Retry-After: 1`을 준다 — 거부된 요청도 한도 계산 창(1초)에 포함된다.
- 워커 40개가 똑같이 1초 뒤 재시도하면 요청이 매초 같은 순간에 몰려 처리량이 오히려 떨어진다.
- 대처는 **클라이언트 측 토큰 버킷으로 한도 아래에서 보내기** + 재시도에 지수 백오프와 지터.
- 발송 속도는 워커 수가 아니라 계약 TPS가 정한다 — 워커를 늘리면 악화된다.

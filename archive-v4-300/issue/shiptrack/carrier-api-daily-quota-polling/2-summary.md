# issue/shiptrack/carrier-api-daily-quota-polling — 정리 (힌트)

태그: `resource-bounding` · `cost` · `integration`

## 전체 흐름

```
변경 전: 진행 중 운송장 × 30분 폴링 → 하루 약 60만 건 (한도 100만)
변경 후: 5분 폴링 → 하루 약 360만 건 페이스 → 15:00 한도 도달 → 429
화면: 조회 실패를 "정보 없음"으로 표시
00:00 한도 초기화 → 정상
```

## 핵심 문장

- 원인은 폴링 주기 단축으로 **택배사 일일 호출 한도를 오후에 소진**한 것이다.
- 한도 초과 응답(429)을 화면이 **"정보 없음"**으로 바꿔 고객 혼란을 키웠다.
- 택배사는 **상태 변경 콜백(웹훅)**을 제공했는데 쓰지 않고 있었다.
- 대처는 웹훅 전환, 폴링은 웹훅 누락 대비 2시간 주기, 사용량 경보, 조회 실패와 정보 없음 구분 표시.

# issue/shiptrack/carrier-new-status-code-unmapped — 정리 (힌트)

태그: `integration` · `contract-drift` · `partial-failure`

## 전체 흐름

```
택배사 상태 코드 → 매핑표 → 사내 상태
10/13~  신설 코드 "보관함 배송 완료" → 매핑표 없음 → 무시 (로그 DEBUG)
        → 주문 "배송 중" 유지 → 구매 확정 자동(완료 7일 뒤) 시작 안 됨 → 판매자 정산 밀림
다른 주문: 기존 "배송 완료" 코드 → 정상
```

## 핵심 문장

- 원인은 **택배사 신설 상태 코드가 매핑표에 없어** 무시된 것이다.
- 영향은 **무인 보관함으로 배송된 주문**에만 있었다 — 같은 택배사라도 일부만.
- 모르는 코드를 **DEBUG 로그로만 남기고 버린** 처리 방식이 무음 정지를 만들었다.
- 대처는 모르는 코드를 경보 큐로 보내기, 택배사 개발자 공지 구독, "배송 중 10일 초과" 주문 점검.

# issue/shiptrack/waybill-number-recycle-wrong-customer — 정리 (힌트)

태그: `identity` · `data-integrity` · `privacy`

## 전체 흐름

```
배송 이벤트 수신 → 운송장 번호로 주문 조회 (운송장 번호 단독 키)
택배사: 번호 대역 소진 시 오래된 번호 재사용 (2년 주기, 계약서 부록)
2026-01 → 2024-01 대 번호 재사용 시작 → 옛 주문에 새 이벤트 매칭 → 옛 주문 고객에게 알림
```

## 핵심 문장

- 원인은 **운송장 번호를 단독 키로** 주문을 찾은 것 — 택배사는 2년 주기로 번호를 재사용한다.
- 재사용 규칙은 **계약서 부록**에만 있었고 개발 문서에 없었다.
- 2026년 1월은 **연동 시작 2년 뒤**라 처음 재사용이 일어났다.
- 대처는 매칭 키를 (택배사, 운송장, 발송일 범위)로, 완료 후 일정 기간 지난 주문은 매칭 제외, 오발송 고객 안내.

# issue/cdcpipe/slot-recreated-snapshot-never-gap — 정답

태그: `silent-failure` · `data-loss`

## 정답
<!-- 질문 1:1 대응 -->

1. **전달되지 않는다.** 새 슬롯은 현재 LSN부터 시작하고, 스냅샷도 하지 않는다.

2. **비활성 슬롯이 WAL을 붙잡아 디스크가 85%를 넘었다.** 커넥터 정지가 배포 때문이라는 걸 몰랐다.

3. **저장된 오프셋을 슬롯이 이어 줄 수 없을 때 스냅샷을 다시 한다.** 대상 테이블이 커서 스냅샷이 2시간 걸리지만 누락은 없다.

4. **커넥터 로그의 슬롯 생성 기록과 누락 건의 커밋 시각을 맞춰 본다.** 누락이 한 연속 구간에 몰리면 이 사건이다.

## 문제 구조 (추상화 코드)

### 변형 A — 스냅샷 생략 설정
① 문제 코드
```properties
slot.name=cdc_stats
snapshot.mode=never
```
② 고친 코드
```properties
slot.name=cdc_stats
snapshot.mode=when_needed
# 운영: 슬롯 삭제는 커넥터 담당 승인 / 매일 원장 vs 통계 건수 대사
```
무엇이 깨졌나: 읽기 위치 보존 장치(슬롯)가 사라질 수 있다는 경우를 설정이 다루지 않았다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| when_needed 스냅샷 | 스냅샷 시간 허용 | 중간 | 긴 재적재 | 기본 |
| 슬롯 삭제 승인 절차 | 운영 합의 | 작음 | 긴급 시 무시 | 함께 적용 |
| 일 건수 대사 | 원장 조회 | 작음 | 하루 늦게 발견 | 항상 |

**결론**: 슬롯이 끊긴 재시작은 스냅샷으로 메우고, 일 건수 대사로 결과를 확인한다.

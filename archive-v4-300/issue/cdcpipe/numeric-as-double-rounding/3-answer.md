# issue/cdcpipe/numeric-as-double-rounding — 정답

태그: `data-semantics` · `precision`

## 정답
<!-- 질문 1:1 대응 -->

1. **1234.56이 될 수 있다.** 원장 decimal로는 1234.57이다.

2. **건별 차이는 반올림 경계 값에서만 생겨 드물다.** 수백만 건을 합치면 수십 원이 된다.

3. **소비자가 문자열을 decimal로 파싱해야 한다.** 분석 도구는 decimal 캐스팅 뷰로 해결했다.

4. **차이 난 건의 원장 값과 분석 저장소 값을 소수 넷째 자리까지 나란히 본다.** 꼬리 자리가 9999..로 끝나면 이 사건이다.

## 문제 구조 (추상화 코드)

### 변형 A — 금액을 부동소수로 전송
① 문제 코드
```properties
decimal.handling.mode=double
```
② 고친 코드
```properties
decimal.handling.mode=string
# 분석 저장소 컬럼: DECIMAL(18,4), 뷰에서만 형 변환
```
무엇이 깨졌나: 금액을 부동소수로 옮겼다 — 정확한 십진 값이 필요한 데이터를 근사 형식에 실었다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| string/precise 모드 | 소비자 파싱 | 작음 | 파싱 누락 | 기본 |
| 원장에서 정수(원·0.0001 단위)로 저장 | 스키마 변경 | 큼 | 이관 위험 | 신규 테이블 |

**결론**: 금액은 파이프라인 전 구간에서 십진 정확 형식으로 옮긴다.

# issue/tokvault/hsm-session-cap-latency — 정리 (힌트)

태그: `performance` · `hsm`

## 전체 흐름

```
tokvault 파드 6개 × 세션 풀 16 = 96
HSM 장비 세션 한도 64
      │  초과 파드는 세션 획득 대기
      ▼
p99 지연 증가, HSM CPU 는 40%
```

## 핵심 문장

- 병목은 HSM 성능이 아니라 **세션 수 한도**였다.
- 파드를 늘릴수록 세션 경합이 커졌다.
- 교정: 파드당 세션 풀을 한도 ÷ 파드 수로 맞추고, 세션 대기 시간 지표 추가.
- 자동 확장(HPA) 최대 파드 수도 세션 한도에서 거꾸로 계산해 상한을 걸었다 — 확장이 곧 경합 증가였다.

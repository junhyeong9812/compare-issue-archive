# issue/csdesk/phone-format-history-split — 정답

태그: `data-semantics` · `identity`

## 정답
<!-- 질문 1:1 대응 -->

1. **2024년 이후 이력만 보인다.** 팝업은 하이픈 없는 번호로 완전일치 검색을 한다.

2. **2023년 이전 상담 이력이 있는 고객만 저장 형식이 섞였기 때문이다.** 약 31만 명.

3. **반대로 2023년 이전 이력만 보인다.** 상담원 다수가 두 번 검색하는 요령으로 버텼다.

4. **상담원이 '처음 문의하신 건가요?'라고 물어 반복 민원 고객이 불만을 냈다.** 2월 한 달 관련 민원 27건.

5. **저장 시점에서 숫자만 남기는 정규화 함수 하나 + 기존 티켓 일괄 변환.** 국제번호는 `82` 시작을 `0`으로 바꾸는 규칙을 같은 함수에 둔다.

## 문제 구조 (추상화 코드)

### 변형 A — 형식 그대로 저장·검색
① 문제 코드
```sql
INSERT INTO ticket(phone, ...) VALUES (:raw_phone, ...);
SELECT * FROM ticket WHERE phone = :caller;
```
② 고친 코드
```sql
-- 저장 시 정규화 (앱 공통 함수 normalizePhone)
INSERT INTO ticket(phone, ...) VALUES (:normalized, ...);
UPDATE ticket SET phone = regexp_replace(phone, '[^0-9]', '', 'g')
WHERE phone ~ '[^0-9]';                    -- 기존 데이터 일괄 변환
```
무엇이 깨졌나: 같은 식별자를 연동마다 다른 표기로 저장해, 같은 고객이 검색 키 기준으로 둘이 됐다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|

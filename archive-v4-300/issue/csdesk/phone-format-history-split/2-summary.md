# issue/csdesk/phone-format-history-split — 정리 (힌트)

태그: `data-semantics` · `identity`

## 전체 흐름

```
티켓 연락처 저장
  ~2023-12  수기·구 IVR → "010-2231-0957"
  2024-01~  새 IVR      → "01022310957"
수신 전화 팝업 검색: WHERE phone = '01022310957' (완전일치)
  → 2024 티켓만 보임

2024 이후 첫 상담 고객 = 문제 없음 / 2023 이전 이력 보유 고객만 단절
```

## 핵심 문장

- 연락처 저장 형식이 **연동 교체 시점에 바뀌었고**, 검색은 완전일치였다.
- 2023년 이전 이력이 있는 고객만 이력이 둘로 갈렸다.
- 정규화는 **저장 시점 한 곳**(숫자만)과 기존 데이터 일괄 변환으로 한다.
- 검색 쪽에서 두 형식을 모두 찾는 임시 처리는 다른 형식(+82 등)을 또 놓친다.

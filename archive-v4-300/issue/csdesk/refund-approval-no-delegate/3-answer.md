# issue/csdesk/refund-approval-no-delegate — 정답

태그: `workflow` · `silent-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **2차 결재 대기에 머문다.** 결재자 부재를 확인하거나 넘기는 장치가 없었다.

2. **상태 표시가 1차 승인 기준이었기 때문이다.** 고객 안내도 '처리되었습니다'로 나갔다.

3. **1차 승인만으로 환불 요청이 나가 영향이 없었다.**

4. **결재 알림은 지정 결재자 메일로만 갔다.** 휴가 중 자동 회신만 쌓였다.

5. **대기 4시간 초과 시 같은 직급 대체 결재자 자동 배정, 화면 상태는 '2차 결재 대기'로 분리.** 휴가 등록 시 위임 설정을 필수로 했다.

## 문제 구조 (추상화 코드)

### 변형 A — 단일 결재자
① 문제 코드
```java
approval.assignTo(team.leader());     // 부재여도 그대로
```
② 고친 코드
```java
User approver = team.leader();
if (absence.isAway(approver)) approver = team.backupLeader();
approval.assignTo(approver, Duration.ofHours(4), team::nextAvailableApprover);
```
무엇이 깨졌나: 결재 흐름이 '결재자는 항상 있다'를 가정했고, 화면 상태가 중간 단계를 완료로 보여 줬다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 대기 상한 + 대체 결재자 | 결재 엔진 수정 | 중간 | 대체자도 부재 | 기본 |
| 휴가 등록 시 위임 필수 | 인사 시스템 연동 | 작음 | 급한 부재 | 함께 |
| 화면 상태 분리 | UI 수정 | 작음 | 없음 | 함께 |

**결론**: 결재는 시간 상한과 대체 경로를 가진다. 중간 상태를 완료로 보이지 않게 한다.

# issue/csdesk/ticket-offset-pagination-skip — 정답

태그: `silent-failure` · `pagination`

## 정답
<!-- 질문 1:1 대응 -->

1. **갱신 지점 뒤 페이지 경계의 티켓 한 건이 빠진다.** 갱신된 티켓이 맨 뒤로 옮겨 가면서 나머지가 한 칸씩 당겨진다.

2. **밤마다 갱신되는 티켓이 다르기 때문이다.** 누락은 순회 중 갱신 위치에 따라 매번 달라진다.

3. **생기지 않는다.** 2024년 7월 24시간 채팅 상담을 시작하기 전에는 같은 배치로 누락이 없었다.

4. **갱신된 티켓이 맨 뒤에서 한 번 더 읽혀 누락을 메웠기 때문이다.** 건수는 같고 ID 집합이 달랐다. 8월 한 달 누락 412건, 같은 수의 중복.

5. **`id > 마지막 id` 커서 + `updated_at <= 배치 시작 시각` 조건.** 시작 이후 갱신분은 다음 회차가 받는다. 이관 검증은 ID 집합 대조로 한다.

## 문제 구조 (추상화 코드)

### 변형 A — 가변 정렬 키 + 오프셋
① 문제 코드
```python
off = 0
while page := api.tickets(sort="updated_at", offset=off, limit=100):
    push(page); off += 100
```
② 고친 코드
```python
start, last = now(), 0
while page := api.tickets(sort="id", after_id=last, updated_before=start, limit=100):
    push(page); last = page[-1].id
```
무엇이 깨졌나: 순회하는 동안 정렬 순서가 바뀌는 집합을 위치(offset)로 나눠 읽었다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| id 커서 + 시작 시각 상한 | API 지원 | 작음 | 시작 후 갱신은 다음 회차 | 기본 |
| 스냅샷 export API | 벤더 기능 | 중간 | export 지연 | 대량 이관 |
| ID 집합 대조 | 이관 대상 조회 | 작음 | 사후 | 검증 |

**결론**: 바뀌는 데이터를 순회할 때는 바뀌지 않는 키로 커서를 잡는다.

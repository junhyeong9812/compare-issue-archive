# issue/csdesk/ticket-offset-pagination-skip — 정리 (힌트)

태그: `silent-failure` · `pagination`

## 전체 흐름

```
정렬 updated_at 오름차순, offset 페이지
  page k 읽는 중에 앞 페이지의 티켓 T 가 갱신 → T 는 맨 뒤로 이동
  → T 뒤의 모든 티켓이 한 칸씩 앞으로 → 다음 페이지 첫 건이 이전 페이지 끝으로 밀려 '건너뜀'
  T 자체는 맨 뒤에서 다시 읽힘(중복)

누락 수 ≈ 순회 중 갱신된 티켓 수 (야간 24시간 상담 채널 운영 후 증가)
처리 건수 = 누락 + 중복 상쇄 → 총건수는 비슷
```

## 핵심 문장

- **순회 중 정렬 키(updated_at)가 바뀌면** 오프셋 페이지는 뒤 레코드를 건너뛰고 바뀐 레코드는 두 번 읽는다.
- 누락과 중복이 상쇄돼 **처리 건수는 맞아 보인다**.
- 야간 상담이 없던 시절엔 문제가 없었다 — 2024-07 24시간 채팅 도입 이후 시작.
- **고정 키 커서(id) + 시작 시각 상한**으로 순회하고, 변경분은 다음 회차가 받는다.

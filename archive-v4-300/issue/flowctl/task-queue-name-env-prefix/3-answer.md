# issue/flowctl/task-queue-name-env-prefix — 정답

태그: `deploy` · `config`

## 정답
<!-- 질문 1:1 대응 -->

1. **성공이다.** 엔진은 큐에 폴러가 있는지 확인하지 않는다.

2. **기존 리전의 ENV 값이 마침 "prod"였다.**

3. **발견은 빨라지지만 원인은 남는다.** 이름 생성을 한 곳으로 모으는 것이 근본 대처다.

## 문제 구조 (추상화 코드)

### 변형 A — 양쪽에서 따로 만든 큐 이름
① 문제 코드
```yaml
# worker.yaml
taskQueue: prod-merchant-review
```
② 고친 코드
```yaml
# worker.yaml
taskQueue: ${FLOW_ENV}-merchant-review       # 시작 측과 같은 생성 규칙(공용 모듈)
# 경보: pollers(taskQueue) == 0 for 5m
```
무엇이 깨졌나: 같은 값을 두 곳에서 따로 정의했다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 공용 이름 생성 | 공용 모듈 | 작음 | 없음 | 기본 |
| 폴러 0 경보 | 지표 | 작음 | 없음 | 함께 적용 |

**결론**: 연결 키 역할의 이름은 한 곳에서만 만들고, 폴러 수를 감시한다.

# issue/cfgsvc/client-token-ttl-stale-node-cache — 정답

태그: `credential` · `cache` · `partial-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **노드별 설정 캐시의 마지막 갱신 성공 시각을 본다.**\
4대가 11월 20일 새벽 이후 갱신에 실패하고 있었다.

2. **8월 21일 기동 후 한 번도 재시작하지 않았다.**\
10월 배포 때 이 4대는 카나리 그룹 밖이라 재시작되지 않았다.

3. **서비스는 새 값을 주지만, 그 4대는 갱신 요청이 인증 실패로 거부돼 옛 캐시를 썼다.**

4. **SDK 기본 정책이 "가용성 우선 — 실패 시 마지막 값 유지"였다.**\
경고 로그는 남았지만 로그 경보 대상이 아니었다.

5. **설정 서비스에서 직접 읽은 값과 노드 캐시 값을 비교한다.**\
서비스 조회가 새 값이고 일부 노드만 옛 값이면 클라이언트 캐시·인증, 서비스 조회부터 옛 값이면 서비스 쪽 노출 시점 문제다.

## 문제 구조 (추상화 코드)

### 변형 A — 캐시 나이를 감시하지 않음
① 문제 코드
```java
Config cfg = sdk.current();       // 갱신 실패해도 마지막 값
```
② 고친 코드
```java
Config cfg = sdk.current();
if (sdk.lastRefreshSuccess().isBefore(now().minus(Duration.ofMinutes(10)))) {
    health.fail("config cache stale");   // 로드밸런서에서 빠짐
}
```
무엇이 깨졌나: "마지막 값 유지"가 실패를 가용성으로 바꾸면서 낡은 정도를 아무도 재지 않았다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 토큰 만료 전 자동 재발급 | SDK 지원 | 작음 | 재발급 실패 무음 | 기본 |
| 캐시 나이 헬스체크 | 헬스체크 연동 | 작음 | 설정 서비스 장애 시 전 노드 이탈 | 기본(임계 신중) |
| 정기 재시작 | 배포 파이프라인 | 작음 | 근본 해결 아님 | 선택하지 않은 방법 |

**결론**: 캐시 값은 나이와 함께 본다 — 낡은 설정은 장애로 취급한다.

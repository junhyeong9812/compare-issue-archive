# issue/cfgsvc/client-token-ttl-stale-node-cache — 정리 (힌트)

태그: `credential` · `cache` · `partial-failure`

## 전체 흐름

```
결제 서버 20대 — SDK: 30초마다 설정 갱신, 실패 시 마지막 캐시값 유지
읽기 토큰 TTL 90일, 노드 기동 시 발급
11/20  노드 4대 (8월 21일 기동, 이후 재시작 없음) → 토큰 만료 → 갱신 401
       SDK: 경고 로그 1줄 / 30초, 마지막 캐시값 계속 사용
       나머지 16대: 10월 배포로 재시작 → 토큰 신규 → 정상
로드밸런서 → 같은 가맹점 결제가 노드에 따라 옛 한도/새 한도
```

## 핵심 문장

- 원인은 **결제 서버 노드 4대의 설정 읽기 토큰 만료** — SDK는 갱신 실패 시 마지막 캐시값을 계속 썼다.
- 공통점은 **기동 시각** — 90일 넘게 재시작하지 않은 노드만 걸렸다.
- 설정 서비스 자체는 새 값을 주고 있었다 — 서비스 쪽 조회는 정상이라 **노드별 캐시 시각**을 봐야 보인다.
- 대처는 토큰 자동 갱신(만료 전 재발급), 캐시 나이(마지막 갱신 성공 후 경과) 지표·경보, 캐시가 10분 넘게 낡으면 헬스체크 실패.

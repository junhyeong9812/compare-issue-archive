# issue/dnsops/ndots-search-domain-amplification — 정답

태그: `performance` · `dns`

## 정답
<!-- 질문 1:1 대응 -->

1. **10번이다.** 검색 도메인 4개 + 원래 이름, 각각 A·AAAA.

2. **피크엔 커넥션이 늘며 새 연결마다 DNS 조회가 일어났다.** 클러스터 DNS가 포화돼 응답이 수십~수백 ms로 늘었다.

3. **곧바로 절대 이름으로 조회해 2번(A·AAAA)이 된다.**

4. **결제 네임스페이스 파드에 `dnsConfig.options ndots:2`**, 노드 로컬 DNS 캐시를 켰다.

## 문제 구조 (추상화 코드)

### 변형 A — 외부 호스트명을 상대 이름으로 설정
① 문제 코드
```yaml
pg:
  base-url: https://api.pgx.com
```
② 고친 코드
```yaml
pg:
  base-url: https://api.pgx.com.
# 또는 파드 spec.dnsConfig.options: [{ name: ndots, value: "2" }]
```
무엇이 깨졌나: 클러스터 내부 이름 편의를 위한 기본값이 외부 호출 비용을 키웠다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| ndots:2 | 파드 설정 | 작음 | 짧은 내부 이름 조회 실패 | 외부 호출 많은 서비스 |
| FQDN 표기 | 설정 수정 | 작음 | TLS SNI 처리 확인 필요 | 개별 호스트 |
| 노드 로컬 DNS 캐시 | 데몬셋 | 중간 | 캐시 장애 | 클러스터 전체 |

**결론**: 외부 호출이 많은 네임스페이스는 ndots를 낮추고 노드 로컬 캐시로 부하를 흡수한다.

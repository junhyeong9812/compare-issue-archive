# issue/dnsops/round-robin-stale-ip-no-fallback — 정답

태그: `silent-failure` · `dns`

## 정답
<!-- 질문 1:1 대응 -->

1. **약 3분의 1이 연결 타임아웃이다.**

2. **재시도 큐에서 같은 확률로 다시 실패했고, 3회 뒤 폐기됐다.** 그중 약 4%(1/3의 3제곱)가 최종 미발송이었다.

3. **두 번째 주소로 넘어가 전부 성공했을 것이다.** 지연만 늘었다.

4. **① DNS 레코드 제거 ② TTL 경과 대기 ③ 서버 종료** 순서. `dnsops check --probe`로 레코드 IP의 포트 응답을 확인한다.

## 문제 구조 (추상화 코드)

### 변형 A — 서버 종료 후 레코드 정리를 미룸
① 문제 코드
```sh
vm stop hook-relay-03
# dns 정리는 '나중에'
```
② 고친 코드
```sh
dnsops record del hook-relay A 10.20.1.19
sleep 600   # TTL 경과
vm stop hook-relay-03
```
무엇이 깨졌나: DNS가 상태 확인을 하지 않는다는 전제가 폐기 절차에 없었다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 레코드 선제거 절차 | 절차 준수 | 작음 | 사람 누락 | 기본 |
| 클라이언트 다중 주소 폴백 | 라이브러리 설정 | 작음 | 지연 증가 | 함께 |
| 헬스체크 있는 LB 뒤로 | LB 비용 | 중간 | LB 장애 | 장기 |

**결론**: 폐기 순서를 고치고 클라이언트 폴백을 켠다. 미발송 웹훅은 원장 기준으로 재발송했다.

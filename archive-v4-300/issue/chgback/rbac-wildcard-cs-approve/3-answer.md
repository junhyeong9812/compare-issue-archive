# issue/chgback/rbac-wildcard-cs-approve — 정답

태그: `security` · `authorization`

## 정답
<!-- 질문 1:1 대응 -->

1. **정리 당시 chargeback 아래 권한이 read뿐이었다.** 이후 accept가 추가되며 자동으로 포함됐다.

2. **카드사 확정 후라 되돌릴 수 없었다.** 손실로 처리하고 재발 방지에 집중했다.

3. **역할별 펼친 권한 목록을 배포 전후로 비교하는 리포트.**

## 문제 구조 (추상화 코드)

① 문제 코드
```yaml
CS_AGENT: [ "chargeback:*" ]
```
② 고친 코드
```yaml
CS_AGENT: [ "chargeback:read" ]
# CI: 역할 정의에 '*' 금지, 변경 시 effective-permissions diff 첨부
```
무엇이 깨졌나: 권한을 이름 패턴으로 묶어 미래 권한까지 열었다.

## 방안 비교

| 방안 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|
| 명시 권한 + diff 리뷰 | 작음 | 없음 | 기본 |
| 와일드카드 유지 + 정기 점검 | 작음 | 점검 사이 노출 | 선택하지 않음 |

**결론**: 권한은 명시 목록으로 주고, 변경은 펼친 결과로 리뷰한다.

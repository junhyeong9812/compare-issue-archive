# issue/ledgerctl/ha-failover-double-batch-run — 정리 (힌트)

태그: `concurrency` · `idempotency` · `deployment`

## 전체 흐름

```
6/1 22:00  크론 노드 이중화 전환 작업 (standby 승격 리허설)
           리허설 후 옛 active 의 크론 데몬 비활성화 누락 → 두 노드 모두 active
6/2 01:30  노드 A: 환불 전표 배치 → 전표 N건 기장
    01:30  노드 B: 환불 전표 배치 → 같은 N건 다시 기장
정산 전표 배치: 사내 분산 잠금(DB advisory lock) 사용 → B 는 잠금 실패로 건너뜀
환불 전표 배치: 잠금 없음 (신규 배치, 2024-05 추가)
```

## 핵심 문장

- 원인은 원장 CLI가 아니라 **배치가 두 노드에서 동시에 실행**된 것이다 — 이중화 리허설 후 옛 노드의 크론이 살아 있었다.
- 정산 전표 배치는 **분산 잠금**이 있어 한 번만 돌았고, 5월에 새로 만든 환불 전표 배치만 잠금이 빠져 있었다.
- 리허설 체크리스트는 승격만 확인하고 **옛 노드 정지 확인**이 없었다.
- 대처는 모든 배치에 공통 잠금 래퍼 적용, 배치 회차 키를 전표 참조에 넣어 대사에서 중복을 바로 찾게 한다.

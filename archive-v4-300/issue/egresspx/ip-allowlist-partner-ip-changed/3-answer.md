# issue/egresspx/ip-allowlist-partner-ip-changed — 정답

태그: `silent-failure` · `network`

## 정답
<!-- 질문 1:1 대응 -->

1. **프록시가 403으로 막는다.**

2. **재시도 큐 길이 경보가 없었고, 개별 실패는 정상 재시도로 기록됐다.**

3. **새 IP로도 허용됐다.**

4. **SNI 도메인 기반 허용으로 바꾸고, `X-Egress-Denied` 응답은 비재시도 오류로 분류해 경보.**

## 문제 구조 (추상화 코드)

### 변형 A — IP 기준 허용
① 문제 코드
```yaml
allow:
  - { dst_ip: 203.0.113.10, port: 443 }
```
② 고친 코드
```yaml
allow:
  - { sni: notify.cardx.example, port: 443 }
```
무엇이 깨졌나: 상대 시스템의 주소가 고정이라는 가정이 허용 규칙에 묻혀 있었다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| SNI 기반 허용 | 프록시 기능 | 작음 | SNI 위장 위험(통제 필요) | 기본 |
| 거부 응답 비재시도 분류 | 앱 수정 | 작음 | 없음 | 함께 |
| 상대 IP 변경 사전 공지 의존 | 파트너 협조 | 작음 | 공지 누락 | 선택하지 않은 방법 |

**결론**: 허용을 도메인으로 바꾸고 프록시 거부는 즉시 드러나게 한다.

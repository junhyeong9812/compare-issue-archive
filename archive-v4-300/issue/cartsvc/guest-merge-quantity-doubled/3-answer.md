# issue/cartsvc/guest-merge-quantity-doubled — 정답

태그: `data-integrity` · `ux` · `merge`

## 정답
<!-- 질문 1:1 대응 -->

1. **비로그인 상태와 로그인 상태 양쪽에 같은 상품을 담아 둔 고객이다.**

2. **같은 상품은 수량을 더했다.**

3. **개편 뒤 자동 로그인 갱신마다 병합이 호출되고, 병합 뒤 비로그인 장바구니가 지워지지 않았다.**

4. **병합 완료 표시와 삭제를 한 트랜잭션으로, 같은 상품은 합산 대신 큰 수량, 병합 호출 지점은 명시적 로그인 한 곳.**

## 문제 구조 (추상화 코드)

### 변형 A — 멱등하지 않은 병합
① 문제 코드
```java
for (Item g : guestCart) loginCart.add(g.sku(), g.qty());   // 합산
```
② 고친 코드
```java
tx(() -> {
    for (Item g : guestCart) loginCart.setMax(g.sku(), g.qty());
    guestCart.delete();
});
```
무엇이 깨졌나: 병합이 여러 번 불려도 결과가 같아야 했는데, 합산 규칙과 삭제 누락이 반복 호출에 약했다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 병합 + 삭제 한 트랜잭션 | 같은 저장소 | 작음 | 저장소 분리 시 불가 | 기본 |
| 큰 수량 규칙 | 사업 합의 | 작음 | 의도적 추가 손실 | 기본 |
| 병합 호출 지점 단일화 | 앱 수정 | 중간 | 앱 버전 혼재 | 병행 |

**결론**: 병합은 몇 번 불려도 같은 결과가 나오게 만든다.

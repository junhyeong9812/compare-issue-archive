# issue/cartsvc/ttl-set-on-create-active-cart-expire — 정답

태그: `data-loss` · `cache` · `partial-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **7일 전에 장바구니를 처음 만든 고객이다.**\
그 뒤 상품을 계속 담았어도 만료가 연장되지 않아 생성 7일째에 통째 사라졌다.

2. **새 클라이언트가 쓰기 때 만료를 재설정하지 않았다.**\
옛 라이브러리는 쓰기 명령에 만료 갱신을 자동으로 붙였다.

3. **수정이 만료를 연장하지 않았기 때문이다.**

4. **매일 "7일 전 처음 담은 고객"만큼씩 만료됐다.**\
이전 직후 일주일은 증상이 없어 이전과 연결이 늦었다.

5. **장바구니 전체가 비었는지, 일부 상품만 빠졌는지 본다.**\
통째로 비면 키 만료·소실, 일부만 빠지면 상품 단위 규칙(판매 종료·옵션 변경)을 본다.

## 문제 구조 (추상화 코드)

### 변형 A — 생성 시에만 만료 설정
① 문제 코드
```java
if (!store.exists(key)) store.expire(key, Duration.ofDays(7));
store.hset(key, sku, qty);
```
② 고친 코드
```java
store.hset(key, sku, qty);
store.expire(key, Duration.ofDays(30));      // 쓰기마다 연장
```
무엇이 깨졌나: 이전 전 라이브러리의 암묵 동작(만료 자동 연장)을 명시 코드로 옮기지 않았다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 쓰기마다 만료 연장 | — | 작음 | 쓰기 누락 경로 | 기본 |
| 로그인 고객 장바구니 DB 저장 | 스키마 | 중간 | 쓰기 부하 | 장기 |
| 만료 길이만 늘림 | — | 작음 | 문제 지연일 뿐 | 선택하지 않은 방법 |

**결론**: 저장소 이전은 데이터뿐 아니라 만료 같은 암묵 동작까지 옮긴다.

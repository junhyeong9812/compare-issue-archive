# issue/cartsvc/promo-end-price-snapshot-mismatch — 정답

태그: `data-consistency` · `cache` · `ux`

## 정답
<!-- 질문 1:1 대응 -->

1. **7월 말에 프로모션 상품을 담아 두고 8월에 결제하려던 고객이다.**

2. **담을 때 가격을 저장해 두고 그대로 표시했다.**\
가격 서비스 호출을 줄이려던 설계였다.

3. **결제 화면의 현재 가격이 맞다.**\
프로모션은 이미 끝났다.

4. **표시용 가격은 현재 가격(5분 캐시), 담을 때와 다르면 변동 표시, 프로모션 종료 전 알림 발송.**

## 문제 구조 (추상화 코드)

### 변형 A — 표시 가격을 스냅샷에 고정
① 문제 코드
```java
cartView.price = item.snapshotPrice();
```
② 고친 코드
```java
Price now = priceCache.get(item.sku());           // 5분 캐시
cartView.price = now;
cartView.changed = !now.equals(item.snapshotPrice());
```
무엇이 깨졌나: 같은 상품의 가격 출처가 화면마다 달라 고객이 본 금액과 청구 금액이 갈렸다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 현재 가격 + 짧은 캐시 | 가격 서비스 용량 | 작음 | 캐시 기간 중 차이 | 기본 |
| 가격 변동 표시 | 스냅샷 유지 | 작음 | 화면 복잡 | 기본 |
| 담은 가격 보장 | 사업 결정 | 큼 | 손실 | 선택하지 않은 방법 |

**결론**: 고객에게 보이는 금액의 출처는 하나로 맞춘다.

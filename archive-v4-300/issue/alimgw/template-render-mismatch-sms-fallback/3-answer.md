# issue/alimgw/template-render-mismatch-sms-fallback — 정답

태그: `contract-drift` · `cost`

## 정답
<!-- 질문 1:1 대응 -->

1. **접수는 200, 고객은 알림톡을 받지 못한다.** 대체발송이 켜져 있으면 같은 내용의 SMS/LMS가 가고, 꺼져 있으면 아무것도 가지 않는다. 결과 조회에 `K105`가 남는다.

2. **대부분 경로가 대체발송을 켜 두었기 때문이다.** 고객은 문자로 받아 문의가 적었고, 일주일 뒤 문자 비용이 평소의 3.1배로 나와 추적이 시작됐다.

3. **같다.** 가맹점명에 줄바꿈이 포함된 소수 가맹점은 이전부터 매번 대체발송되고 있었다 — 이번 조사에서 함께 발견됐다.

4. **결과 조회의 실패 코드를 본다.** `K105`면 본문 불일치, 수신자 측 코드(차단·미가입)면 고객 쪽이다. 대체발송 비율이 갑자기 오르면 이 사건을 먼저 의심한다.

## 문제 구조 (추상화 코드)

### 변형 A — 문자열 결합으로 본문 생성
① 문제 코드
```java
String body = name + "님, " + store + " 결제 " + amount + "원이 완료됐습니다. ";
alimgw.send(T0412, phone, body, Fallback.SMS);
```
② 고친 코드
```java
String body = Templates.render(T0412, Map.of("고객명", name, "가맹점", oneLine(store), "금액", amount));
if (!Templates.matches(T0412, body)) throw new TemplateMismatch(T0412);   // 승인 원문과 대조
alimgw.send(T0412, phone, body, Fallback.SMS);
```
무엇이 깨졌나: 승인된 원문을 기준으로 본문을 만들지 않고 코드에서 다시 써서, 게이트웨이의 정확 일치 규칙에 걸렸다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 승인 원문 기반 렌더 + 대조 | 템플릿 원문 동기화 | 작음 | 원문 동기화 누락 | 기본 |
| 대체발송 비율 경보 | 일별 집계 | 작음 | 하루 늦게 발견 | 안전망 |

**결론**: 본문은 승인 원문에서만 만들고, 대체발송 비율을 지표로 본다.

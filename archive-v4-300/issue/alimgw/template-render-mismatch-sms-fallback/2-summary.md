# issue/alimgw/template-render-mismatch-sms-fallback — 정리 (힌트)

태그: `contract-drift` · `cost`

## 전체 흐름

```
승인 템플릿 T0412: "#{고객명}님, #{가맹점} 결제 #{금액}원이 완료됐습니다."
발송 본문(코드):   "#{고객명}님, #{가맹점} 결제 #{금액}원이 완료됐습니다. "   ← 끝 공백 하나
   alimgw: 접수 200 → 카카오 단계 템플릿 대조 실패(코드 K105)
            ├─ fallback=sms 설정 건 → SMS 대체발송 (건당 비용 약 2.5배)
            └─ fallback 미설정 건(해외 가맹점 경로) → 실패, 결과 조회에만 K105
```

## 핵심 문장

- `alimgw`는 접수 시 본문을 검사하지 않는다 — 템플릿 대조는 **발송 단계**에서 하고 결과는 조회 API로만 보인다.
- 대조는 **치환 후 본문 전체의 정확한 일치**다 — 줄바꿈·끝 공백·전각 기호 하나도 불일치다.
- 이번 건은 문구 수정 배포에서 문자열 결합 끝에 공백이 붙었다. 대체발송이 켜진 경로는 문자로 가서 비용만 늘었고, 꺼진 경로는 누락됐다.
- 대처: 발송 전에 승인 템플릿과 치환 결과를 같은 함수로 대조하는 검사, 대체발송 비율 경보.

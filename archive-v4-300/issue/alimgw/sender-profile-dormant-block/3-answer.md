태그: `credential-lifecycle` · `ops`

## 정답
<!-- 질문 1:1 대응 -->

1. **즉시 `400 P301`이다.** 이 사건은 조용한 실패가 아니라 명시적 거절이었다 — 다만 재개 당일 아침에야 처음 보냈다.

2. **리허설을 스테이징의 시험 프로필로 했다.** 운영 프로필은 한 번도 호출되지 않았다.

3. **대표 프로필(hb-main)로 같은 템플릿을 재심사 없이 쓸 수 없었다** — 템플릿은 프로필 단위로 승인된다. 하루 동안 SMS로 안내했다.

## 문제 구조 (추상화 코드)

### 변형 A — 운영 자격 상태를 확인하지 않은 재개
① 문제 코드
```sh
# 재개 체크리스트
deploy remit-service --enable
```
② 고친 코드
```sh
alimgw profile show hb-remit | grep -q 'status=ACTIVE' || { echo "휴면/정지"; exit 1; }
alimgw send --dry-run --profile hb-remit --template R001 --to "$OPS_PHONE"
deploy remit-service --enable
```
무엇이 깨졌나: 오래 쓰지 않은 외부 자격(발신 프로필)의 상태를 재개 전에 운영 환경에서 확인하지 않았다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 재개 전 운영 프로필 실발송 점검 | 운영 담당 번호 | 작음 | 없음 | 기본 |
| 휴면 방지용 월 1회 발송 | 내부 수신자 | 작음 | 정책 위반 소지 | 선택하지 않음 |

**결론**: 외부 자격은 공용 관리자 연락처로 두고, 재개 전에 운영 프로필로 실발송 점검을 한다.

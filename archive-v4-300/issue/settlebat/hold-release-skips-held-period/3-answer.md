# issue/settlebat/hold-release-skips-held-period — 정답

태그: `data-meaning` · `state-transition`

## 정답
<!-- 질문 1:1 대응 -->

1. **3/05 이후 매출만 들어간다.** 보류 기간 매출은 '정산 대기'로 남았다.

2. **신규 가맹점은 가입 시각 이전 매출이 없다.**

3. **아주 오래된 '정산 대기' 매출이 갑자기 지급되지 않는지 — 대기 매출 목록을 먼저 검토했다.**

4. **매출의 정산 상태가 '대기'로 남은 기간과 가맹점 상태 이력을 맞대 본다.**

## 문제 구조 (추상화 코드)

① 문제 코드
```sql
WHERE m.st = 'ACTIVE' AND s.sale_date >= m.status_changed_at AND s.st = 'PENDING'
```
② 고친 코드
```sql
WHERE m.st = 'ACTIVE' AND s.st = 'PENDING'
```
무엇이 깨졌나: 다른 목적의 시각 필드를 정산 범위 조건으로 재사용했다.

## 방안 비교

| 방안 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|
| 상태 기반 대상 선정 | 작음 | 오래된 대기 매출 검토 필요 | 기본 |
| 보류 해제 시 수동 정산 | 반복 | 누락 | 선택하지 않음 |

**결론**: 정산 대상은 매출의 정산 상태로 고른다.

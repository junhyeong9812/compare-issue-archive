# issue/etaxbr/sync-issue-timeout-thread-block — 정리 (힌트)

태그: `performance` · `coupling`

## 전체 흐름

```
가맹점 가입 API → 가입비 결제 → etaxbr issue (동기, 타임아웃 30s)
      │  중계사 응답 없음 → 스레드 30s 대기
      ▼
톰캣 스레드 200개 소진 → 가입 외 API 까지 503
```

## 핵심 문장

- 세금계산서 발행은 가입 완료의 조건이 아니다 — 동기일 이유가 없었다.
- 타임아웃 30초 × 스레드 200개 = 분당 400건이면 포화된다.
- 교정: 발행을 아웃박스 테이블 + 비동기 워커로 분리, 동기 경로의 외부 호출은 타임아웃 3초·벌크헤드.

# issue/etaxbr/api-key-rotation-grace-end — 정답

태그: `auth` · `credential-rotation`

## 정답
<!-- 질문 1:1 대응 -->

1. **스테이징 갱신 후 운영 반영이 별도 티켓으로 미뤄졌다.**

2. **전부 실패하면서 중계사 쪽 IP 단위 rate limit에 걸린다.** 새 키를 넣은 뒤에도 20분간 429가 났다.

3. **거의 없다.** 중계사 장애 시 401을 잘못 내는 사례가 한 번 있었지만, 그래도 첫 건에서 멈추고 사람이 판단하는 편이 싸다.

4. **비밀 저장소에 만료일을 기록하고 14일 전 경보를 둔다.** 인증 오류는 배치 중단 조건이다.

## 문제 구조 (추상화 코드)

① 문제 코드
```python
for inv in batch: retry(lambda: etax.issue(inv), times=3)
```
② 고친 코드
```python
for inv in batch:
    try: etax.issue(inv)
    except AuthError: alert('etaxbr auth'); break       # 첫 건에서 중단
```
무엇이 깨졌나: 재시도 불가 오류를 일시 오류처럼 다뤘고, 자격증명 만료를 관리하지 않았다.

## 방안 비교

| 방안 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|
| 인증 오류 즉시 중단 + 만료 경보 | 작음 | 경보 무시 | 기본 |
| 구 키 유예 연장 요청 | 협의 | 임시방편 | 보조 |

**결론**: 자격증명은 만료일을 데이터로 관리하고, 인증 실패는 배치 중단 조건으로 둔다.

# issue/consentdb/purge-cascade-tx-records — 정답

태그: `irreversible` · `data-retention`

## 정답
<!-- 질문 1:1 대응 -->

1. **그 회원의 거래 기록 전부가 지워진다.**

2. **전자금융거래법상 5년 보관 의무가 있다.** 개인정보 파기 의무와 별개다.

3. **일 백업 30일·월 백업 12개월이 있어 6~8월 삭제분을 월 백업 + 일 백업으로 복구했다.** 약 41만 행. 개인 식별 컬럼은 복구 후 바로 비식별화했다.

4. **거래 기록 조회가 드물었다.** 9월 분쟁 조정 요청에서 원거래를 찾다 발견했다.

5. **파기 배치는 `member`의 이름·연락처 등을 비식별화하고 행은 남긴다.** FK는 RESTRICT로 되돌리고, 스키마 변경 리뷰에 'CASCADE 추가 = 데이터 보관 검토' 항목을 넣었다.

## 문제 구조 (추상화 코드)

### 변형 A — 회원 행 삭제
① 문제 코드
```sql
DELETE FROM member WHERE withdrawn_at < now() - interval '30 days';
```
② 고친 코드
```sql
UPDATE member SET name = NULL, phone = NULL, email = NULL, purged = true
WHERE withdrawn_at < now() - interval '30 days' AND NOT purged;
-- 행 삭제는 보관 기간(5년) 경과 후 별도 배치
```
무엇이 깨졌나: 개인정보 파기를 행 삭제로 구현해, 참조 무결성 설정이 다른 법적 의무 데이터까지 지웠다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 비식별화 + 보관 기간 후 삭제 | 컬럼 구분 | 중간 | 비식별 누락 컬럼 | 기본 |
| FK RESTRICT | 스키마 변경 | 작음 | 고아 행 관리 | 함께 |
| 보관 테이블 분리 | 구조 변경 | 큼 | 이중 쓰기 | 장기 |

**결론**: 파기와 보관은 다른 의무다. 삭제는 연쇄 효과를 검토한 뒤에만 쓴다.

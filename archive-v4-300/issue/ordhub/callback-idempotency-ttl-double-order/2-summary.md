# issue/ordhub/callback-idempotency-ttl-double-order — 정리 (힌트)

태그: `idempotency` · `retry` · `data-integrity`

## 전체 흐름

```
결제 완료 콜백 → 허브: 멱등 키(결제 ID) 를 캐시에 10분 보관
19:00~19:40  결제 대행 콜백 큐 적체 → 첫 콜백 응답 대기 중 허브 타임아웃 → 결제 대행 재시도
             재시도 도착: 첫 콜백 후 11~18분 → 멱등 키 만료 → 새 주문 생성
평시: 재시도 도착 1분 이내 → 멱등 키 살아 있음
```

## 핵심 문장

- 원인은 **멱등 키 보관 시간(10분)이 재시도 도착 간격보다 짧았던 것**이다.
- 평시 재시도는 1분 안에 와서 문제가 없었다 — **상대 적체 때만** 간격이 벌어졌다.
- 진짜 멱등성은 캐시가 아니라 **주문 테이블의 결제 ID 유일 제약**으로 지켜야 한다.
- 대처는 결제 ID 유일 인덱스, 캐시 보관 24시간, 이중 출고 63건은 회수·취소 처리.

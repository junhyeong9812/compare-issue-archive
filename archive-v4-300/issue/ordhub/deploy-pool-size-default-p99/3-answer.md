# issue/ordhub/deploy-pool-size-default-p99 — 정답

태그: `config` · `deployment` · `latency`

## 정답
<!-- 질문 1:1 대응 -->

1. **DB 커넥션 풀 대기 시간과 활성 커넥션 수를 본다.**\
활성 10에 붙어 있고 대기가 쌓였다.

2. **통합 과정에서 운영 전용 `pool.max=60` 줄이 빠져 기본값 10이 적용됐다.**

3. **스테이징 시험의 동시 요청이 8이라 기본값으로도 충분했다.**

4. **시작 시 핵심 설정 값 출력·하한 검증, 풀 대기 시간 경보, 부하 시험 동시성을 운영 피크의 1.5배로.**

## 문제 구조 (추상화 코드)

### 변형 A — 핵심 설정 누락을 기본값으로 조용히 대체
① 문제 코드
```yaml
datasource:
  url: ${DB_URL}
  # pool.max 없음 → 라이브러리 기본 10
```
② 고친 코드
```yaml
datasource:
  url: ${DB_URL}
  pool:
    max: ${DB_POOL_MAX:?DB_POOL_MAX required}   # 없으면 기동 실패
```
무엇이 깨졌나: 운영 필수 값이 기본값으로 조용히 대체돼 설정 정리가 성능 변경이 됐다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 필수 설정 기동 검증 | 설정 목록 정의 | 작음 | 목록 누락 | 기본 |
| 풀 대기 시간 경보 | 지표 수집 | 작음 | 임계 설정 | 기본 |
| 운영 피크 기준 부하 시험 | 시험 환경 | 중간 | 시험 데이터 차이 | 병행 |

**결론**: 운영에 필수인 설정은 기본값을 허용하지 않는다.

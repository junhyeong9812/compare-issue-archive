# issue/ordhub/live-commerce-hot-partition-lag — 정리 (힌트)

태그: `latency` · `partitioning` · `capacity`

## 전체 흐름

```
주문 이벤트 → 파티션 = hash(가맹점 ID) % 24
21:00 라이브 방송 (가맹점 M-2071) → 분당 4,800건 → 파티션 7 하나로
      파티션 7 소비자 1개: 분당 1,200건 처리 → 지연 누적 최대 25분
      나머지 23개 파티션: 한가함
결과: 주문 확인 알림 지연, 재고 차감 지연 → 한정 수량 초과 판매 140건
```

## 핵심 문장

- 원인은 **파티션 키가 가맹점 ID**라 한 가맹점의 폭주가 파티션 하나에 몰린 것이다.
- 클러스터 전체 여유와 무관하게 **한 파티션 = 한 소비자**의 처리량이 상한이었다.
- 가맹점 ID를 키로 둔 이유는 **가맹점 안 주문 순서 보장**이었다 — 실제로 필요한 순서는 주문 단위였다.
- 대처는 키를 주문 ID로 변경(주문 단위 순서만 보장), 파티션별 지연 경보, 한정 수량 상품은 재고 차감을 동기 경로로.

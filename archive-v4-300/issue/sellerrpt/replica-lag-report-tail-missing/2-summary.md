# issue/sellerrpt/replica-lag-report-tail-missing — 정리 (힌트)

태그: `replication` · `data-freshness` · `partial-failure`

## 전체 흐름

```
주 DB → 읽기 복제본 (평소 지연 < 1초)
11/11 행사: 쓰기 폭증 → 복제 지연 최대 45분
00:05 리포트 생성 (복제본 조회) → 복제본 시각 ≈ 23:20 → 이후 거래 없음
재생성(오전): 복제 따라잡음 → 정상
```

## 핵심 문장

- 원인은 **복제 지연 중인 읽기 복제본**에서 마감 리포트를 만든 것이다.
- 평소 복제 지연은 1초 미만이라 차이가 없었고 **행사 날 쓰기 폭증**으로 45분까지 밀렸다.
- 다시 만들면 정상 — **재현이 안 돼** 원인 파악이 늦었다.
- 대처는 리포트 생성 전 복제본 지연 확인(마감 시각 이후 데이터 도착까지 대기), 마감 리포트는 주 DB 스냅샷 또는 지연 확인 후 생성, 리포트에 기준 시각 표시.

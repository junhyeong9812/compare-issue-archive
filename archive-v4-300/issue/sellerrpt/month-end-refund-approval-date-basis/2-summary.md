# issue/sellerrpt/month-end-refund-approval-date-basis — 정리 (힌트)

태그: `data-semantics` · `reconciliation` · `cutoff`

## 전체 흐름

```
환불 요청 3/31 21:00 → PG 승인 4/01 02:00 (야간 일괄 승인)
sellerrpt: 환불 요청일 기준 → 3월
PG 정산:  환불 승인일 기준 → 4월
평소: 월말 야간 환불 수십 건 → 차이 수십만 원 → "반올림 오차"로 넘김
3월: 봄맞이 행사 반품 몰림 → 1,840만 원
4월 리포트: 반대로 PG 쪽이 그만큼 많음 → 두 달 합은 일치
```

## 핵심 문장

- 원인은 두 시스템의 **환불 귀속 기준일이 다른 것** — 리포트는 요청일, PG는 승인일이다.
- 차이 건은 **월말 밤에 요청되고 다음 달 새벽 승인된 환불**이다.
- 두 달을 합치면 일치한다 — **누락이 아니라 이월**이다.
- 대처는 리포트 기준일을 승인일로 맞추고, 리포트에 "다음 달 승인 대기" 항목을 따로 표시.

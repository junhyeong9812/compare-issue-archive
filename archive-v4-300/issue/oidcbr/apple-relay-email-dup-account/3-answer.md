# issue/oidcbr/apple-relay-email-dup-account — 정답

태그: `identity`

## 정답
<!-- 질문 1:1 대응 -->

1. **연결되지 않고 새 계정이 생긴다.**

2. **실제 이메일이 와서 기존 회원과 일치했다.**

3. **한 번 연결한 뒤 같은 사용자를 찾는 키로 쓴다.** 처음 연결에는 쓸 수 없다.

4. **포인트·쿠폰·결제수단이 없는 새 계정에 들어갔다.** 2월 한 달 약 3,800건, 계정 병합 요청이 몰렸다.

5. **신규 소셜 사용자는 '기존 회원이세요?' 단계 → 기존 계정 로그인 → `sub` 연결.** 이미 생긴 중복 계정은 고객 요청 시 병합 도구로 합쳤다.

## 문제 구조 (추상화 코드)

### 변형 A — 이메일 일치 없으면 자동 가입
① 문제 코드
```java
Member m = members.findByEmail(token.email())
    .orElseGet(() -> members.create(token));
```
② 고친 코드
```java
Optional<Member> m = links.findBySub("apple", token.sub())
    .or(() -> members.findByEmail(token.email()));
if (m.isEmpty()) return redirect("/link-or-signup");   // 사용자 선택
```
무엇이 깨졌나: 외부 IdP가 주는 속성(이메일)을 안정적인 식별자로 가정했다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 연결 또는 가입 선택 단계 | UI 추가 | 중간 | 이탈 | 기본 |
| 휴대폰 본인확인으로 자동 연결 | 본인확인 비용 | 중간 | 비용 | 보조 |
| 병합 도구 | 운영 | 중간 | 포인트 충돌 | 사후 |

**결론**: 외부 계정은 자체 식별자(sub)로 연결하고, 첫 연결은 사용자 확인을 거친다.

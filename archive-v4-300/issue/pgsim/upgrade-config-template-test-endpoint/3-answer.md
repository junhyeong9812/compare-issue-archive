# issue/pgsim/upgrade-config-template-test-endpoint — 정답

태그: `deployment` · `environment-drift` · `silent-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **받지 못했다.**\
요청이 테스트 환경으로 가서 정상 응답이 왔지만 실제 출금은 일어나지 않았다.

2. **설치 스크립트가 기존 설정을 `.rpmsave`로 옮기고 기본 템플릿을 깔았다.**\
이번 업그레이드에서 벤더가 설정 파일 표시 방식을 바꾼 것이 원인이었고, 변경 공지 마지막 줄에만 적혀 있었다.

3. **개발 서버는 원래 테스트 엔드포인트를 쓰므로 덮어써도 동작이 같았다.**\
운영과 다른 값이 바뀌는지 볼 수 없는 검증이었다.

4. **다음 날 PG 정산 대사에서 환불 0건으로 나와 발견했다.**\
접수 응답만 보던 배치는 이상을 몰랐다.

5. **설정을 패키지 관리 경로 밖으로 분리, 배치 시작 시 운영 엔드포인트 확인, 업그레이드 후 설정 diff 확인.**\
테스트 환경으로 나간 환불은 다시 운영으로 보냈다.

## 문제 구조 (추상화 코드)

### 변형 A — 실행 환경을 확인하지 않는 배치
① 문제 코드
```python
cfg = load("/etc/pgsim/client.conf")
run_refund_batch(cfg, file)
```
② 고친 코드
```python
cfg = load(os.environ["PGSIM_CONF"])          # 패키지 밖 경로
if cfg.endpoint not in PROD_ENDPOINTS:
    raise WrongEnvironment(cfg.endpoint)       # 운영 배치는 운영만
run_refund_batch(cfg, file)
```
무엇이 깨졌나: 배치가 자신이 어느 환경에 붙었는지 확인하지 않아 정상 응답이 곧 성공으로 기록됐다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 설정을 패키지 밖으로 분리 | 실행 환경 변수 | 작음 | 경로 오타 | 기본 |
| 시작 시 엔드포인트 검사 | 운영 주소 목록 | 작음 | 주소 변경 시 목록 갱신 | 기본 |
| 업그레이드 후 설정 diff | 절차 | 작음 | 절차 생략 | 병행 |

**결론**: 정상 응답은 환경을 증명하지 않는다 — 운영 배치는 시작할 때 운영인지 확인한다.

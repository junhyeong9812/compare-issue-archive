# issue/pgsim/merchant-api-key-expiry-refund-delay — 정답

태그: `credential` · `latency` · `vendor-notice`

## 정답
<!-- 질문 1:1 대응 -->

1. **배치가 두 번 연속 실패해 민원이 들어온 9일 오후 수동 실행으로 나갔다.**\
고객 입장에서 약 이틀 늦었다.

2. **알림 메일이 정산팀 공용 메일로 가서 메일 필터에 걸려 '공지' 폴더로 이동했다.**\
키 만료일을 관리하는 대장도 없었다.

3. **승인 요청은 결제 서버의 별도 키를 쓰고, 그 키는 11월 발급이라 만료 전이었다.**

4. **맞지 않았다.**\
이월은 일시 장애에 맞는 처리다 — 인증 실패는 즉시 경보하고 사람이 키를 갱신해야 한다.

5. **건 수와 금액을 나눠 본다.**\
이 사건은 환불 요청 건 전부가 하루 단위로 통째 지연됐고 건별 금액은 정확했다. 일부 건·일부 금액만 빠지는 유형과 다르다.

## 문제 구조 (추상화 코드)

### 변형 A — 인증 실패를 다음 회차로 이월
① 문제 코드
```python
r = pgsim_refund_batch(file)
if not r.ok:
    schedule_next_run(file)      # 원인 구분 없음
```
② 고친 코드
```python
r = pgsim_refund_batch(file)
if not r.ok:
    if r.kind == "auth":
        page_oncall("pgsim refund key", r)   # 즉시 사람에게
    schedule_next_run(file)
```
무엇이 깨졌나: 이월은 시간이 해결하는 실패에만 맞다 — 자격증명 만료를 하루짜리 지연 둘로 바꿨다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 키 만료 대장 + 30일 전 티켓 자동 생성 | 키 목록 관리 | 작음 | 대장 누락 키 | 기본 |
| 인증 실패 즉시 호출 | 오류 종류 구분 | 작음 | 야간 호출 피로 | 기본 |
| 만료 없는 키 요청 | PG 정책 허용 | 협의 | 키 유출 시 피해 확대 | 선택하지 않은 방법 |

**결론**: 키는 만료일까지 자산으로 관리하고, 인증 실패는 이월하지 않는다.

# issue/pgsim/merchant-api-key-expiry-refund-delay — 정리 (힌트)

태그: `credential` · `latency` · `vendor-notice`

## 전체 흐름

```
2023-04-08  환불 전용 키 발급 (유효 1년)
2024-03-09  PG 만료 30일 전 알림 → 수신: 정산팀 공용 메일 (필터로 '공지' 폴더 이동)
2024-04-08  00:00 키 만료
            02:00 환불 배치 → 인증 오류 → 래퍼: "다음 회차로 이월"
            2024-04-09 02:00 동일 실패 → 이월
            2024-04-09 15:00 민원 접수 → 키 재발급 → 수동 실행
승인 요청: 결제 서버의 별도 키 (2023-11 발급) → 영향 없음
```

## 핵심 문장

- 원인은 **환불 전용 API 키의 연간 만료** — 만료 알림이 메일 필터로 공지 폴더에 묻혔다.
- 래퍼는 인증 실패를 "다음 회차 이월"로 처리했다 — 인증 실패는 다음 날에도 똑같이 실패한다.
- 승인용 키는 발급일이 달라 만료되지 않았다 — 용도별 키는 **만료일도 따로** 관리해야 한다.
- 금액 부족형 대사 차이와 달리 이 사건은 **환불 건 전체가 통째로 늦었고 금액은 정확**했다.

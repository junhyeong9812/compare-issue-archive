# issue/flagkit/key-case-default-fallback — 정답

태그: `contract-drift` · `silent-failure` · `environment-drift`

## 정답
<!-- 질문 1:1 대응 -->

1. **3.x는 `false`(기본값), 2.x는 `true`.**\
3.x SDK는 조회 전에 키를 소문자로 정규화해 `payment.newrouting`을 찾는다. 저장소의 키는 `Payment.NewRouting`이라 일치하는 항목이 없고, 호출자가 준 기본값을 돌려준다.\
2.x는 정규화 없이 그대로 찾아 `true`를 받는다. 3.x 릴리스 노트에는 "키 처리 개선"이라고만 적혀 있었다.
   > **기본값 폴백** — 플래그를 찾지 못했을 때 예외 대신 호출자가 준 기본값을 돌려주는 SDK 동작. 실패가 정상 값처럼 보인다.

2. **SDK 버전이다.** 증상이 난 두 서비스는 그 분기에 3.x로 올린 서비스였다.\
콘솔 반영 이력과 캐시 갱신은 모두 정상이었다 — 스냅샷에는 플래그가 들어 있었고, 조회 키만 달랐다.

3. **`flagkit: miss key=payment.newrouting` 한 줄이 DEBUG 레벨로 남는다.**\
운영 기본 로그 레벨이 INFO라 보이지 않았다. SDK 내부 메트릭 `flagkit_miss_total`은 있었지만 수집 대상에 없었다.

4. **반영 지연이 아니었기 때문이다.** TTL을 줄이면 스냅샷을 더 자주 받을 뿐, 소문자 키로 찾는 동작은 그대로다.\
몇 시간이 지나도 값이 안 바뀐다는 점이 지연 가설을 반증하는 단서였는데, TTL 조정 후 하루를 더 기다리며 놓쳤다.

5. **같은 의미의 플래그가 두 개가 된다.** 2.x 서비스는 대문자 키를, 3.x 서비스는 소문자 키를 읽는다.\
한쪽만 끄면 서비스별로 라우팅이 갈려, 결제 경로가 서비스마다 다른 상태가 된다 — 이번 사건에서 실제로 하루 동안 그렇게 됐다.\
임시 조치는 두 키를 함께 바꾸는 절차를 둘 때만 쓰고, 키 이전이 끝나면 대문자 키를 지운다.

6. **"기다리면 바뀌는가"와 "SDK가 그 키를 찾았는가"를 본다.**\
SDK의 `flags.debugLookup(key)`(또는 miss 메트릭)로 찾은 키 이름과 결과를 직접 확인한다. 찾았는데 옛 값이면 지연, 못 찾았으면 키 불일치다.

## 문제 구조 (추상화 코드)

### 변형 A — 대소문자 섞인 키로 조회
① 문제 코드
```java
// 콘솔 키: "Payment.NewRouting"
boolean on = flags.bool("Payment.NewRouting", false);   // 3.x: 소문자로 찾음 → 없음 → false
```
② 고친 코드
```java
// 콘솔 키를 "payment.new-routing" 으로 이전하고, 코드도 같은 소문자 키를 쓴다
boolean on = flags.bool("payment.new-routing", false);
flags.onMiss(key -> metrics.counter("flag_miss", "key", key).increment());
```
무엇이 깨졌나: 저장 측(대소문자 보존)과 조회 측(소문자 정규화)의 키 규칙이 SDK 버전업으로 갈라졌다.

### 변형 B — 지연으로 오진해 TTL만 조정
① 문제 코드
```yaml
flagkit:
  cacheTtlSeconds: 30     # 300 → 30, 효과 없음
```
② 고친 코드
```yaml
flagkit:
  cacheTtlSeconds: 300    # 원복
  logMissAt: WARN         # miss 를 운영 레벨로
```
무엇이 깨졌나: 시간이 지나도 안 바뀌는 증상을 지연으로 해석했다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 키를 소문자로 이전 + 콘솔 생성 검사 | 키 사용처 전수 파악 | 중간(이전 작업) | 이전 중 혼재 | 기본 |
| SDK를 2.x로 고정 | 보안 패치 포기 | 작음 | 장기 유지 불가 | 선택하지 않은 방법 |
| 소문자 복제 키 운영 | 두 키 동시 변경 | 작음 | 서비스별 값 분기 | 이전 기간 임시로만 |

**결론**: 키 규칙을 소문자로 정해 양쪽(콘솔·코드)이 같은 이름을 쓰게 하고, miss를 메트릭으로 감시한다.

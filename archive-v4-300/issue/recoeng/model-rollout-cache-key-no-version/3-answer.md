# issue/recoeng/model-rollout-cache-key-no-version — 정답

태그: `cache` · `deployment` · `data-integrity`

## 정답
<!-- 질문 1:1 대응 -->

1. **`reco:{고객ID}:{영역}` — 모델 버전이 없었다.**

2. **공유 영역(홈 상단)에서 B군 요청이 채운 결과를 같은 키의 A군 고객이 받았다.**\
공유 영역 키에 고객 대신 세그먼트를 쓰던 곳이 있었다.

3. **캐시 유지 시간 6시간이 지나며 옛 결과가 만료됐다.**

4. **키에 `{모델버전}:{테스트 군}` 포함, 배포 시 영역 캐시 무효화, 배포 후 6시간 지표 제외 후 재판독.**

## 문제 구조 (추상화 코드)

### 변형 A — 결과를 만든 조건이 없는 캐시 키
① 문제 코드
```java
String key = "reco:" + customerId + ":" + slot;
```
② 고친 코드
```java
String key = "reco:" + model.version() + ":" + arm + ":" + customerId + ":" + slot;
```
무엇이 깨졌나: 캐시 키가 결과를 결정하는 입력(모델·테스트 군)을 빠뜨려 서로 다른 결과가 같은 칸을 썼다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 키에 모델·테스트 군 포함 | 캐시 용량 증가 | 작음 | 키 폭증 | 기본 |
| 배포 시 무효화 | 무효화 도구 | 작음 | 콜드 캐시 부하 | 기본 |
| 캐시 끄기 | — | 작음 | 추천 지연 | 선택하지 않은 방법 |

**결론**: 캐시 키는 결과를 바꾸는 모든 입력을 담는다.

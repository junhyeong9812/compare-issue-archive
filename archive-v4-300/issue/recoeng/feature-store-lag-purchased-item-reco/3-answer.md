# issue/recoeng/feature-store-lag-purchased-item-reco — 정답

태그: `data-freshness` · `pipeline` · `silent-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **구매 이력 피처 적재가 11월 10일 값에서 멈췄다.**

2. **원천 테이블 파티션 경로가 바뀌어 적재가 입력을 찾지 못했다.**\
입력 없음을 오류로 보지 않고 0건 적재로 성공 종료했다.

3. **신규 고객은 구매 이력 피처를 쓰지 않는다.**

4. **작업은 매일 "성공"이었고 피처 나이를 보는 경보가 없었다.**

5. **적재 건수 하한, 피처 나이(최근 갱신 후 경과) 경보, 최근 24시간 주문은 추천 단계에서 실시간 제외.**

## 문제 구조 (추상화 코드)

### 변형 A — 0건 적재를 성공으로 처리
① 문제 코드
```python
rows = read_partition(path)
store.write(rows)                    # 0건이어도 성공
```
② 고친 코드
```python
rows = read_partition(path)
if len(rows) < 0.5 * yesterday_count():
    raise LoadTooSmall(path, len(rows))
store.write(rows)
```
무엇이 깨졌나: "읽을 것이 없음"을 정상으로 봐서 입력 경로 변경이 조용한 정지가 됐다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 적재 건수 하한 | 전일 기준 | 작음 | 연휴 등 정상 감소 | 기본 |
| 피처 나이 경보 | 갱신 시각 기록 | 작음 | 임계 설정 | 기본 |
| 최근 주문 실시간 제외 | 주문 조회 | 중간 | 지연 증가 | 병행 |

**결론**: 데이터 파이프라인에서 0건은 의심부터 한다.

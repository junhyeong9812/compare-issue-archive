# issue/notifyhub/http2-single-connection-stream-cap — 정리 (힌트)

태그: `performance` · `capacity`

## 전체 흐름

```
notifyhub 발송 풀 ──(HTTP/2 연결 1개, max_concurrent_streams=1000)──▶ 푸시 플랫폼
  응답 지연 평균 250ms → 이론 처리량 4,000건/s, 실측 3,400건/s
  대상 820만 단말 → 약 40분
CPU·메모리 여유 많음, 스레드는 스트림 대기
```

## 핵심 문장

- HTTP/2는 연결 하나에 **동시 스트림 수 상한**이 있다 — 플랫폼이 1000으로 알렸다.
- 연결 하나에 모든 요청을 실어, 처리량이 `스트림 상한 ÷ 응답 시간`에 묶였다.
- 대처: 연결 풀을 8개로 늘리고(플랫폼 권장 범위 안), 대량 발송은 별도 풀로 분리.
- 결과: 같은 공지가 6분에 끝났다.

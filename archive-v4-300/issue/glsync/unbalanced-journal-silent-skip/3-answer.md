## 정답
<!-- 질문 1:1 대응 -->

1. **아무것도 남지 않는다.** WARN 한 줄이 로그에 남고 요약은 정상이다.

2. **공급가·부가세 반올림이 총액과 어긋나는 금액이 그날 있었는지에 달렸다.** 1/11이 깔끔하게 안 떨어지는 금액에서만 생긴다.

3. **아니다.** 같은 분개는 또 불일치다. 분개 생성 규칙을 고친 뒤 재생성해야 한다.

4. **전표 번호 집합 비교가 먼저다.** 원장 전표 번호와 ERP 전표 번호의 차집합을 보고, 금액 비교는 그다음이다.

## 문제 구조 (추상화 코드)

① 문제 코드
```java
long supply = Math.round(total / 1.1); long vat = Math.round(total / 11.0);
```
② 고친 코드
```java
long supply = Math.round(total / 1.1);
long vat = total - supply;                 // 나머지 몰기 → 차대 항상 일치
// glsync: unbalanced → 실패 반환, 요약에 skipped 수 표시
```
무엇이 깨졌나: 분개를 두 번 따로 반올림해 차대가 깨졌고, 연동이 그 전표를 조용히 버렸다.

## 방안 비교

| 방안 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|
| 나머지 몰기 + 건너뛰기 실패 처리 | 작음 | 없음 | 기본 |
| ERP에서 1원 자동 조정 | 중간 | 원인 은폐 | 선택하지 않음 |

**결론**: 분개는 합이 맞게 만들고, 연동은 거부를 숨기지 않는다.

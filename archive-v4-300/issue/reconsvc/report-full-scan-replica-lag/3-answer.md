# issue/reconsvc/report-full-scan-replica-lag — 정답

태그: `performance` · `replication`

## 정답
<!-- 질문 1:1 대응 -->

1. **같은 복제본의 I/O를 다 써서 복제 적용이 늦어졌다.**

2. **`created_at >= ? AND created_at < ?` 범위 조건으로 바꿔 인덱스를 탔다.**

3. **월간 리포트는 수 분 지연이 허용된다.** 서비스 조회와 분리한 이유다.

## 문제 구조 (추상화 코드)

① 문제 코드
```sql
WHERE DATE(created_at) = '2024-02-01'
```
② 고친 코드
```sql
WHERE created_at >= '2024-02-01' AND created_at < '2024-02-02'
```
무엇이 깨졌나: 분석 부하와 서비스 조회가 자원을 공유했고 쿼리가 인덱스를 못 썼다.

## 방안 비교

| 방안 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|
| 쿼리 재작성 + 분석 복제본 | 중간 | 없음 | 기본 |
| 야간 실행 | 작음 | 운영 제약 | 보조 |

**결론**: 분석 쿼리는 분리된 자원에서 인덱스를 타게 돌린다.

# issue/artihub/remote-404-cached-new-release — 정답

태그: `stale-read` · `ci`

## 정답
<!-- 질문 1:1 대응 -->

1. **24시간 동안 404를 받는다.** 캐시된 '없음'이다.

2. **사내 빌드만 프록시를 거쳤다.**

3. **된다, 다만 30분이다.** 그래서 목록엔 보이는데 받기는 실패하는 구간이 있었다.

4. **해당 경로 캐시 삭제 후 재요청.** 런북에 넣었다.

## 문제 구조 (추상화 코드)

### 변형 A — 부정 캐시 기본값 유지
① 문제 코드
```yaml
remote: maven-central
missed_retrieval_ttl: 86400
```
② 고친 코드
```yaml
remote: maven-central
missed_retrieval_ttl: 1800
```
무엇이 깨졌나: 프록시가 '없음'도 기억한다는 점이 패치 절차에 없었다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| TTL 30분 | 설정 | 작음 | 원격 조회 증가 | 기본 |
| 경로 캐시 삭제 런북 | 관리자 권한 | 작음 | 사람 의존 | 긴급 |
| 프록시 우회 | 외부망 허용 | 작음 | 공급망 통제 상실 | 선택하지 않은 방법 |

**결론**: 부정 캐시 TTL을 줄이고 긴급 패치 런북에 캐시 삭제를 넣는다.

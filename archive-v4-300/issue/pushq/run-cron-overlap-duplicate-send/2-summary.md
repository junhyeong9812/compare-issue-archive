# issue/pushq/run-cron-overlap-duplicate-send — 정리 (힌트)

태그: `concurrency` · `scheduling` · `idempotency`

## 전체 흐름

```
* * * * *  pushq 발송 실행 (예약 시각이 지난 티켓 발송)
평시: 1회 실행 10초 이내
11/24 10:00  예약 약 92만 건 몰림 → 1회 실행 4분
             10:01, 10:02 … 실행이 앞 실행 종료 전 시작
             사내 래퍼: 발송 대상 목록 조회 → 발송 → 완료 표시 (표시 전에 다음 실행이 같은 목록 조회)
결과: 10:00 ~ 10:06 예약분 약 7% 중복 발송
```

## 핵심 문장

- 원인은 **크론 실행 겹침** — 평소 10초짜리 실행이 대량 예약으로 4분이 되며 다음 실행과 겹쳤다.
- 사내 래퍼가 "조회 → 발송 → 완료 표시" 순서라 표시 전에 다음 실행이 **같은 대상을 다시 조회**했다.
- 평시에는 실행 시간이 짧아 **겹침이 한 번도 없었다** — 부하가 숨은 전제를 드러냈다.
- 대처는 실행 단위 잠금(flock), 대상 조회 시 "처리 중" 선점, 실행 시간 지표 경보.

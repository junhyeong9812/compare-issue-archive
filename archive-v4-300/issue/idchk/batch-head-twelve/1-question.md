# issue/idchk/batch-head-twelve — 본인확인 CLI는 한 번에 12줄까지만 본다 — 질문

## 질문
1. (예측) 20줄짜리 요청 파일로 `idchk batch --in FILE`을 돌리면 `J0000001	20`과 exit 0이 나온다. 20건 모두 `idchk result <ref>`로 판정을 볼 수 있는가? `idchk job J0000001`은 무엇을 보여 주는가?
2. (경계) 12줄, 13줄, 30줄을 각각 한 번에 보내면 판정되는 줄은 몇 개이고 어느 줄인가? 버려지는 줄은 내용(이름·생년월일·번호)과 관계가 있는가?
3. (왜) 재확인 배치는 벤더가 돌려준 "읽은 줄 수"가 보낸 줄 수와 같은지 확인하고 있었고 종료 코드도 0이었다. 그런데 왜 일부 가맹점만 재확인 미완료로 남았고, 왜 다음 날 배치로도 풀리지 않았나?
4. (왜) 판정이 없는 요청에 `result`가 돌려주는 `E31`을 "아직 처리 중"으로 해석하면 무엇이 일어나는가? `E31`과 "처리 중"을 구분할 방법은 무엇인가?
5. (경계) 버려진 요청을 그대로 다시 보내면 어떻게 되는가? 이미 판정된 요청을 다시 보내는 것은 안전한가?
6. (연결) 배치 호출부가 "보냈다"와 "판정됐다"를 구분하려면 호출 단위와 확인 단위를 각각 어떻게 잡아야 하는가?

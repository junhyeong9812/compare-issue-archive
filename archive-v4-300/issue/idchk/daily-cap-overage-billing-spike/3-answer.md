# issue/idchk/daily-cap-overage-billing-spike — 정답

태그: `cost` · `resource-bounding` · `observability`

## 정답
<!-- 질문 1:1 대응 -->

1. **일 기본 건수를 넘는 호출에 2.5배 초과 단가가 붙었다.**\
14일간 매일 기본 건수를 넘었다.

2. **앱 가입 화면이 결과 화면에서 뒤로 가기 하면 확인을 처음부터 다시 요청했다.**\
이벤트 경품 안내 화면으로 오가는 사용자가 많아 중복이 늘었다.

3. **일 단위다.**\
월 합계로 상쇄되지 않는다 — 이벤트처럼 하루에 몰리는 패턴이 가장 비싸다.

4. **사용량이 벤더 포털에만 있었고 경보가 없었다.**\
사내 지표에는 가입 건수만 있고 외부 호출 수는 없었다.

5. **회원별 확인 결과를 15분간 재사용, 일 사용량 80% 경보, 이벤트 기획 체크리스트에 외부 API 비용 추정.**\
초과분은 벤더와 협의해 일부 감면받았다.

## 문제 구조 (추상화 코드)

### 변형 A — 화면 진입마다 외부 확인 호출
① 문제 코드
```javascript
onEnter(VerifyScreen, () => idchkApi.request(member));
```
② 고친 코드
```javascript
onEnter(VerifyScreen, async () => {
  const cached = await verifyCache.get(member.id);      // 15분 재사용
  if (cached) return show(cached);
  show(await idchkApi.request(member));
});
```
무엇이 깨졌나: 화면 흐름이 외부 유료 호출과 1:1로 묶여 사용자 행동이 곧 비용이 됐다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 결과 재사용(15분) | 확인 결과 저장 허용 | 작음 | 재사용 기간 중 정보 변경 | 기본 |
| 일 사용량 경보 | 벤더 사용량 API | 작음 | 경보 무시 | 기본 |
| 계약 기본 건수 상향 | 예산 | 고정비 증가 | 평시 낭비 | 이벤트 많을 때만 |

**결론**: 유료 외부 호출은 사용량을 사내 지표로 끌어오고, 같은 회원 재확인은 재사용한다.

# issue/metricdb/rollup-avg-on-counter-monthly-report — 정리 (힌트)

태그: `data-semantics` · `retention`

## 전체 흐름

```
원본(15s) 30일 → 삭제
롤업(5m, avg) → 카운터 리셋(재배포) 구간이 평균으로 뭉개짐 → 증가분 계산 오차
월 경계가 원본 보관 30일을 넘는 날 → 리포트가 롤업 사용
```

## 핵심 문장

- 카운터의 증가분은 **리셋을 감지**해야 맞다 — 평균 롤업은 리셋 지점을 지운다.
- 31일짜리 달의 1일은 원본 보관(30일) 밖이라 리포트가 롤업으로 넘어갔다.
- 카운터 롤업은 `last`(또는 증가분 합) 기준이어야 한다.
- 업무 수치는 **원장 DB 집계**가 정본이고 메트릭은 관측용이다.

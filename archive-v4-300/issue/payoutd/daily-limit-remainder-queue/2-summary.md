# issue/payoutd/daily-limit-remainder-queue — 정리 (힌트)

태그: `partial-processing` · `limit`

## 전체 흐름

```
모계좌 일일 이체 한도 300억 (은행 약정)
12-26 지급 총액 342억
payoutd run
   ├─ 한도까지 지급 (가맹점 순서대로)
   └─ 초과분 → 마지막 가맹점 금액을 분할, 잔액 PENDING_LIMIT (다음 영업일 첫 회차)
   요약 "executed 2,104 / ok"    ← 분할 건도 ok
```

## 핵심 문장

- `payoutd`는 한도 초과 시 오류를 내지 않고 **분할 + 잔액 대기**로 처리한다 — 요약상 성공이다.
- 평소 지급 총액은 한도의 60% 안팎이라 연말·명절 피크에만 드러난다.
- 가맹점 정렬 순서가 가맹점번호라 뒤쪽 대형 가맹점이 매번 분할 대상이 됐다.
- 교정: 피크일 전 한도 증액 신청, 분할 발생 시 경보·가맹점 안내.

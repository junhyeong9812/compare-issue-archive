## 정답
<!-- 질문 1:1 대응 -->

1. **같은 이체 고유번호로 요청해 은행이 두 번째를 거절했다.**

2. **아니다.** 롤링 배포 중 잠깐 두 파드가 겹친다. 실행 중복을 코드에서 막아야 한다.

3. **이중 지급이 실제로 난다.** 그래서 건 단위 선점을 넣었다.

## 문제 구조 (추상화 코드)

① 문제 코드
```sql
SELECT * FROM payout WHERE st = 'READY';
```
② 고친 코드
```sql
SELECT * FROM payout WHERE st = 'READY' ORDER BY id LIMIT 200 FOR UPDATE SKIP LOCKED;
-- 선점 후 st = 'SENDING' 으로 갱신하고 커밋, 그 다음 이체 요청
```
무엇이 깨졌나: 단일 실행 전제를 배포 설정에만 두었다.

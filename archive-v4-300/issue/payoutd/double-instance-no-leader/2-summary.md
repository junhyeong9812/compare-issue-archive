# issue/payoutd/double-instance-no-leader — 정리 (힌트)

태그: `concurrency` · `deploy`

## 전체 흐름

```
헬름 값 공통화 → payoutd replicas: 2  (원래 1 고정)
두 파드가 같은 지급 대상 조회 → 둘 다 이체 요청
      │  은행: 같은 이체 고유번호 → 두 번째는 중복 거절
      ▼
실제 이중 지급 0건 (은행 고유번호 덕분), 로그·경보 폭주
```

## 핵심 문장

- 이중 지급을 막은 것은 **은행 쪽 이체 고유번호 중복 검사**였다 — 우리 쪽 방어는 없었다.
- 데몬은 단일 실행을 전제로 했는데 그 전제가 배포 설정에만 있었다.
- 교정: DB 행 잠금(`FOR UPDATE SKIP LOCKED`)으로 건 단위 선점 + 리더 잠금.

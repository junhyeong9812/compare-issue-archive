# issue/wmsbridge/confirm-file-read-while-writing — 정리 (힌트)

태그: `race-condition` · `file-integration` · `partial-failure`

## 전체 흐름

```
WMS: 출고 확정 파일을 공유 폴더에 바로 씀 (최종 이름으로 생성 후 줄 단위 append)
폴러: 1분마다 새 파일 확인 → 처리 → "처리 완료" 목록에 파일명 기록
17:00 회차: 2,140줄 쓰기에 90초 (평소 300줄, 10초)
폴러가 쓰기 60초 시점에 파일 발견 → 그때까지의 1,388줄만 처리 → 파일명 완료 기록
남은 752줄: 이후 다시 읽히지 않음
```

## 핵심 문장

- 원인은 WMS가 **최종 이름으로 파일을 만들고 이어 쓰는** 방식이라 폴러가 **쓰는 도중의 파일**을 집은 것이다.
- 평소 회차는 쓰기가 10초로 짧아 겹칠 확률이 낮았다 — **연말·행사 대량 회차**에서 드러났다.
- 폴러는 파일명으로 완료를 기록해 **같은 파일을 다시 읽지 않았다**.
- 대처는 WMS가 임시 이름으로 쓴 뒤 이름 변경(또는 완료 표식 파일), 파일 끝 줄 수 트레일러 대조, 처리 후 줄 수 기록.

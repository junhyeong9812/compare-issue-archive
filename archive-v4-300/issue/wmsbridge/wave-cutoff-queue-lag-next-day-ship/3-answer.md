# issue/wmsbridge/wave-cutoff-queue-lag-next-day-ship — 정답

태그: `latency` · `cutoff` · `integration`

## 정답
<!-- 질문 1:1 대응 -->

1. **WMS 수신 시각이었다.**\
주문 시각은 마감 전이었지만 WMS에 도착한 시각이 14:00을 넘었다.

2. **상품 정보 일괄 동기화가 같은 큐를 쓰면서 주문 메시지가 뒤로 밀렸다.**

3. **평소 큐 지연은 수 초라 수신 시각과 주문 시각이 거의 같았다.**

4. **화면은 주문 시각으로 마감을 판정했다.**

5. **주문 시각과 WMS 수신 시각의 차이를 본다.**\
차이가 크면 연동 지연, 차이가 없는데 빠지면 WMS 쪽 배정 규칙·재고 문제다.

## 문제 구조 (추상화 코드)

### 변형 A — 마감 판정을 수신 시각으로
① 문제 코드
```java
boolean sameDay = wmsReceivedAt.isBefore(cutoff);
```
② 고친 코드
```java
boolean sameDay = order.placedAt().isBefore(cutoff);    // 주문 시각을 WMS 로 함께 전달
```
무엇이 깨졌나: 고객에게 약속한 기준(주문 시각)과 창고가 쓰는 기준(수신 시각)이 달랐다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 주문 시각 기준 판정 | WMS 필드 추가 | 중간 | 마감 직후 작업량 증가 | 기본 |
| 주문 전용 큐 | 큐 추가 | 작음 | 큐 관리 | 기본 |
| 마감 전 큐 지연 경보 | 지표 | 작음 | 경보 후 대응 시간 부족 | 병행 |

**결론**: 마감 약속은 고객이 본 시각으로 판정하고, 연동 지연은 그 앞에서 감시한다.

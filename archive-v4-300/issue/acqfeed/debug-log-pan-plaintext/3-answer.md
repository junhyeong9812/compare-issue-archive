# issue/acqfeed/debug-log-pan-plaintext — 정답

태그: `security` · `deploy`

## 정답
<!-- 질문 1:1 대응 -->

1. **DEBUG 문장이 마스킹 전 객체를 찍었기 때문이다.** 마스킹은 정산 DB 적재 직전에만 적용됐다.

2. **충분하지 않다.** 다음 배포 실수 때 다시 나온다. 원문 레코드를 찍는 문장을 지우고, 로그 출력 계층에 카드번호 패턴 마스킹 필터를 추가했다.

3. **해당 기간 인덱스를 파기하고 파기 증적을 점검 대응 문서에 첨부했다.** 백업 스냅숏에도 같은 기간이 있어 함께 파기했다.

4. **배포 산출물 검사에 로그 레벨 확인을 넣었다.** 운영 프로파일에서 루트 레벨이 INFO 미만이면 빌드 실패.

## 문제 구조 (추상화 코드)

① 문제 코드
```java
log.debug("raw record: {}", line);           // 카드번호 포함 원문
```
② 고친 코드
```java
log.debug("record parsed: seq={} card={}", rec.seq(), Pan.mask(rec.pan()));
// + 로그 appender 에 PanMaskingFilter (13~19자리 Luhn 통과 숫자 마스킹)
```
무엇이 깨졌나: 민감 데이터 보호를 로그 레벨 설정에 의존했다.

## 방안 비교

| 방안 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|
| 원문 로그 제거 + 출력 필터 | 작음 | 필터 정규식 미탐 | 기본 |
| 운영 로그 레벨 강제만 | 작음 | 다음 배포 실수 | 보조 |

**결론**: 원문 자체를 찍지 않고, 출력 계층 필터와 빌드 검사를 겹쳐 둔다.

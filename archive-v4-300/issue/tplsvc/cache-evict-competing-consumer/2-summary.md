# issue/tplsvc/cache-evict-competing-consumer — 정리 (힌트)

태그: `caching` · `consistency`

## 전체 흐름

```
관리 콘솔 저장 → DB 갱신 → queue "tpl.evict" 발행
tplsvc 파드 6개가 같은 소비자 그룹 → 메시지 1건을 1개 파드만 소비
나머지 5개 파드: 로컬 캐시 TTL 24h 동안 옛 템플릿
발송 요청은 파드에 고르게 분산 → 약 5/6 이 옛 문구
```

## 핵심 문장

- **작업 큐(경쟁 소비)** 는 메시지 하나를 소비자 하나에게만 준다 — 모든 파드에 알려야 하는 무효화에는 맞지 않는다.
- 파드가 1개이던 시절 설계가 수평 확장 후에도 그대로였다.
- 대처: 무효화는 파드마다 고유 구독(브로드캐스트)으로, 캐시 TTL은 5분으로 줄이고 템플릿에 버전 번호를 붙여 발송 기록에 남김.

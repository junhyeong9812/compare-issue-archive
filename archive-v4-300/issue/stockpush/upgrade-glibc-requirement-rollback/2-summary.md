# issue/stockpush/upgrade-glibc-requirement-rollback — 정리 (힌트)

태그: `deployment` · `environment-drift` · `rollback`

## 전체 흐름

```
2/10 14:00  운영 배치 서버(구형 OS) 업그레이드
            새 바이너리: 더 높은 glibc 버전 요구 → 로더 오류 "version not found" → 실행 불가
스테이징: 지난해 OS 업그레이드 완료 → 정상
롤백: 이전 패키지 파일이 저장소 정리 정책으로 삭제됨 → 벤더에 요청 → 3시간
```

## 핵심 문장

- 원인은 **새 바이너리의 런타임 라이브러리 요구 버전** — 운영 서버 OS가 스테이징보다 오래됐다.
- 스테이징과 운영의 **OS 버전이 달라** 사전 검증이 운영을 대표하지 못했다.
- 롤백이 늦은 이유는 **이전 패키지가 사내 저장소에서 지워져** 있었기 때문이다.
- 대처는 스테이징·운영 OS 일치, 이전 두 판 패키지 보관, 업그레이드는 업무 시간 외 재고 동기화 공백이 짧은 시간대에.

# issue/callrec/stt-single-channel — 정답

태그: `environment-drift` · `silent-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **거의 나오지 않는다.** 상담원 채널이 인식되지 않았다.

2. **됐다.** 2센터는 고객이 왼쪽이라 오히려 고객 발화만 색인됐다.

3. **모노는 두 화자가 섞여 인식돼 검색은 된다.** 화자 구분만 안 된다.

4. **2센터 상담원 고지 누락으로 보고 교육 공문을 냈다.** 실제 녹취를 들어 보니 고지를 하고 있었다.

5. **녹취 메타에 장비 ID를 두고 장비별 채널 매핑으로 화자를 붙인다. STT는 두 채널 모두 인식.** 3월분 2센터 녹취 약 6만 건을 재색인했다.

## 문제 구조 (추상화 코드)

### 변형 A — 고정 채널 인식
① 문제 코드
```python
text = stt.recognize(audio, channel=0)
index(call_id, speaker="agent", text=text)
```
② 고친 코드
```python
m = CHANNEL_MAP[call.device_id]          # {"agent": 1, "customer": 0}
for who, ch in m.items():
    index(call_id, speaker=who, text=stt.recognize(audio, channel=ch))
```
무엇이 깨졌나: 녹음 장비의 채널 배치를 상수로 가정해, 장비가 바뀌자 화자가 뒤집혔다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 장비별 매핑 + 두 채널 인식 | 장비 메타 | 중간 | 매핑 누락 | 기본 |
| 2센터 장비 채널 반전 설정 | 장비 설정 | 작음 | 다음 장비 | 임시 |
| 센터별 검색 건수 비교 경보 | 지표 | 작음 | 사후 | 안전망 |

**결론**: 장비 차이는 메타로 들고 다닌다. 센터 간 지표 급차이는 데이터부터 의심한다.

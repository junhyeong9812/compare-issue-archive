# issue/callrec/long-call-part-unlinked — 정답

태그: `data-integrity` · `silent-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **60분까지만.** 메타가 첫 파일만 가리킨다.

2. **있었다.** 업로드는 됐지만 어떤 통화에도 연결되지 않은 파일로 남았다. 2년간 약 1,700개.

3. **`-p3` 이후도 마찬가지로 빠진다.**

4. **1시간 넘는 통화가 전체의 0.4%로 드물었다.** 4월 민원(장시간 상담 중 안내 내용 다툼) 조사에서 후반부가 없었다.

5. **수집이 `<통화ID>*.wav`를 순서대로 모아 메타의 파일 목록에 넣는다.** 녹취 길이 합이 통화 길이보다 1분 이상 짧으면 경보. 고아 파일은 이름으로 재연결했다.

## 문제 구조 (추상화 코드)

### 변형 A — 첫 파일만 연결
① 문제 코드
```python
meta = {"call_id": cid, "file": f"{cid}.wav"}
```
② 고친 코드
```python
parts = sorted(store.list(prefix=cid), key=part_no)   # cid.wav, cid-p2.wav ...
meta = {"call_id": cid, "files": parts}
if sum(dur(p) for p in parts) < call.duration - 60:
    alert("recording shorter than call", cid)
```
무엇이 깨졌나: 장비의 분할 규칙을 연동이 몰라 한 통화 = 한 파일로 가정했다.

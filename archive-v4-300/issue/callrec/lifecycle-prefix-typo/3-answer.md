# issue/callrec/lifecycle-prefix-typo — 정답

태그: `irreversible` · `data-retention`

## 정답
<!-- 질문 1:1 대응 -->

1. **90일 뒤 삭제된다.** 장기 보관 규칙이 매칭되지 않아 기본 규칙이 적용된다.

2. **일반 녹취는 원래 90일 보관이라 기본 규칙과 같았다.**

3. **삭제 표식만 남고 이전 버전을 되살릴 수 있었다.** 이 버킷은 비용 때문에 꺼져 있었다.

4. **90일 지연이 있었고, 삭제 대상이 민원 건에 한정돼 조회가 드물었다.** 12월 민원 조사에서 발견, 이미 약 2,100건이 지워졌다.

5. **규칙 변경 전 규칙별 매칭 객체 수를 확인(0이면 실패)하고, `recordings/legal/`에 3년 보존 모드 객체 잠금을 건다.** 보존 모드는 수명 주기 규칙보다 우선한다.

## 문제 구조 (추상화 코드)

### 변형 A — 접두어 오타 규칙
① 문제 코드
```json
{ "Rules": [
  { "ID": "legal-3y", "Filter": { "Prefix": "recording/legal/" }, "Expiration": { "Days": 1095 } },
  { "ID": "default",  "Filter": {}, "Expiration": { "Days": 90 } } ] }
```
② 고친 코드
```json
{ "Rules": [
  { "ID": "legal-3y", "Filter": { "Prefix": "recordings/legal/" }, "Expiration": { "Days": 1095 } },
  { "ID": "default",  "Filter": { "Prefix": "recordings/general/" }, "Expiration": { "Days": 90 } } ] }
// + recordings/legal/ 객체 잠금 보존 모드 1095일
```
무엇이 깨졌나: 보관 규칙이 '매칭되면 보호'로 짜여 있어, 매칭 실패가 곧 삭제로 이어졌다(기본값이 삭제).

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 객체 잠금 보존 모드 | 버킷 기능 | 중간 | 잘못 잠그면 못 지움 | 법정 보관 |
| 기본 규칙을 접두어 한정 | 경로 정리 | 작음 | 새 경로 무규칙 | 함께 |
| 규칙별 매칭 수 확인 | dry-run 도구 | 작음 | 사람 의존 | 변경 절차 |

**결론**: 삭제가 기본값인 구조를 피하고, 법정 보관은 규칙이 아닌 잠금으로 지킨다.

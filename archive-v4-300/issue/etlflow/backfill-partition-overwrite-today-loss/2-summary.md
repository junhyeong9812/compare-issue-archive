# issue/etlflow/backfill-partition-overwrite-today-loss — 정리 (힌트)

태그: `data-loss` · `backfill` · `concurrency`

## 전체 흐름

```
일 파티션 dt=2025-12-02: 증분 적재(시간 단위)가 계속 append
12/03 09:00 백필 시작 (11/01 ~ 12/02, 원천 스냅샷 = 12/02 12:00 기준 추출본)
       모드: 파티션 덮어쓰기 → dt=12-02 를 12:00 까지 데이터로 교체
→ 12/02 12:00 ~ 24:00 증분 적재분 소실 → 하루 매출 절반
12/01 이전 파티션: 스냅샷이 완전 → 정상
```

## 핵심 문장

- 원인은 백필이 **불완전한 스냅샷(12/02 정오 기준)으로 12/02 파티션을 통째 덮어쓴** 것이다.
- 덮어쓰기 모드는 이전 파티션에는 안전했지만 **증분이 계속 쌓이던 최근 파티션**에서는 데이터를 지웠다.
- 대시보드는 다음 날 오전 정기 보고에서야 봤다 — **적재 후 행 수 비교**가 없었다.
- 대처는 백필 범위를 완결 파티션(어제 이전)으로 제한, 덮어쓰기 전후 행 수 비교·감소 시 중단, 파티션 스냅샷 보관.

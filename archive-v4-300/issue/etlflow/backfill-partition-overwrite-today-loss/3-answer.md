# issue/etlflow/backfill-partition-overwrite-today-loss — 정답

태그: `data-loss` · `backfill` · `concurrency`

## 정답
<!-- 질문 1:1 대응 -->

1. **12월 2일 정오 이후의 증분 적재분이 지워졌다.**

2. **백필 원천이 12월 2일 정오 기준 추출본이라 그 시각까지 데이터로 파티션을 교체했다.**

3. **12월 1일 이전 파티션은 추출본이 완전했다.**

4. **적재 전후 행 수를 비교하는 단계가 없었다.**\
오전 매출 보고에서 영업팀이 발견했다.

5. **백필 대상은 완결 파티션만, 덮어쓰기 전후 행 수 감소 시 중단·복원, 파티션 단위 스냅샷 7일 보관.**\
소실분은 원천에서 재적재했다.

## 문제 구조 (추상화 코드)

### 변형 A — 진행 중인 파티션 덮어쓰기
① 문제 코드
```python
for dt in date_range("2025-11-01", "2025-12-02"):
    overwrite_partition(dt, extract(dt))
```
② 고친 코드
```python
for dt in date_range("2025-11-01", last_closed_partition()):
    new = extract(dt)
    if len(new) < 0.99 * count_partition(dt):
        raise BackfillShrinks(dt)
    overwrite_partition(dt, new)
```
무엇이 깨졌나: 덮어쓰기의 안전 조건(원천이 완전함)을 확인하지 않고 진행 중인 파티션에 적용했다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 완결 파티션만 백필 | 완결 기준 정의 | 작음 | 기준 오류 | 기본 |
| 전후 행 수 비교 | — | 작음 | 정상 감소(정정) 구분 | 기본 |
| 병합(upsert) 모드 | 키 정의 | 중간 | 삭제 반영 못함 | 대안 |

**결론**: 덮어쓰기는 원천이 완전한 파티션에만 쓴다.

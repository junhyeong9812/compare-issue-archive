# issue/etlflow/peak-volume-join-oom-empty-dashboard — 정리 (힌트)

태그: `capacity` · `resource-bounding` · `observability`

## 전체 흐름

```
야간 집계: 주문 × 주문 상품 × 상품 마스터 조인 (작업자 메모리 8GB)
평소: 주문 상품 1,200만 줄 → 정상
11/24: 6,100만 줄 + 특정 인기 상품 키 쏠림 → 한 작업자에 몰림 → 메모리 부족
재시도 3회: 같은 설정·같은 데이터 → 같은 실패
경보: 잡 실패 메일 (주말 미확인)
```

## 핵심 문장

- 원인은 데이터량 5배와 **인기 상품 키 쏠림**으로 조인이 한 작업자에 몰려 메모리 부족이 난 것이다.
- 재시도는 **같은 조건의 반복**이라 의미가 없었다.
- 실패 경보가 **주말 미확인 메일**이라 아침까지 아무도 몰랐다.
- 대처는 쏠림 키 분산(salting)·브로드캐스트 조인, 행사 전 용량 리허설, 실패 경보를 당직 호출로.

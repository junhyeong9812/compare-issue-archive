# issue/etlflow/peak-volume-join-oom-empty-dashboard — 정답

태그: `capacity` · `resource-bounding` · `observability`

## 정답
<!-- 질문 1:1 대응 -->

1. **조인 단계 작업자의 메모리 부족 종료가 반복됐다.**

2. **데이터량이 5배였고 인기 상품 몇 개에 주문이 몰려 조인 키가 쏠렸다.**

3. **재시도가 같은 데이터·같은 설정으로 돌아 같은 지점에서 죽었다.**

4. **상품 마스터 브로드캐스트 조인, 쏠림 키 분산, 행사 전 전년 피크 데이터로 리허설, 실패는 당직 호출.**\
당일은 메모리를 늘려 수동 재실행했다.

## 문제 구조 (추상화 코드)

### 변형 A — 평시 데이터에 맞춘 조인 설정
① 문제 코드
```python
orders.join(order_items, "order_id").join(products, "product_id")
```
② 고친 코드
```python
orders.join(order_items, "order_id").join(broadcast(products), "product_id")   # 작은 마스터는 브로드캐스트
```
무엇이 깨졌나: 평시 데이터 분포를 전제로 한 설정이 행사 날 분포 변화(양·쏠림)를 견디지 못했다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 브로드캐스트 조인 | 마스터가 작음 | 작음 | 마스터 증가 | 기본 |
| 행사 전 리허설 | 전년 데이터 | 중간 | 분포 차이 | 기본 |
| 메모리 증설 | 비용 | 작음 | 쏠림 심해지면 재발 | 임시 |

**결론**: 행사 날 데이터 분포로 미리 돌려 본다.

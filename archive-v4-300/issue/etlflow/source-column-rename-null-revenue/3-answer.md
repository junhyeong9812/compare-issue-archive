# issue/etlflow/source-column-rename-null-revenue — 정답

태그: `schema-drift` · `silent-failure` · `data-quality`

## 정답
<!-- 질문 1:1 대응 -->

1. **오류는 없고 "원천에 없는 컬럼" 경고 로그만 있었다.**

2. **바뀐 컬럼이 앱 주문 매출 계산식에만 쓰였다.**\
NULL이 계산식을 타고 매출 NULL이 됐고 집계에서 0이 됐다.

3. **건수는 정상이었다.**\
품질 검사가 건수만 봤다.

4. **매핑 엄격 모드(없는 컬럼이면 실패), 금액 컬럼 NULL 비율 0.1% 초과 시 실패, 원천 DB 변경 리뷰에 데이터팀 포함.**\
8/5 ~ 8/6 적재분은 재처리했다.

## 문제 구조 (추상화 코드)

### 변형 A — 없는 원천 컬럼을 NULL로 대체
① 문제 코드
```yaml
mapping:
  on_missing_column: fill_null
```
② 고친 코드
```yaml
mapping:
  on_missing_column: fail
quality:
  - column: revenue
    max_null_ratio: 0.001
```
무엇이 깨졌나: 스키마 불일치를 데이터 값(NULL)으로 바꿔 파이프라인 오류가 집계 오류로 번졌다.

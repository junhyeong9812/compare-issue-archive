# issue/prodsrch/bulk-index-refresh-interval-cpu — 정답

태그: `capacity` · `latency` · `operations`

## 정답
<!-- 질문 1:1 대응 -->

1. **CPU — 세그먼트 생성·병합이 95%를 차지했다.**

2. **새 색인 샤드가 운영 색인과 같은 노드에 있었다.**

3. **새벽엔 검색 트래픽이 적어 같은 부하에도 응답 지연이 체감되지 않았다.**

4. **적재 중 새로 고침 비활성·복제본 0, 완료 후 복원·강제 병합, 적재 속도 상한, 야간 작업.**

## 문제 구조 (추상화 코드)

### 변형 A — 대량 적재에 실시간 색인 설정 사용
① 문제 코드
```json
{ "index": { "refresh_interval": "1s", "number_of_replicas": 1 } }
```
② 고친 코드
```json
{ "index": { "refresh_interval": "-1", "number_of_replicas": 0 } }
```
무엇이 깨졌나: 실시간 검색용 설정을 대량 적재에 그대로 써서 자원을 운영 검색과 다퉜다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 적재 중 새로 고침 끔 | 적재 후 복원 | 작음 | 복원 누락 | 기본 |
| 적재 속도 상한 | 적재기 설정 | 작음 | 작업 시간 증가 | 기본 |
| 색인 전용 노드 | 노드 추가 | 큼 | 비용 | 장기 |

**결론**: 대량 적재는 적재용 설정으로, 끝나면 반드시 되돌린다.

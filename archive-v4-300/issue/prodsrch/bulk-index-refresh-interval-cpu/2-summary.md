# issue/prodsrch/bulk-index-refresh-interval-cpu — 정리 (힌트)

태그: `capacity` · `latency` · `operations`

## 전체 흐름

```
새 색인 대량 적재 (초당 2만 문서), 새로 고침 간격 1초(기본) · 복제본 1
→ 1초마다 세그먼트 생성·병합 → CPU 95%
운영 색인과 같은 노드 → 검색 처리 스레드 대기 → p95 3초
새벽: 검색 트래픽 낮아 체감 없음
```

## 핵심 문장

- 원인은 대량 적재 중 **새로 고침 간격 1초·복제본 1** 기본값을 그대로 둔 것 — 세그먼트 생성·병합이 CPU를 다 썼다.
- 새 색인과 운영 색인이 **같은 노드**에 있어 운영 검색이 영향을 받았다.
- 예전에는 **새벽**에 돌려 검색 트래픽이 적었다 — 이번에 일정이 낮으로 옮겨졌다.
- 대처는 적재 동안 새로 고침 끔·복제본 0, 끝난 뒤 되돌림, 적재 속도 제한, 작업은 야간.

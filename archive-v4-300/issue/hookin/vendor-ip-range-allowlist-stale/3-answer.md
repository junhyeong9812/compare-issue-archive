# issue/hookin/vendor-ip-range-allowlist-stale — 정답

태그: `infra` · `allowlist`

## 정답
<!-- 질문 1:1 대응 -->

1. **경계 방화벽에서 403으로 막힌다.** 애플리케이션 로그에는 아무 흔적이 없었다.

2. **애플리케이션 지표만 보고 있었다.** 방화벽 403은 별도 시스템 로그였다.

3. **서명 검증이 있으므로 IP 제한은 이중 방어다.** 정책상 유지하되 목록 동기화를 자동화했다.

## 문제 구조 (추상화 코드)

### 변형 A — 수동 관리 허용 목록
① 문제 코드
```yaml
allowlist:
  pg-a: [198.51.100.0/24]        # 수기 관리
```
② 고친 코드
```yaml
allowlist:
  pg-a:
    source: https://pg-a.example/ip-ranges.json   # 하루 1회 동기화, 변경 시 티켓
    pinned: [198.51.100.0/24]
alerts: { edge_403_ratio: "> 2% / 10m" }
```
무엇이 깨졌나: 상대 변경을 사람의 메일 수신에 의존해 반영했다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| IP 목록 API 동기화 | 상대가 목록 제공 | 작음 | 목록 위조(전송 보안 필요) | 기본 |
| 공용 공지 수신함 | 운영 | 작음 | 담당 누락 | 함께 적용 |

**결론**: 외부 의존 설정은 상대의 기계 판독 원천에서 동기화하고, 경계 거절 비율을 경보로 본다.

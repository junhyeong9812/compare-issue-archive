# issue/hookin/arrival-order-status-overwrite — 정리 (힌트)

태그: `ordering` · `data-semantics`

## 전체 흐름

```
PG: 승인 통지(10:00:01) 발송 → 우리 쪽 일시 503 → PG 재전송 10:05:01
    취소 통지(10:02:30) 발송 → 정상 수신 → 상태 CANCELED
    10:05:01 재전송된 승인 통지 수신 → 상태 APPROVED 로 덮어씀
```

## 핵심 문장

- PG 통지는 **재전송 때문에 발생 순서와 도착 순서가 다를 수 있다**.
- `hookin`은 "마지막에 도착한 통지가 최신"이라고 가정하고 상태를 그대로 덮었다.
- 통지 본문에는 PG 쪽 발생 시각과 거래 상태 순번(`seq`)이 있었지만 쓰지 않았다.
- 대처: 상태 전이 규칙(취소 후 승인은 불가) + `seq` 비교로 낮은 순번은 무시하고 기록만.

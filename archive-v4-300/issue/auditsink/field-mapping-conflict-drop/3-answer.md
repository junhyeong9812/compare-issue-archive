# issue/auditsink/field-mapping-conflict-drop — 정답

태그: `silent-failure` · `schema`

## 정답
<!-- 질문 1:1 대응 -->

1. **거부된다.** 그날 인덱스의 `actor_id`는 첫 문서 때문에 long으로 고정돼 `ADM-07`을 넣을 수 없다.

2. **그날 첫 이벤트의 주인이다.** 외주 운영자가 새벽 점검으로 먼저 작업한 날(주로 월요일)은 keyword로 잡혀 문제가 없었다.

3. **수집기 dead-letter 큐로 가고 7일 뒤 지워진다.** 발견 시점(10월 21일)에 남아 있던 7일치는 재처리했고, 그 이전 9일치 약 3,100건은 복구하지 못했다.

4. **정규직 사번은 숫자라 어느 쪽 타입에도 들어간다.** keyword 인덱스에는 문자열로 저장되고, long 인덱스에도 그대로 들어간다. 문자열 ID만 거부됐다.

5. **템플릿에 `actor_id: keyword`를 명시하고, 동적 매핑을 `strict`로 바꿔 모르는 필드는 거부 + 경보한다.** 템플릿 변경은 다음 날 인덱스부터 적용되므로 당일 인덱스는 재생성했다.

## 문제 구조 (추상화 코드)

### 변형 A — 식별자 동적 매핑
① 문제 코드
```json
{ "index_patterns": ["audit-*"],
  "mappings": { "dynamic": true,
    "properties": { "ts": { "type": "date" } } } }
```
② 고친 코드
```json
{ "index_patterns": ["audit-*"],
  "mappings": { "dynamic": "strict",
    "properties": { "ts": { "type": "date" },
                    "actor_id": { "type": "keyword" },
                    "action":   { "type": "keyword" } } } }
```
무엇이 깨졌나: 스키마를 데이터 도착 순서에 맡겨, 같은 필드의 타입이 날마다 달라졌다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |

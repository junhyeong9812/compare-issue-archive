# issue/splitab/late-event-early-readout-underestimate — 정리 (힌트)

태그: `data-freshness` · `statistics` · `experimentation`

## 전체 흐름

```
앱 SDK: 이벤트를 모아 최대 6시간마다 업로드 (배터리 절약 모드)
B안: 새 결제 화면 → 앱 사용자 비중 높음 (앱에서만 노출되는 진입점 포함)
종료 직후 판독: 앱 이벤트 일부 미도착 → B 전환 과소
다음 날: 지연 이벤트 도착 → B 우세
웹: 실시간 전송 → 두 시점 결과 같음
```

## 핵심 문장

- 원인은 **앱 이벤트 업로드 지연(최대 6시간)** 을 기다리지 않고 판독한 것이다.
- B안이 **앱 비중이 높아** 지연 영향이 B쪽에 더 컸다 — 군 사이 지연이 비대칭이었다.
- 웹만 보면 두 시점 결과가 같았다 — **채널별 도착 지연**이 단서다.
- 대처는 판독 시점을 종료 + 지연 상한(24시간) 이후로 고정, 판독 화면에 이벤트 도착 완료율 표시.

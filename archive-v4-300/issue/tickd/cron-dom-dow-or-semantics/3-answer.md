# issue/tickd/cron-dom-dow-or-semantics — 정답

태그: `config` · `semantics`

## 정답
<!-- 질문 1:1 대응 -->

1. **돈다.** 일 필드 1-7이 맞기 때문이다.

2. **식을 "AND"로 읽었다.** 다음 실행 시각 미리보기(`tickd next --n 10`)를 확인하지 않았다.

3. **아니다.** Quartz 형식은 일·요일 중 하나를 `?`로 비워야 하고, `MON#1`을 지원한다 — 스케줄러마다 해석이 다르니 미리보기로 확인한다.

## 문제 구조 (추상화 코드)

### 변형 A — 일·요일 동시 지정
① 문제 코드
```yaml
schedule: "0 0 9 1-7 * MON"
```
② 고친 코드
```yaml
schedule: "0 0 9 * * MON"
guard: "dayOfMonth <= 7"        # 작업 첫 줄에서 확인 후 아니면 종료
# 등록 시: tickd next --n 10 결과를 리뷰에 첨부
```
무엇이 깨졌나: cron 의미를 직관으로 읽었고, 다음 실행 시각을 확인하지 않았다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 요일 식 + 코드 가드 | 없음 | 작음 | 없음 | 기본 |
| 확장 문법(MON#1) | 스케줄러 지원 | 작음 | 다른 스케줄러 이식 시 깨짐 | 지원 시 |

**결론**: cron 식은 다음 실행 시각 10개를 리뷰에 첨부해 확인한다.

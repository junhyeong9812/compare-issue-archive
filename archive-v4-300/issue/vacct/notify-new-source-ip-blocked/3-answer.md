# issue/vacct/notify-new-source-ip-blocked — 정답

태그: `environment-drift` · `network`

## 정답
<!-- 질문 1:1 대응 -->

1. **신규 IP에서 나간 통지만 막혔고, 재시도 중 기존 IP로 나간 것은 통과했다.**

2. **입금 조회 폴링으로 보완할 수는 있지만 근본은 아니다.** 허용 목록 갱신이 정답이다.

3. **벤더 통지 이력(시도 시각·결과 코드)과 사내 수신 로그를 맞대 봤다.** 벤더 쪽 1차 시도가 connection refused였다.

## 문제 구조 (추상화 코드)

① 문제 코드
```sh
allow vacct-notify 203.0.113.10/32 203.0.113.11/32
```
② 고친 코드
```sh
allow vacct-notify 203.0.113.10/32 203.0.113.11/32 198.51.100.24/32
# 지표: vacct_notify_lag_seconds = 수신 시각 - 입금 시각 (p95 > 120s 경보)
```
무엇이 깨졌나: 상대 인프라 변경이 일부 요청에만 영향을 줘 전체 실패 경보에 걸리지 않았다.

## 방안 비교

| 방안 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|
| 허용 목록 갱신 + 지연 지표 | 작음 | 공지 누락 | 기본 |
| 폴링 보완 | 중간 | 벤더 rate limit | 보조 |

**결론**: 외부 발신 IP는 공지 절차로 관리하고, 성공률이 아니라 지연을 본다.

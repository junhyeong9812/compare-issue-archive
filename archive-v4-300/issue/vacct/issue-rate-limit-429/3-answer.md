# issue/vacct/issue-rate-limit-429 — 정답

태그: `performance` · `rate-limit`

## 정답
<!-- 질문 1:1 대응 -->

1. **사내 요청이 계약 한도를 넘었다.**

2. **한도를 더 오래 넘겨 회복이 늦어진다.** 재시도는 최대 3회, Retry-After 준수.

3. **예상 피크 초당 요청 수 산정, 벤더 한도 상향 요청, 클라이언트 쪽 속도 제한 설정.**

## 문제 구조 (추상화 코드)

① 문제 코드
```java
return vacct.issue(order);              // 429 → 예외 → 결제 실패
```
② 고친 코드
```java
limiter.acquire();                      // 초당 45
return retry(() -> vacct.issue(order), on429(RetryAfter::header), 3);
```
무엇이 깨졌나: 외부 한도를 요청 경로가 몰랐다.

## 방안 비교

| 방안 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|
| 클라이언트 속도 제한 + 429 재시도 | 작음 | 대기 증가 | 기본 |
| 벤더 한도 상향 | 협의 | 비용 | 병행 |

**결론**: 외부 한도는 요청 쪽에서 지킨다.

# issue/maskd/regex-backtrack-latency — 정답

태그: `performance` · `regex`

## 정답
<!-- 질문 1:1 대응 -->

1. **백트래킹으로 분할 조합을 끝까지 시도한다.** 400자에서 3~4초가 걸렸다.

2. **메모가 길고 '로/길'이 없는 거래만 그랬다.** 전체의 0.3%.

3. **선형 시간이라 수 ms 안에 끝난다.** 다만 역참조 등 일부 문법을 못 쓴다 — 주소 규칙에는 필요 없었다.

4. **워커 32개 중 몇 개만 묶였기 때문이다.** 평균 CPU는 20%대였고, 지연 분포의 꼬리에서만 보였다.

5. **규칙**: `[^\s]+(로|길)\s?\d+`처럼 중첩을 없앤다.\
**엔진**: RE2 엔진으로 전환하고, 필드당 20ms 시간 상한 초과 시 필드 전체를 마스킹한다.

## 문제 구조 (추상화 코드)

### 변형 A — 중첩 수량자 규칙
① 문제 코드
```python
ADDR = re.compile(r"(\S+\s?)+(로|길)\s?\d+")
masked = ADDR.sub(mask, memo)
```
② 고친 코드
```python
ADDR = re2.compile(r"\S+(로|길)\s?\d+")      # 중첩 제거 + 선형 엔진
masked = ADDR.sub(mask, memo[:2000]) if len(memo) <= 2000 else MASK_ALL
```
무엇이 깨졌나: 실패하는 입력에서의 비용을 고려하지 않은 정규식이 공용 경로에 들어갔다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 선형 시간 엔진 | 엔진 교체 | 중간 | 문법 제한 | 기본 |

# issue/maskd/regex-backtrack-latency — 정리 (힌트)

태그: `performance` · `regex`

## 전체 흐름

```
(\S+\s?)+ (로|길) ...
  긴 문자열에 '로|길' 이 끝내 없으면 → (\S+\s?)+ 의 분할 방법을 전부 시도 → 지수 시간
  메모 400자, 공백 적음 → 요청 하나 3~4초

대부분 응답: 메모 짧거나 주소 포함 → 빠름
maskd 워커 32개 중 몇 개만 묶임 → 평균 CPU 낮음, p99 만 상승
```

## 핵심 문장

- `(\S+\s?)+` 같은 **중첩 수량자**는 일치 실패 시 분할 조합을 모두 시도해 지수 시간이 된다.
- **긴 메모 + 주소 키워드 없음** 조합에서만 느렸다 — p99만 올랐다.
- 선형 시간 엔진(RE2 계열)은 백트래킹이 없어 이 문제가 없다.
- 규칙에 입력 길이 상한과 시간 상한을 두고, 중첩 수량자를 금지하는 린트를 넣는다.

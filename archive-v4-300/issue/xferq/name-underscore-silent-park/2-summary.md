# issue/xferq/name-underscore-silent-park — 정리 (힌트)

태그: `silent-failure` · `contract-drift`

## 전체 흐름

```
배치 ──send --as NAME──▶ xferq ──▶ spool
                           │
         NAME 의 '_' ≤ 3 개 │ st 2 (상대 수신함)  ──▶ ls / pull 에 나온다 → 상대가 받는다
         NAME 의 '_' ≥ 4 개 │ st 6 (묶임)         ──▶ ls / pull 에 안 나온다 → 상대는 모른다
                           │
                           └─ 두 경우 모두: stdout "T0000xxxx", exit 0, stderr 없음

이름 예                                   '_' 수   결과
  HBP_RECON_K01_20260814.dat               3       st 2 (첫 전송)
  HBP_RECON_K01_20260814_R1.dat            4       st 6 (재전송 — 묶임)
  HBPRECONK0120260814ABCDEFGHIJKLMNOP.dat  0       st 2 (길이 무관)
  A__B__C.dat                              4       st 6 (빈 필드도 센다)
  HBP_RECON_K01_20260814-R1.dat            3       st 2 (덧붙임을 '-'로)

잘못된 교정: 길이 탓으로 보고 이름을 줄임(HBP_RECON_K01_260814_R1.dat) → '_' 4개 그대로라 여전히 st 6, 날짜 형식이 바뀌어 상대 적재기도 못 고른다
올바른 교정: 합의 접두는 유지, 덧붙이는 표시(재전송·분할 번호 등)는 '_' 아닌 구분자로 → '_' ≤ 3
발견 방법:   status <접수번호> 의 마지막 칸 (2=수신함, 6=묶임) · 보낸 이름 vs ls --to <상대> 대조
```

## 핵심 문장

- `xferq send`는 원격 이름에 **`_`가 4개 이상**이면 오류 없이 exit 0·접수 번호를 주고, 전송을 **st 6(묶임)**으로 남긴다 — 상대 수신함(`ls`·`pull`)에 나타나지 않는다.
- 기준은 **이름 길이도 필드 의미도 아니고 `_` 문자 개수**다 — 빈 필드(`__`)도 센다. 하이픈·점은 세지 않는다.
- 대처는 **합의 접두는 그대로 두고, 덧붙이는 부분을 `-` 등 다른 구분자로** 붙여 `_`를 3개 이하로 유지하는 것이다.
- 접수 번호는 "접수"일 뿐 "전달"이 아니다 — 전달은 `status`의 st 2 또는 `ls --to <상대>`에 이름이 나오는지로 판정한다.
- 묶인 전송은 저절로 풀리지 않는다 — 올바른 이름으로 다시 보내면 새 전송이 생기고 묶인 건은 그대로 남는다(정리는 벤더 창구).

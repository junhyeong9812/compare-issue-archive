# issue/xferq/vendor-dc-move-hostkey-mismatch — 정답

태그: `environment-drift` · `vendor-notice` · `security`

## 정답
<!-- 질문 1:1 대응 -->

1. **호스트 키 불일치로 연결이 거부됐다는 오류였다.**\
인증서·비밀번호 오류가 아니라 서버 신원 확인 단계에서 끊겼다.

2. **공지가 퇴사한 담당자 개인 메일로 갔다.**\
벤더 연락처 목록이 개인 주소로 등록돼 있었고 퇴사 처리 때 전달 설정이 없었다.

3. **다른 카드사는 서버 이전이 없었다.**\
같은 도구·같은 배치라도 상대 서버 신원만 달라졌다.

4. **경보가 파일 단위 24시간 기준이었고, 매일 새 파일이 생겨 기준에 닿지 않았다.**\
상대별 "마지막 성공 전송 시각" 경보가 없었다.

5. **키 검사를 끄거나 첫 연결 키를 자동 신뢰하게 바꾸는 것.**\
중간자 공격과 구별할 수 없게 된다 — 새 지문을 공지 원문·전화 확인으로 대조한 뒤 등록했다.

6. **벤더 연락처를 팀 메일링 리스트로 교체, 상대별 마지막 성공 전송 시각 경보(26시간) 추가.**\
미전송 3회차는 카드사와 협의해 재전송했다.

## 문제 구조 (추상화 코드)

### 변형 A — 상대별 성공 시각이 아닌 파일별 경보
① 문제 코드
```python
if file.age_hours > 24 and not file.sent:
    alert(file.name)
```
② 고친 코드
```python
for partner in PARTNERS:
    if now() - last_success(partner) > timedelta(hours=26):
        alert(f"{partner}: no successful transfer")
```
무엇이 깨졌나: 경보 단위가 파일이라 매일 새 파일이 상대 단위의 연속 실패를 가렸다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |

| 상대별 마지막 성공 경보 | 성공 기록 저장 | 작음 | 휴일 무전송과 구분 필요 | 기본 |

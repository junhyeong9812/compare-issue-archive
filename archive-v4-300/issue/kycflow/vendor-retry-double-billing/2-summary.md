# issue/kycflow/vendor-retry-double-billing — 정리 (힌트)

태그: `idempotency` · `data-semantics`

## 전체 흐름

```
kycflow ──요청 #1 (3s 타임아웃)──▶ 벤더 처리 3.4s → 과금 1
        ──재시도 #2──────────────▶ 벤더 처리 0.8s → 과금 2   ← 새 요청으로 봄
        ◀── 응답 #2 성공
내부 집계 = 최종 성공 1건 / 벤더 청구 = 2건

Idempotency-Key 를 같은 값으로 보내면 → 벤더가 #1 결과 재사용, 과금 1
키 = case_id + 시도 차수(사람 재요청 단위)  ← 네트워크 재시도 사이에는 같게
```

## 핵심 문장

- 벤더는 **도착한 요청마다** 과금한다 — 클라이언트가 포기한 요청도 벤더에서는 처리됐다.
- 벤더가 지원하는 `Idempotency-Key`를 **네트워크 재시도 사이에 같은 값**으로 보내면 중복 과금이 없다.
- 키는 심사 건 ID와 사람 재요청 차수로 만든다 — 재시도마다 새로 만들면 소용없다.
- 벤더 지연이 큰 시간대(월말 가입 몰림)에 타임아웃이 늘어 차이도 커졌다.
- 청구 대사는 **벤더 거래 ID 목록**과 내부 호출 로그를 맞대 1:N 매핑을 본다.

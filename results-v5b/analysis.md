# 5차-b 분석 — 의사결정 히스토리 (ADR-0006)

- 실행: 10케이스 × B·L·P·F × 3회 × Sonnet·Haiku = 240회. 무효·변조는 0건이고 재실행은 없다.
  - 파일럿 6회는 따로 둔다(`results-v5b-pilot`).
- 과제는 버그 수정이 아니라 **변경 요청**이다. 순진하게 구현하면 test.sh는 통과하지만, 과거 결정의 불변식을 검사하는 hidden에서 실패한다.
- 실행 조건:
  - 결과 폴더: `results-v5b`, `results-v5b-haiku`
  - 아카이브: `archive-v6/issue`(관련 10 + 미끼 12)
  - 프롬프트 세트: `--prompt-set decision`
  - 같은 케이스는 동시에 돌리지 않았다. Sonnet → Haiku 순차.
- 집계 스크립트: 세션 scratchpad `an5b.py`
- 총 토큰 = input + output + cache_creation + cache_read. ÷B는 이번 실험 B 중앙값으로 나눈다(Sonnet 154,375, Haiku 330,236).
- **실패 분류:** 실패한 실행의 hidden 실패 항목이 그 케이스 naive.patch의 hidden 실패 항목과 겹치면 **결정 위반**, 아니면 **그 밖**이다.
  - hidden 출력이 잘린 01·08 실패는 보존된 작업 폴더로 hidden을 다시 돌려 분류했다.

### 토큰

- Sonnet은 L 0.88, P 0.93, F 1.05다. 거의 B 수준이다.
- Haiku는 L·P·F 모두 1.14~1.21로 B보다 비싸다.
  - 기록을 받으면 대안 구현(상태 추가·별도 표시·런북 갱신 등)이 커지고, 결정을 설명하는 출력이 늘어난다(관찰, 토큰 내역은 분해하지 않음).
- 3차(버그 수정, 블랙박스 규칙 카드)의 ÷B 0.42~0.64와 달리, **결정 기록은 토큰을 줄이지 않는다.** 가치는 정답률(결정 위반 방지) 쪽에 있다.
- 미끼 결정 기록 열람: F 60회 중 6회. 03과 주제가 가까운 bizmsg 타임아웃 재발송 미끼는 1회 열람에 그쳤다.

## 판정 (ADR-0006 "예측과 판정")

- **가설 지지: 정답률 측면.**
  - 기록이 없는 B는 test.sh를 통과하면서 과거 결정을 깨는 변경을 Sonnet 33%, Haiku 20% 냈다.
  - 결정 기록을 받으면(요약 2~3줄 L 포함) 180회 중 위반 0이다.
- 토큰 측면의 이득은 없다(Sonnet ≈1, Haiku 1.14~1.21).
  - ADR-0006의 두 번째 예측 "B가 단서로 싸게 복원하면 가치는 탐색 비용 쪽"과는 반대다.
  - B는 싸게 복원하지 못하고 그냥 결정을 모른 채 구현했다. 기록의 가치는 비용이 아니라 **위반 방지**다.
- 1~4차와 합친 그림:

| 기록 종류 | 정답률 효과 | 토큰 효과 |
|---|---|---|
| 일반 CS 지식(1·2차) | 없음 | 손해 |
| 모델이 모르는 벤더 동작(3차) | B도 대부분 성공 | 절반 안팎으로 절감 |
| 낡은 벤더 동작(4차) | 오히려 위반 유발 | 손해 |
| 의사결정 히스토리(5차-b) | 위반 방지(B 20~33% → 0%) | 중립~약간 손해 |

## 한계

- 결정의 단서는 케이스 안 파일 2~5곳에만 두었다. git 이력이나 더 큰 저장소에서는 B의 복원 비용이 다를 수 있다.
- 케이스는 3회씩이라 케이스 단위 차이(예: 01 Sonnet 2/3 대 Haiku 0/3)는 변동이 크다.
- 결정 기록이 정확하다는 전제다. 낡은 결정 기록(결정이 이미 폐기됨)의 피해는 재지 않았다. 4차의 낡은 카드 결과를 보면 같은 위험이 있을 것이다.
- 04 hidden의 "빈 날 표시 불변" 검사는 결정과 무관한 회귀 검사다. 그래서 결정 위반과 따로 셌다.
- 03은 파일럿 게이트에 미달한 케이스다(B가 싸게 복원). 재설계하지 않고 포함했다(log.md).

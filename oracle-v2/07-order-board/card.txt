채택 사건: 변형 C — 중복 키 무음 덮어쓰기 (여러 도메인 상태를 한 평면 맵에 합침)
  인용(3-answer.md 정답 3): "JS 런타임 에러는 나지 않는다 — ... 같은 키를 허용하고 **마지막 값**으로 덮는다(TS 타입 검사는 리터럴 키 중복을 오류로 잡지만, JS 파일·검사 제외 경로·계산된 키에서는 통과한다)."
  인용(3-answer.md 정답 3): "여러 도메인(주문·결제·…)의 상태를 한 평면 맵에 넣으면 같은 단어(`PENDING`)가 충돌한다. 도메인별 상태 타입·메타로 분리"
1차와의 차이: 1차는 변형 D(await 없는 return). v2는 변형 C. 리터럴 중복은 tsc 7이 TS1117로 잡으므로(계산된 enum 키도 실측 거부), 도메인별 맵을 객체 스프레드로 합치는 형태로 숨겼다 — 같은 "평면 맵에서 마지막 값이 조용히 이김" 기제이며 tsc·런타임 모두 무음.
근본 원인: src/ui/badges/index.ts 가 ORDER/SHIPMENT/PAYMENT 배지 맵을 `{...ORDER, ...SHIPMENT, ...PAYMENT}` 로 한 평면 맵에 합쳐, 도메인 간 같은 상태 문자열(PENDING: 주문↔결제, FAILED: 배송↔결제)이 결제 쪽 값으로 조용히 덮인다. 증상은 API 응답(주문 상태 칸 "결제 대기", 대시보드 확인 필요 누락).
올바른 해결: 도메인별 맵을 분리 유지하고 조회에 도메인을 함께 넘긴다(badgeFor(domain, status) / orderBadge·paymentBadge·shipmentBadge), presenter 가 칸마다 해당 도메인 조회를 쓴다.
미끼: src/ui/statusPriority.ts(같은 PENDING 키를 가진 도메인별 맵 — 분리돼 있어 무죄), src/util/money.ts 의 memo 캐시(로케일 키, 무죄), src/repository/paymentRepository.ts latestFor(최신 결제 선택 — 무죄), src/presenter/dashboardPresenter.ts(톤 집계 — 무죄).
hidden: 보이는 테스트는 주문 PENDING 만 본다. hidden 은 배송 FAILED ↔ 결제 FAILED 충돌, 결제 PENDING, 반송, 상태 필터 목록, 대시보드 attention·톤 집계를 다른 데이터로 검사 → 스프레드 순서만 바꾸기(주문을 마지막에)·presenter 에서 PENDING 만 땜질하기를 잡는다.

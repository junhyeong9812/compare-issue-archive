# 신규 가입 일부가 '확인 대기'에서 넘어가지 않습니다

## 상황
회원 가입 서비스(hbonboard)는 가입 직후 회원을 `pending`(확인 대기)으로 두고, 본인확인 실행(`POST /kyc/run`)에서 결과를 받아 `active` 또는 `rejected`로 바꿉니다.
10월 9일 가입분 23명에 대해 본인확인 실행을 돌렸는데 일부 회원이 계속 확인 대기입니다.

- 실행 응답은 200이고 23명 모두 보냈다고 나옵니다(`sent: 23`). 오류 로그는 없습니다.
- 절반가량은 결과가 나와 가입 완료·거절 문자가 나갔지만, 나머지는 그대로 `pending`이고 문자도 받지 못했습니다.
- 다음 날 본인확인 실행을 다시 돌려도 이 회원들은 그대로입니다. 고객센터에 "가입이 끝나지 않는다"는 문의가 들어오고 있습니다.
- 운영 콘솔의 대기 현황(`GET /reports/kyc-backlog`)에도 같은 회원들이 남아 있습니다.
- 남는 회원은 매번 같은 사람들이고(예: M2610003, M2610008, M2610020), 가입 경로·나이·통신사·이름 형식에는 공통점이 없습니다.

환경: Ubuntu 24.04, Python 3.12. 본인확인 벤더 CLI는 `vendor/bin/idchk`(벤더 제공 바이너리, 수정 불가)입니다. 샘플 데이터(`tests/fixtures/signups_2026_10.json`)로 재현됩니다.

## 기대
- 본인확인 실행 한 번이면 그때까지 가입한 회원 모두가 확인 결과(`active` 또는 `rejected`)를 받아야 합니다.
- 결과는 본인확인 벤더의 판정과 같아야 하고, 지금 결과가 정상으로 나오는 회원은 그대로여야 합니다.

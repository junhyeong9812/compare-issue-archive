# 이번 설정 배포 후 api 서버들이 옛 설정으로 떠 있습니다

## 상황
10월 8일 릴리스(`r2026.10.08`)로 api 풀의 DB 커넥션 풀 크기(20 → 40)와 HTTP 타임아웃(3000 → 2500ms)을 바꿨습니다.
배포 후에도 api-01·02·03 세 대가 계속 커넥션 부족 경보를 내서 확인해 보니, 세 서버의 `app.conf`가 여전히 20 / 3000이었습니다.

- 배포(`bin/rollout apply r2026.10.08`)는 exit 0으로 끝났고, verify 단계도 "verified 7 hosts"로 통과했습니다.
- 같은 릴리스에 들어 있던 batch 풀의 fast-pay 켜기와 bat-02 로그 레벨 debug는 정상으로 반영됐습니다.
- 배포가 끝난 뒤 운영자가 설정 서비스에서 `pool.api.db_pool_size`를 조회하면 40이 나옵니다. 서버 설정 파일만 20입니다.
- 지난주 기준 배포(`r2026.10.01`)를 새 환경에 처음 깔았을 때는 모든 서버가 정상이었습니다.

환경: Ubuntu 24.04, bash 5.2, GNU coreutils/sed. 설정 서비스 CLI는 `vendor/bin/cfgsvc`(벤더 제공 바이너리, 수정 불가)입니다.
저장소의 릴리스 파일 두 개로 재현됩니다.

## 기대
- 배포가 끝나면 모든 활성 서버의 `app.conf`가 그 시점 설정 서비스에 있는 값과 같아야 합니다(릴리스로 바꾼 값, 운영자가 서비스에 넣은 값 모두).
- 이번 릴리스와 무관한 서버·설정은 그대로여야 합니다.

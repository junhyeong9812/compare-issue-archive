# 배송 출발 알림 문자를 못 받은 고객이 있습니다

CS팀 문의입니다. 주문 알림 서비스는 발송 회차(`POST /dispatch`)마다 쌓인 주문 이벤트(결제 완료·배송 시작·배송 완료)를 고객 문자로 보내고, 회차 리포트(`GET /reports/dispatch/:runId`)를 운영 화면에 띄웁니다.

## 상황
- 지난주부터 "배송이 시작됐다는 문자를 못 받았다"는 고객 문의가 하루 몇 건씩 들어옵니다.
- 해당 회차 리포트를 보면 계획·발행 건수는 맞는데 발송 건수가 모자라고, 몇몇 주문이 "미발송"으로 남아 있습니다. 예) `계획 7 / 발행 7 / 발송 4 / 실패 0`
- 못 받은 고객은 매번 다릅니다. 같은 고객이 다른 날에는 정상으로 받기도 합니다. 전화번호·수신 동의는 정상입니다.
- 회차 처리는 매번 오류 없이 끝나고, 서버 로그에도 예외가 없습니다.

환경: Node 18, 사내 메시지 발행 도구 mqpub 3.4.1(`vendor/bin/mqpub`, 스풀 디렉토리는 `MQPUB_SPOOL`). 저장소의 E2E 테스트로 재현됩니다.

## 기대
- 수신 동의한 고객의 주문 이벤트는 회차마다 빠짐없이 문자로 나가야 합니다.
- 리포트의 발송 건수와 실제 수신 내역이 일치해야 합니다.
- 회차 하나는 지금처럼 한 번에 발행되어야 하고, 같은 알림이 두 번 나가면 안 됩니다.

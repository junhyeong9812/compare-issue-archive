# issue/bizmsg/ad-template-night-hold — 정답

태그: `contract-drift` · `silent-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **다음 날 08:00 직후에 받는다.**\
`EVT_END_02`는 심사에서 AD로 분류된 템플릿이라, 21:00 접수 건은 `HOLD` 상태로 들어간다.\
`status`는 `st=HOLD accepted_at=21:00:02 release_at=08:00`을 보여 준다. 08:00에 `SENT`로 바뀐다.
   > **HOLD** — 벤더가 접수는 했지만 발송을 미뤄 둔 상태. 송신 응답에서는 구별되지 않는다.

2. **템플릿의 분류(category)가 달랐다.** "결제 완료"는 INFO, "이벤트 종료 안내"는 AD로 심사돼 있었다.\
발송 코드는 템플릿 코드만 바꿔 같은 함수로 보냈으므로 코드에서는 차이가 보이지 않는다.

3. **접수 시각 기준 20:50부터 다음 날 08:00까지.**\
법적 야간 광고 전송 제한(21시~08시)보다 10분 일찍 시작한다 — 벤더가 전송 지연을 감안해 둔 여유다.\
그래서 20:55 예약 건도 보류됐다. 벤더 연동 문서에는 "야간 광고 정책 준수"라고만 적혀 있었다.

4. **분류는 문구가 아니라 템플릿 심사 때 정해진다.**\
이 템플릿은 원래 쿠폰 링크 버튼이 달린 "이벤트 참여 안내"로 등록돼 AD로 심사됐고, 이후 문구만 바꿔 재사용됐다.\
`bizmsg tpl show EVT_END_02`의 `category=AD`가 근거다.

5. **내용이 실제로 정보성(거래·계약 이행 안내 등)일 때만 정보형 템플릿으로 새로 심사받아 보낸다.**\
혜택·이벤트 홍보가 들어 있으면 광고성이므로, 야간 발송에는 수신자의 야간 광고 수신 동의가 필요하다 — 동의가 없으면 08시 이후 발송이 맞는 동작이다.\
이번 사건은 "종료 안내"에 다음 이벤트 쿠폰이 함께 있어 광고성으로 판단하고, 발송 시각을 20:30으로 당기는 쪽을 택했다.

6. **`status`의 `accepted_at`과 `st`를 먼저 본다.**\
사내 큐가 늦었으면 `accepted_at` 자체가 늦다. `accepted_at`은 제시각인데 `st=HOLD`면 이 사건이다.

## 문제 구조 (추상화 코드)

### 변형 A — 템플릿 분류를 모르고 야간 예약
① 문제 코드
```ts
await scheduler.at("21:00", () => msg.send({ tpl: "EVT_END_02", to: users }));  // AD → HOLD
```
② 고친 코드
```ts
const tpl = await msg.templateInfo("EVT_END_02");
const sendAt = tpl.category === "AD" ? clampToAdWindow("21:00") : "21:00";  // 08:00~20:50 안으로
await scheduler.at(sendAt, () => msg.send({ tpl: tpl.code, to: users }));
```
무엇이 깨졌나: 발송 시각 결정이 템플릿 분류에 따른 벤더 보류 규칙을 고려하지 않았다.

### 변형 B — 접수 응답을 발송 완료로 기록
① 문제 코드
```ts
const id = await msg.send(req);
campaign.markSent(id, now());           // 실제 발송은 08:00
```
② 고친 코드
```ts
const id = await msg.send(req);
const st = await msg.status(id);
campaign.markAccepted(id, st.acceptedAt, st.state);   // HOLD 면 release_at 기록
```
무엇이 깨졌나: 캠페인 리포트의 "발송 시각"이 실제 수신 시각과 10시간 넘게 달랐다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| AD 템플릿은 08:00~20:50 안으로 예약 | 분류 조회 | 작음 | 마케팅 시각 요구와 충돌 | 기본 |
| 야간 광고 수신 동의 고객만 야간 발송 | 동의 데이터·벤더 동의 플래그 | 중간 | 동의 관리 누락 시 법 위반 | 야간 발송이 꼭 필요할 때 |
| 정보형으로 재심사 | 내용이 실제 정보성 | 작음 | 광고성 내용이면 위반 | 내용이 정보성일 때만 |

**결론**: 내용의 성격을 먼저 판단하고, 광고성이면 시간대를 지킨다. 분류는 코드가 발송 전에 조회한다.

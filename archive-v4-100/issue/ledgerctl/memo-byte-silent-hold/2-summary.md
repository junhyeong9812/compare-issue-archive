# issue/ledgerctl/memo-byte-silent-hold — 정리 (힌트)

태그: `silent-failure` · `encoding` · `contract-drift`

## 전체 흐름

```
배치 ──post --memo M──▶ ledgerctl ──▶ journal
                          │
         len_utf8(M) ≤ 48 │ st 1 (기장)  ──▶ list / 월말·대사 조회에 나온다
         len_utf8(M) > 48 │ st 4 (보류)  ──▶ list 에서 빠진다
                          │
                          └─ 두 경우 모두: stdout "R0000xxxx", exit 0, stderr 없음

글자 수 검증만 하는 호출부
  ASCII 40자   = 40 바이트  → 통과 (경계 밖)
  한글 17자    = 51 바이트  → 보류 (글자 수로는 짧다)
  한글 16자    = 48 바이트  → 통과 (정확히 경계)

잘못된 교정: bytes[:48] 그대로 전달 → 멀티바이트 문자 중간 절단 → 잘못된 UTF-8 → E17 (exit 3)
올바른 교정: 문자 단위로 누적하며 UTF-8 48바이트를 넘기 직전에서 멈춘다 → 항상 st 1
발견 방법:   show <영수번호> 의 st 값 (1=기장, 4=보류) · post 건수 vs list 건수 대사
```

## 핵심 문장

- `ledgerctl post`는 메모가 **UTF-8 48바이트**를 넘으면 오류 없이 exit 0·영수 번호를 주고, 전표를 **st 4(보류)**로 저장한다 — `list`에서 빠진다.
- 경계는 **글자 수가 아니라 바이트 수**다 — 한글(글자당 3바이트)·이모지(4바이트) 메모만 걸리고 영문 메모는 걸리지 않는다.
- 대처는 호출 직전 **문자 경계를 지키며 48바이트 이하로 자르기** — 바이트열을 그냥 자르면 E17로 거부된다.
- 영수 번호는 "접수"일 뿐 "기장"이 아니다 — 기장 완료는 `list`(또는 `show`의 st 1)로 대사해서 판정한다.
- 보류 건은 재전송해도 사라지지 않는다 — 대사는 영수 번호가 아니라 조회 결과 기준으로 한다.

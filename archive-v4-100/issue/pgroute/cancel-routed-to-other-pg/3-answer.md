# issue/pgroute/cancel-routed-to-other-pg — 정답

태그: `contract-drift` · `silent-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **PG-B로 가서 E-ORG(원거래 없음)를 받는다.** pgroute는 이를 일시 오류로 분류해 재시도 큐에 넣고 환불 서비스에는 '접수'만 돌려준다.

2. **PG-A와 PG-B가 상호 거래 조회 연동을 하고 있었기 때문이다.** PG-B가 모르는 거래를 PG-A에 대신 물어 처리했다. 8/5 계약 정리로 그 연동도 꺼졌다.

3. **원거래의 최대 취소 가능 기간(카드사 기준 승인 후 1년 등)까지다.** 신규 승인 가중치를 0으로 두는 것과 취소 경로 폐쇄는 별개 작업이다.

4. **취소 요청의 대상 PG와 원거래 승인 PG를 나란히 본다.** 다르면 라우팅 문제다. 재시도 큐의 E-ORG 건수도 경보 지표에 넣었다.

## 문제 구조 (추상화 코드)

① 문제 코드
```java
Pg pg = router.pick(merchant, amount);        // 승인·취소 공통
return pg.cancel(req);
```
② 고친 코드
```java
Pg pg = (req.type() == APPROVE) ? router.pick(merchant, amount)
                                : registry.get(origTxn.pgCode());  // 원거래 PG 고정
return pg.cancel(req);
```
무엇이 깨졌나: 취소를 독립 요청으로 보고 원거래와의 연결(어느 PG인가)을 라우팅에서 버렸다.

## 방안 비교

| 방안 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|
| 원거래 PG 고정 라우팅 | 원거래에 PG 코드 저장(이미 있음) | PG 폐쇄 시 취소 불가 — 폐쇄 일정 관리 필요 | 기본 |
| PG 간 거래 조회 연동 유지 | 계약 비용 | 상대 PG 의존 | 선택하지 않음 |

**결론**: 승인 외 요청은 원거래 PG로 고정하고, PG 계약 정리 시 취소 경로 유지 기간을 따로 정한다.

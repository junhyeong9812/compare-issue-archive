# issue/maskd/txid-pattern-masked-recon — 정리 (힌트)

태그: `silent-failure` · `data-semantics`

## 전체 흐름

```
정산 리포트 API ──응답 JSON──▶ maskd ──▶ 대사 배치
  {"tx_id":"20250805113042", "acct":"110234567890", ...}
maskd 2.4 규칙 R-17: 값이 숫자 10~14자리 → 앞 3·뒤 2 남기고 마스킹
  tx_id → "202*********42"   acct → "110*******90"
대사: tx_id 로 PG 기록과 조인 → 매칭 실패 → '미매칭'

신 형식 tx_id(14자리 숫자) = 08월 신규 파트너 3곳 / 구 형식 "T-…"(문자 포함) = 영향 없음
```

## 핵심 문장

- 규칙 R-17이 **값 모양(숫자 10~14자리)**만 보고 마스킹해 거래 ID까지 가렸다.
- 문자가 섞인 구 형식 ID는 안 걸리고, **숫자 14자리 ID를 쓰는 신규 파트너**만 미매칭이었다.
- 대사 배치는 마스킹된 값을 정상 문자열로 받아 '미매칭'으로 분류했다 — 오류가 없다.
- 마스킹은 **필드 이름 기반**으로 하고, 값 모양 규칙은 자유 텍스트 필드에만 쓴다.

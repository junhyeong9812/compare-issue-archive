# issue/maskd/txid-pattern-masked-recon — 정답

태그: `silent-failure` · `data-semantics`

## 정답
<!-- 질문 1:1 대응 -->

1. **`202*********42`를 받는다.** 숫자 14자리라 계좌번호로 판정됐다.

2. **거래 ID 형식이 파트너마다 달랐다.** 8월에 붙은 신규 파트너 3곳만 숫자 14자리 ID였다. 미매칭 하루 약 1,900건.

3. **됐다.** maskd는 호출자 구분 없이 모든 응답에 적용됐다. 대사 배치는 원래 개인정보 필드를 쓰지 않아 예외 대상이 아니었다.

4. **마스킹된 ID도 형식상 문자열이라 조인만 실패했다.** 미매칭은 평소에도 수십 건씩 있어 수작업 큐로 넘어갔고, 사흘 뒤 정산팀이 비율 급증으로 알렸다.

5. **필드 이름(`acct`, `account_no` 등) 목록 기반.** 값 모양 규칙은 메모·주소 같은 자유 텍스트 필드에만 적용한다. 규칙 추가 전 주요 API 응답 표본으로 영향 필드를 확인한다.

## 문제 구조 (추상화 코드)

### 변형 A — 값 모양으로 마스킹
① 문제 코드
```yaml
rules:
  - id: R-17
    match: value
    pattern: '^\d{10,14}$'
    action: mask_middle
```
② 고친 코드
```yaml
rules:
  - id: R-17
    match: field
    fields: [acct, account_no, refund_acct]
    action: mask_middle
  - id: R-17t
    match: value
    pattern: '\b\d{10,14}\b'
    fields: [memo, address_detail]     # 자유 텍스트만
```
무엇이 깨졌나: 개인정보 판정을 값의 모양에 맡겨, 같은 모양의 업무 식별자가 함께 가려졌다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 필드 이름 기반 | 필드 목록 관리 | 작음 | 새 필드 누락 | 기본 |
| 값 모양은 자유 텍스트만 | 필드 분류 | 작음 | 분류 실수 | 함께 |
| 규칙 추가 전 응답 표본 diff | 표본 수집 | 중간 | 표본 밖 API | 배포 검증 |

**결론**: 구조화 필드는 이름으로, 자유 텍스트는 모양으로 마스킹한다.

# issue/otpsvc/otp-shared-bulk-queue — 정리 (힌트)

태그: `resource-isolation` · `latency`

## 전체 흐름

```
otpsvc 발송 큐 (FIFO 하나, 발송사 처리량 초당 1,000)
  19:00 마케팅 400,000 건 적재  → 소진에 약 6.7분
  19:03 인증번호 1 건 적재       → 마케팅 뒤에서 대기 → 19:07 발송
인증번호 유효 3분 → 도착 시 이미 만료 → 재요청 → 또 대기

2025-11 마케팅팀이 '문자 발송 공용 모듈'로 otpsvc 클라이언트를 재사용 → 같은 큐
```

## 핵심 문장

- 인증번호와 마케팅이 **같은 FIFO 큐**를 써서 인증번호가 대량 발송 뒤에서 기다렸다.
- 발송 API의 '접수'는 큐 적재다 — 대기 시간을 알려 주지 않는다.
- 큐 대기가 **유효 시간(3분)을 넘으면** 도착해도 쓸 수 없다 — 재요청이 큐를 더 늘린다.
- 인증번호는 **전용 큐·전용 발송 계정**으로 분리하고, 큐 대기 시간을 지표로 본다.

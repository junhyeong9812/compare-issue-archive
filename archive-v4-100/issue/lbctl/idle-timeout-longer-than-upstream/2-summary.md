# issue/lbctl/idle-timeout-longer-than-upstream — 정리 (힌트)

태그: `timeout` · `race`

## 전체 흐름

```
백엔드: 5초 유휴 → FIN 전송
LB:     120초까지 커넥션 재사용 가능으로 판단
경쟁:   LB 가 요청을 쓰는 순간 백엔드가 닫음 → RST → 502
```

## 핵심 문장

- **백엔드가 먼저 닫으면** LB가 그 커넥션에 요청을 실어 보내는 경쟁이 생긴다.
- 트래픽이 적을 때 커넥션이 유휴 상태로 오래 있어 경쟁이 잦다.
- 이 LB는 요청 본문을 이미 보낸 뒤의 실패는 재시도하지 않는다.
- 백엔드 keep-alive를 LB 유휴 타임아웃보다 **길게** 둔다.

# issue/pushq/schedule-offslot-silent-ticket — 정답

태그: `silent-failure` · `contract-drift`

## 정답
<!-- 질문 1:1 대응 -->

1. **나오지 않는다.** `10:17:42`는 5분 경계가 아니다.\
pushq는 이런 예약에도 티켓 번호를 발급하고 exit 0으로 끝나지만 큐에는 넣지 않는다.\
직후 `pushq list`에 그 티켓이 없고, 시각이 지나 `pushq run`을 돌려도 `pushq log`에 나오지 않는다.
   > **티켓** — `schedule` 한 번마다 1씩 오르는 접수 번호. 적재 여부와 무관하게 발급된다.

2. **`10:15:00`·`10:20:00`만 적재된다.**\
`10:17:00`은 분이 5의 배수가 아니라서, `10:20:30`은 초가 00이 아니라서 빠진다.\
판정 기준은 "분이 5의 배수이고 초가 00" 둘 다다 — 하루를 300초 단위로 나눈 경계에 정확히 놓여야 한다.

3. **성공 신호가 전부 정상이기 때문이다.** 티켓 번호, exit 0, stderr 없음.\
예약 측은 "예약함"으로 기록하고, 손실은 고객 쪽 "안 왔다"로만 드러난다.\
쿠폰 만료 알림 사건에서도 발송 대시보드의 예약 성공률은 100%였고, 가입 축하 쿠폰 사용률이 떨어진 지표로 처음 드러났다.\
손실을 처음 보여 줄 수 있는 명령은 예약 직후의 `pushq list`(티켓 부재)와 시각 이후의 `pushq log`(발송 부재)다.

4. **예약 시각이 고정 시각에서 왔느냐, 이벤트 시각에서 왔느냐의 차이다.**\
정각 일괄 발급 쿠폰은 발급이 `10:00:00`이라 만료 − 60분도 `09:00:00` 같은 경계 시각이 됐다.\
가입 축하 쿠폰은 가입 순간(`10:17:42` 등)에 발급돼 만료·알림 시각에 그 초까지 실렸다.\
경계에 우연히 맞는 가입 시각(300초 중 1초)만 살아남아, 거의 전부가 사라지면서도 아주 가끔 받는 고객이 있었다.\
어떤 고객이 잃는지는 가입 시각에 달려 있어 매번 달라 보였다.

5. **기한 알림에는 ①만 맞다.**\
① 직전 경계로 내림: 최대 4분 59초 일찍 도착한다. 약속 시점("만료 1시간 전")보다 늦지 않는다.\
② 올림: 적재는 되지만 최대 5분 늦게 도착해 "1시간 전" 약속을 어긴다. 시작 시각 안내처럼 "일러서는 안 되는" 알림에만 맞다.\
③ 반올림: 절반은 늦게 도착한다 — 기한 알림에서 고른 시각과 실제 시각의 방향이 섞여 검증이 어렵다.\
④ 즉시 발송: 빠진 것을 발견한 순간에 도착하므로 시각 약속이 깨지고, 근본 원인(경계 밖 예약)이 그대로 남는다.\
방향은 업무 약속으로 정한다 — "늦으면 안 됨"이면 내림, "이르면 안 됨"이면 올림.

6. **탐침 5~6회로 확정된다.**\
앱이 실제로 만드는 시각(초 포함)과 그 시각을 정각 분으로 바꾼 것을 각각 `schedule` → `list`로 어느 쪽이 남는지 본다.\
분만 바꿔 가며(`:15`, `:16`, `:17`) 반복 → 5의 배수만 남는다.\
5의 배수 분에 초를 붙여(`:20:30`) 반복 → 빠진다(초도 조건임).\
`run --until`로 시각을 넘긴 뒤 `log`로 빠진 티켓이 끝내 발송되지 않음을 확인한다.

7. **티켓이 아니라 큐를 확인한다.** 예약 직후 `pushq list`에 그 티켓이 있는지 대조하고, 없으면 예약 실패로 기록한다.\
예약 시각을 만드는 함수 끝에서 "경계에 맞는가"를 단언하면, 계산식이 바뀌어 경계 밖 시각이 섞이는 것을 배포 전에 잡는다.

## 문제 구조 (추상화 코드)

### 변형 A — 이벤트 시각에서 계산한 예약이 경계 밖으로 나감 (가입 쿠폰 만료 알림)
① 문제 코드
```ts
// 쿠폰 발급 → 만료 1시간 전 알림 예약
const expiresAt = addHours(issuedAt, 72);          // issuedAt = 가입 순간, 초까지
const notifyAt = addMinutes(expiresAt, -60);       // 10:17:42 같은 시각
const ticket = push.schedule(device, notifyAt, tag, text);   // 티켓·exit 0 — 그러나 큐에는 없음
markScheduled(coupon, ticket);
```
② 고친 코드
```ts
const SLOT = 300;                                   // 벤더 예약 경계(초)
const floorToSlot = (t) => fromEpoch(toEpoch(t) - (toEpoch(t) % SLOT));
const notifyAt = floorToSlot(addMinutes(expiresAt, -60));   // 늦지 않게 직전 경계로
const ticket = push.schedule(device, notifyAt, tag, text);
if (!push.list().some((q) => q.ticket === ticket)) markFailed(coupon);   // 적재 대조
```
무엇이 깨졌나: 예약 시각이 벤더의 5분 경계 밖이라 접수(티켓)만 되고 큐에 적재되지 않았다.\

| 빠진 건 즉시 발송 | 시각 무관 | 발견 로직 필요 | 엉뚱한 시각 도착·원인 잔존 | 선택하지 않은 방법 |

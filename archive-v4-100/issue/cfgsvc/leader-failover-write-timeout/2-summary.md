# issue/cfgsvc/leader-failover-write-timeout — 정리 (힌트)

태그: `availability` · `timeout` · `operations`

## 전체 흐름

```
14:00~14:40  노드 순차 패치 (인프라팀)
14:12  리더 노드 재시작 → 새 리더 선출 (선출 제한 시간 설정: 기본값 그대로, 실측 20~35초)
       그 사이 쓰기 요청: 리더 없음 → 대기 → 콘솔 타임아웃 30초 → 오류
       읽기: 각 노드 로컬 응답 → 정상
14:13  새 리더 → 재시도 성공
콘솔: 오류 후 사용자가 다시 눌러 저장 2번 → 변경 이력 중복
```

## 핵심 문장

- 원인은 **리더 노드 재시작으로 인한 리더 선출 대기** — 그동안 쓰기는 받을 노드가 없었다.
- 인프라팀은 순차 패치라 무중단이라고 봤지만, **리더 노드를 먼저 내리면** 선출 시간만큼 쓰기가 멈춘다.
- 읽기는 각 노드가 응답해 결제 서버는 영향이 없었다 — **읽기와 쓰기의 가용성이 다르다**.
- 대처는 리더 노드를 마지막에 패치하고 그 전에 리더 이양, 콘솔 저장은 요청 키로 중복 방지, 패치 공지를 운영 콘솔 사용자에게.

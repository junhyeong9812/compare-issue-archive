# issue/cfgsvc/leader-failover-write-timeout — 정답

태그: `availability` · `timeout` · `operations`

## 정답
<!-- 질문 1:1 대응 -->

1. **리더 노드가 패치로 재시작돼 새 리더 선출 중이었다.**\
선출이 끝나기 전 쓰기는 대기하다 콘솔의 30초 제한에 걸렸다.

2. **리더 노드를 먼저 패치했기 때문이다.**\
팔로워부터 하고, 리더는 마지막에 리더 이양 후 내렸어야 했다.

3. **읽기는 리더 없이 각 노드가 응답했다.**

4. **사용자가 다시 누르면서 같은 변경이 두 번 기록됐다.**\
변경 이력 감사에서 중복 두 건이 나와 원인 조사가 늦어졌다.

5. **패치 순서(팔로워 먼저·리더 이양 후 리더), 콘솔 저장 요청에 요청 키, 패치 공지 대상에 운영 콘솔 사용자 추가.**

## 문제 구조 (추상화 코드)

### 변형 A — 리더 여부를 보지 않은 순차 패치
① 문제 코드
```sh
for n in cfg1 cfg2 cfg3; do patch_and_restart $n; done
```
② 고친 코드
```sh
leader=$(cfg_leader)
for n in $(cfg_nodes | grep -v "$leader"); do patch_and_restart $n; done
cfg_transfer_leader "$leader" && patch_and_restart "$leader"
```
무엇이 깨졌나: 노드를 동등하게 취급해 리더 재시작이 쓰기 중단이라는 사실을 놓쳤다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 리더 마지막·이양 후 패치 | 이양 기능 | 작음 | 이양 실패 시 수동 | 기본 |
| 콘솔 요청 키 | 콘솔 수정 | 작음 | 키 재사용 실수 | 기본 |
| 콘솔 타임아웃 60초 | — | 작음 | 사용자 대기 증가 | 선택하지 않은 방법 |

**결론**: 순차 패치도 리더를 먼저 내리면 중단이다 — 리더는 이양 후 마지막에.

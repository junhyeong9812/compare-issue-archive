# issue/mlgsettle/partner-cutoff-2330-window — 정답

태그: `contract-drift` · `single-source-of-truth`

## 정답
<!-- 질문 1:1 대응 -->

1. **6월 3일 파일에는 없고 6월 4일 파일에 들어 있다.**\
제휴사 정산일 6/4는 6/3 23:30부터 6/4 23:30까지다. 23:41 적립은 그 창에 속한다.\
`export` 출력의 각 줄에는 `settle_date` 칸이 있고, 이 건은 `2026-06-04`로 찍혀 있다.
   > **정산일(settle_date)** — 제휴사가 이 거래를 정산하는 기준 날짜. 거래 발생 일시와 다를 수 있다.

2. **같은 건들이 경계를 넘어 다음 날로 옮겨 가기 때문이다.**\
사내 리포트는 적립 일시의 달력일로 묶었다. 매일 23:30~24:00 적립분이 사내 D와 제휴 D+1에 각각 잡혔다.\
그래서 D에는 사내가 많고, D+1에는 전날 밤 분이 제휴에만 더해져 사내가 적다 — 하루 단위로 보면 차이가 계속 나지만 두 날을 합치면 거의 상쇄된다.\
남는 차이는 월말 마감 시각이 다른 날에만 커졌다.

3. **아니다.** 평일·주말 모두 23:30이지만, 매월 말일은 22:00, 12월 31일은 18:00이다.\
월말에는 22:00~23:30 적립분이 다음 달 1일 정산으로 넘어가 월 정산 대사에서 차이가 크게 보였다.\
이 예외는 제휴 계약 부속서에만 있고 API 문서에는 없다.

4. **귀속(어느 날에 속하는가)의 규칙이 두 시스템에서 다르다는 것.**\
건별 값(회원·금액·적립률)이 모두 맞는다면 계산 로직이 아니라 집계 단위가 다르다.\
이번 사건은 1주일 동안 계산 로직(반올림·적립률 테이블)을 의심하며 시간을 썼다.

5. **충분하지 않다.** 월말·연말 예외가 빠지고, 제휴사가 마감 시각을 바꾸면 다시 깨진다.\
정산 파일을 받은 뒤 각 건의 `settle_date`를 사내 적립 테이블에 저장하고, 대사는 그 컬럼으로 묶는다.\
정산 파일이 아직 오지 않은 당일 분은 "미정산"으로 따로 표시한다.

6. **건별 대조(거래 번호 기준 조인)를 먼저 한다.**\
식별자 변환 문제면 특정 회원·거래가 한쪽에 "없음"으로 남는다.\
창 문제면 모든 건이 양쪽에 있고, 날짜 귀속만 다르다(23:30 이후 건에 몰린다).

## 문제 구조 (추상화 코드)

### 변형 A — 달력일로 묶은 일별 대사
① 문제 코드
```sql
SELECT DATE(earned_at) AS d, SUM(miles)
FROM mileage_earn
GROUP BY DATE(earned_at);        -- 사내 기준: 달력일
-- 제휴 정산 파일의 일 합계와 d 기준으로 비교
```
② 고친 코드
```sql
-- 정산 파일 수신 시 settle_date 를 적립 건에 기록해 둔다
SELECT settle_date AS d, SUM(miles)
FROM mileage_earn
WHERE settle_date IS NOT NULL
GROUP BY settle_date;            -- 제휴 기준 귀속으로 비교
```
무엇이 깨졌나: 두 시스템이 같은 "일자"라는 말을 다른 경계로 쓰고 있었다.

### 변형 B — 마감 시각을 상수로 흉내 낸 1차 수정
① 문제 코드
```java
LocalDate settleDate(LocalDateTime t) {
    return t.toLocalTime().isBefore(LocalTime.of(23, 30)) ? t.toLocalDate() : t.toLocalDate().plusDays(1);
}
```
② 고친 코드
```java
// 정산일은 제휴사가 정한 값을 받아 쓴다 — 사내에서 계산하지 않는다
earn.setSettleDate(partnerRow.settleDate());
```
무엇이 깨졌나: 월말 22:00·연말 18:00 예외를 몰라 월 정산에서 다시 어긋났다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 정산 파일의 settle_date 저장 후 대사 | 파일에 건별 거래 번호 | 컬럼 1개·적재 로직 | 파일 지연 시 당일 대사 불가 | 기본 |
| 마감 시각 규칙을 사내에서 재계산 | 규칙 전부를 앎 | 작음 | 예외·변경에 깨짐 | 선택하지 않은 방법 |
| 주 단위로만 대사 | 상쇄 허용 | 작음 | 실제 누락이 상쇄에 묻힘 | 선택하지 않은 방법 |

**결론**: 귀속 날짜는 정산 주체(제휴사)가 정한 값을 그대로 받아 쓴다.

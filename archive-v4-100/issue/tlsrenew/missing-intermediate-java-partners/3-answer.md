# issue/tlsrenew/missing-intermediate-java-partners — 정답

태그: `tls` · `deploy`

## 정답
<!-- 질문 1:1 대응 -->

1. **브라우저는 성공, 자바 클라이언트는 `PKIX path building failed`.**

2. **합성 점검이 브라우저 엔진이었다.**

3. **이전엔 사람이 수동으로 체인 파일을 넣었고, 자동화 전환 때 경로가 `cert.pem`으로 바뀌었다.**

4. **배포 후 `s_client`로 체인 2개 이상 확인 + 자바 HTTP 클라이언트 점검을 추가.**

## 문제 구조 (추상화 코드)

### 변형 A — 리프 인증서만 배포
① 문제 코드
```nginx
ssl_certificate /etc/tlsrenew/api/cert.pem;
```
② 고친 코드
```nginx
ssl_certificate /etc/tlsrenew/api/fullchain.pem;
```
무엇이 깨졌나: 자동화 전환에서 파일 의미가 바뀐 것을 검증하지 않았다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| fullchain 사용 + 체인 검증 | 배포 스크립트 | 작음 | 없음 | 기본 |
| 다양한 클라이언트 합성 점검 | 점검 추가 | 작음 | 점검 유지 | 함께 |
| 파트너에 중간 인증서 배포 요청 | 파트너 협조 | 큼 | 파트너마다 다름 | 선택하지 않은 방법 |

**결론**: 체인 파일을 쓰고 비브라우저 클라이언트 점검을 둔다.

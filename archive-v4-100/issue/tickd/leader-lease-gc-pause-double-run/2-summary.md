# issue/tickd/leader-lease-gc-pause-double-run — 정리 (힌트)

태그: `concurrency` · `split-brain`

## 전체 흐름

```
노드 A (리더, 리스 TTL 10s)  ── 09:00:00 작업 시작 직전 Full GC 14초 정지
노드 B : 09:00:11 리스 만료 확인 → 리더 획득 → 작업 실행
노드 A : 09:00:14 GC 끝 → 자신이 아직 리더라고 믿고 작업 실행
→ 같은 회차 2회 실행, 앞 구간 일부 고객 중복 발송
```

## 핵심 문장

- 리스 기반 리더 선출에서 리더는 **리스가 아직 유효한지 실행 직전에 확인**해야 한다 — 정지된 프로세스는 시간이 흐른 것을 모른다.
- `tickd` 1.9는 리스 갱신 스레드와 실행 스레드가 분리돼 있어, 실행 스레드가 오래된 "리더" 플래그를 읽었다.
- 대처: 실행 시 펜싱 토큰(리스 세대 번호)을 작업 실행 기록에 조건부로 써서, 낮은 세대는 실행을 거부. 발송 작업은 회차 키로 멱등 처리.

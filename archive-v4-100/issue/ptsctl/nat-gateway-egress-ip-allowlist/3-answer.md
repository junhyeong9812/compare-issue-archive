# issue/ptsctl/nat-gateway-egress-ip-allowlist — 정답

태그: `environment-drift` · `network` · `vendor-notice`

## 정답
<!-- 질문 1:1 대응 -->

1. **출발지 공인 IP가 바뀌었다.**\
NAT 게이트웨이 교체 때 기존 고정 IP 재할당이 실패해 새 IP가 붙었다.

2. **외부 벤더의 IP 허용 목록 의존을 기록한 곳이 없었다.**\
점검은 사내 방화벽 규칙만 봤다.

3. **환율·본인확인 벤더는 출발지 IP를 제한하지 않는다.**

4. **벤더 측 허용 목록 변경이 영업일 담당자 확인 절차를 거쳤다.**\
사전 등록된 예비 IP가 없었다.

5. **IP 허용 목록 벤더 대장, 고정 IP 이전 실패 시 작업 중단, 벤더에 예비 IP 두 개 사전 등록.**

## 문제 구조 (추상화 코드)

### 변형 A — 출발지 IP 의존을 모른 채 네트워크 변경
① 문제 코드
```text
NAT 교체 체크리스트
- 사내 방화벽 규칙 확인
- 라우팅 테이블 확인
```
② 고친 코드
```text
NAT 교체 체크리스트
- 사내 방화벽 규칙 확인
- 라우팅 테이블 확인
- 고정 IP 이전 성공 확인 (실패 시 작업 중단)
- IP 허용 목록 벤더 대장의 벤더별 접속 시험
```
무엇이 깨졌나: 외부 상대가 우리의 IP에 의존한다는 사실이 사내 문서 어디에도 없었다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| IP 허용 목록 벤더 대장 | 대장 관리 | 작음 | 신규 벤더 누락 | 기본 |
| 예비 IP 사전 등록 | 벤더 허용 | 작음 | 예비 IP 관리 | 기본 |
| 고정 IP 이전 필수화 | 클라우드 지원 | 작음 | 재할당 실패 시 롤백 필요 | 기본 |

**결론**: 네트워크 변경은 외부 상대의 허용 목록까지 범위로 본다.

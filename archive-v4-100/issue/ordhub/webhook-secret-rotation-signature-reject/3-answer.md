# issue/ordhub/webhook-secret-rotation-signature-reject — 정답

태그: `credential` · `partial-failure` · `integration`

## 정답
<!-- 질문 1:1 대응 -->

1. **서명 검증 실패와 401 응답이 남았다.**\
실패는 14:00 ~ 14:40에 몰려 있었다.

2. **마켓 쪽 새 비밀은 발송 서버들에 순차 전파돼 최대 40분 동안 옛 비밀 서명이 섞여 나왔다.**\
허브는 옛 비밀을 즉시 지웠다.

3. **옛 비밀이 남은 발송 서버를 탄 웹훅만 실패했다.**

4. **재시도가 같은 발송 서버에서 나가 계속 옛 비밀로 서명된 건이 있었다.**\
6회를 다 쓰기 전에 전파가 끝난 건은 복구됐고, 그렇지 않은 214건은 포기됐다.

5. **허브 수신 로그의 실패 응답과 시간대를 본다.**\
401이 한 시간대에 몰리면 인증·서명 문제다. 수신 기록 자체가 없으면 마켓 발송·네트워크 쪽을 본다.

## 문제 구조 (추상화 코드)

### 변형 A — 비밀 교체 시 옛 값 즉시 폐기
① 문제 코드
```java
boolean ok = hmacValid(body, sig, secrets.current());
```
② 고친 코드
```java
boolean ok = hmacValid(body, sig, secrets.current())
          || (secrets.previousValidUntil().isAfter(now()) && hmacValid(body, sig, secrets.previous()));
```
무엇이 깨졌나: 상대 쪽 전파가 즉시라고 가정했다 — 비밀 교체는 양쪽이 동시에 바뀌지 않는다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 교체 기간 두 비밀 허용 | 비밀 2개 저장 | 작음 | 옛 비밀 폐기 잊음 | 기본 |
| 마켓 주문 목록 시간대별 대사 | 마켓 조회 API | 중간 | 조회 호출 한도 | 기본(안전망) |
| 새벽 교체 | 주문 적은 시간 | 작음 | 누락은 그대로, 규모만 작음 | 선택하지 않은 방법 |

**결론**: 서명 비밀 교체는 겹침 기간을 두고, 수신은 상대 원장과 대사한다.

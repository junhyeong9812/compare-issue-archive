# issue/secbox/lease-max-ttl-renew — 정답

태그: `lifecycle` · `silent-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **자격증명이 만료되고 DB 계정이 삭제돼 인증이 실패한다.**

2. **`renew` 응답의 TTL이 점점 줄어드는 것을 보지 않았다.** 29일째엔 남은 시간이 몇 시간뿐이었다.

3. **자주 배포돼 30일이 되기 전에 새 자격증명을 받았다.** 정산 서비스는 월 1회 배포였다.

4. **정산 서비스가 새벽 정기 점검 뒤 재기동되는 일이 많았다.** 2025년 상반기 다섯 번.

5. **`renew` 응답의 남은 TTL이 lease 기간의 1/3 미만이면 새로 발급받아 풀을 교체한다.** secbox 에이전트 사이드카의 자동 재발급 기능을 켰다.

## 문제 구조 (추상화 코드)

### 변형 A — renew 성공만 확인
① 문제 코드
```java
Lease l = secbox.renew(lease.id());     // "renewed"
// 남은 TTL 무시
```
② 고친 코드
```java
Lease l = secbox.renew(lease.id());
if (l.ttl().compareTo(Duration.ofHours(8)) < 0) {
    Credentials c = secbox.issue("db/settle");     // 새 자격증명
    pool.rotate(c);                                 // 풀 교체
}
```
무엇이 깨졌나: '갱신 성공'을 '수명 연장'과 같다고 봤다 — 상한이 있는 연장이었다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 남은 TTL 기반 재발급 | 클라이언트 수정 | 작음 | 풀 교체 중 오류 | 기본 |
| 에이전트 사이드카 자동 재발급 | 사이드카 배포 | 중간 | 사이드카 장애 | 함께 |
| 최대 수명 상향 | 정책 변경 | 작음 | 보안 약화 | 선택하지 않은 방법 |

**결론**: 갱신 응답의 남은 수명을 보고 재발급한다.

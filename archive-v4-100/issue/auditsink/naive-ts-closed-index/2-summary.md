# issue/auditsink/naive-ts-closed-index — 정리 (힌트)

태그: `silent-failure` · `timezone` · `environment-drift`

## 전체 흐름

```
관리자 콘솔 (2025-04-29 베이스 이미지 교체 → JVM 기본 TZ = UTC)
  로거 형식 yyyy-MM-dd'T'HH:mm:ss (오프셋 없음)
  실제 KST 05-02 07:30 → "2025-05-01T22:30:00"
        │
auditsink: 오프셋 없음 → KST 로 해석 → 05-01 22:30 → 인덱스 audit-0501
  일별 인덱스 봉인 = 다음 날 06:00 KST (읽기 전용)
        │ audit-0501 은 05-02 06:00 에 봉인됨 → 쓰기 거부 (debug 로그만)

KST 00:00~05:59 → 전날 인덱스(아직 열림)에 저장, 날짜는 틀림
KST 06:00~08:59 → 전날 인덱스(봉인) → 거부 → 누락
KST 09:00~     → 같은 날 인덱스, 9시간 이른 시각으로 저장
```

## 핵심 문장

- 베이스 이미지 교체로 콘솔 JVM 타임존이 UTC가 됐고, 로거는 **오프셋 없는 시각**을 보냈다.
- auditsink는 오프셋 없는 시각을 **KST로 해석**한다 — 실제보다 9시간 이른 시각이 된다.
- 일별 인덱스는 다음 날 06:00에 봉인된다 — **KST 06~09시 이벤트만** 봉인된 전날 인덱스로 가서 거부됐다.
- 나머지 시간대도 저장은 됐지만 시각이 9시간 틀렸다 — 누락보다 넓은 피해다.
- 고칠 곳은 **보내는 쪽 형식**(오프셋 포함 ISO-8601)이고, 수집기는 오프셋 없는 시각을 거부한다.

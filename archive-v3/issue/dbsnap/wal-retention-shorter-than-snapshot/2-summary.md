# issue/dbsnap/wal-retention-shorter-than-snapshot — 정리 (힌트)

태그: `silent-failure` · `contract-drift`

## 전체 흐름

```
         일      월      화      수      목      금      토      일
스냅샷   S1 ─────────────────────────────────────────────────── S2
WAL 보존(3일, 매일 오래된 것 삭제)
목요일 시점에 남은 WAL:                [화 ── 수 ── 목]
                     빠진 구간:  [일 ── 월]

목 14:00 복구 = S1 복원 + 일~목 WAL 재생 필요
              → 일~월 WAL 없음 → 재생 중단 → 복구 불가

조건: WAL 보존 ≥ 스냅샷 주기 + 스냅샷 소요 시간 + 여유
감시: 매일 "가장 오래된 WAL 시각 ≤ 최근 스냅샷 시작 시각" 확인 + 정기 자동 복구 리허설
```

## 핵심 문장

- 시점 복구는 **스냅샷 + 그 이후 WAL 전부**가 있어야 한다 — WAL이 하나라도 빠지면 그 뒤 시점은 복구할 수 없다.
- 스냅샷 주기(7일)보다 WAL 보존(3일)이 짧으면 **스냅샷 직후 구간 WAL이 먼저 지워져** 주 중반 시점 복구가 불가능하다.
- 스냅샷 작업·WAL 아카이브 작업은 각각 성공했다 — **둘의 관계**는 아무도 검사하지 않았다.
- 보존 기간은 "주기 + 소요 시간 + 여유"로 정하고, 주기를 바꿀 때 함께 바꾼다.
- 복구 가능성은 **실제 복구**(자동 리허설)로만 확인된다.

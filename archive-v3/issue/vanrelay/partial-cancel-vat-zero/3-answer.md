# issue/vanrelay/partial-cancel-vat-zero — 정답

태그: `contract-drift` · `silent-failure`

## 정답
<!-- 질문 1:1 대응 -->

1. **0원으로 잡힌다.** `vanrelay`는 부분취소 전문의 부가세 필드를 요청에서 받은 값 그대로 채우고, 값이 없으면 0으로 채운다.\
응답은 `OK <취소승인번호>`이고 exit 0이다 — 부가세가 0인지 알려 주지 않는다.\
`vanrelay show C55102`를 보면 `vat=0`이 보인다.
   > **부가세 안분** — 부분취소 금액에 대응하는 부가세를 원거래의 공급가:부가세 비율로 나누는 것. 이 VAN 중계는 하지 않는다.

2. **환불 금액(총액)은 정확했기 때문이다.**\
고객 환불·매출 합계는 총액만 보므로 맞았다. 부가세 신고 자료는 사내 주문 시스템이 비율대로 계산한 취소 부가세(1,000원)를 썼고, 카드사 매입은 0원이었다.\
분기 신고 전 세무 대사에서 부분취소 건 수 × 평균 부가세만큼 차이가 나서 발견됐다.

3. **생기지 않는다.** 전액취소는 `vanrelay`가 원거래 전문의 부가세를 그대로 복사한다.\
부분취소가 거의 없는 온라인 가맹점에서는 증상이 없었고, 부분취소가 잦은 오프라인 가맹점(묶음 상품 반품)에서만 쌓였다.

4. **각 부분취소는 내림으로 계산하고, 원거래가 완전히 취소되는 마지막 취소는 "원거래 부가세 − 이미 취소된 부가세"로 보낸다.**\
예: 33,000(3,000)에서 11,000 → 1,000, 다시 11,000 → 1,000, 마지막 11,000 → 3,000 − 2,000 = 1,000.\
비율이 나눠떨어지지 않을 때도 합계가 원거래 부가세와 정확히 같아진다.

5. **세금 성격의 차이를 놓친다.** 총액이 맞으면 금액 대사는 "일치"로 끝난다.\
이번 사건은 처음엔 "환불 금액 대사 차이"로 올라왔지만, 실제 차이는 공급가·부가세 분할에만 있었다 — 대사 항목에 부가세를 추가하고서야 위치가 보였다.

6. **① 건 수와 승인번호 매핑을 먼저 본다.** 환불 요청 건 수와 VAN 취소 승인 건 수가 같고 1:1로 이어지면 병합·누락형이 아니다.\
**② 그다음 건별 총액, ③ 건별 부가세 순으로 본다.** 이 사건은 ①·② 일치, ③에서만 차이가 났다.

## 문제 구조 (추상화 코드)

### 변형 A — 부분취소에 부가세를 보내지 않음
① 문제 코드
```java
VanResult r = van.cancel(orig.approvalNo(), refundAmount);   // vat 생략 → VAN 이 0 으로 전송
refund.complete(r.cancelNo());
```
② 고친 코드
```java
long vat = isFinalCancel(orig, refundAmount)
        ? orig.vat() - orig.cancelledVat()                      // 잔여 몰아주기
        : Math.floorDiv(orig.vat() * refundAmount, orig.amount()); // 비율 안분, 내림
VanResult r = van.cancel(orig.approvalNo(), refundAmount, vat);
orig.addCancelled(refundAmount, vat);
refund.complete(r.cancelNo());
```
무엇이 깨졌나: 호출부가 VAN이 부가세를 나눠 준다고 가정했다 — 실제로는 받은 값(없으면 0)을 그대로 보낸다.

### 변형 B — 금액 총액만 대사
① 문제 코드
```python
assert sum(r.amount for r in our_refunds) == sum(c.amount for c in card_cancels)
```
② 고친 코드
```python
for ours, theirs in join_by_cancel_no(our_refunds, card_cancels):
    check(ours.amount == theirs.amount and ours.vat == theirs.vat, ours.id)
```
무엇이 깨졌나: 대사가 총액만 봐서 세목 차이를 숨겼다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 호출부에서 안분 + 잔여 몰아주기 | 원거래 누적 취소 부가세 저장 | 컬럼·로직 | 동시 부분취소 시 누적 경합 | 기본 |
| 부분취소를 전액취소 후 재승인으로 처리 | 고객 카드 재승인 가능 | 큼(승인 실패 위험) | 재승인 거절 시 고객 손해 | 선택하지 않은 방법 |

**결론**: 부가세는 호출부가 책임지고 보낸다. 누적 취소 갱신은 원거래 단위로 직렬화한다.

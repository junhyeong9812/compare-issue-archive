# issue/fxq/tilde-quote-requery — 정리 (힌트)

> ⚠️ Claude 초안 — 사건 기록 대조 전.

## 전체 흐름

```
fxq rate PAIR DATE                         (exit 0, stderr 없음 — 어떤 날이든 "값"이 나온다)

  벤더 영업일   →  PAIR DATE RATE                 그날 값 (정산 가능)
  벤더 휴장일   →  PAIR DATE RATE ~N              N일 전(직전 벤더 영업일)의 값을 그대로 이월 — 정산·평가 금지
                     │
                     └→ fxq rate PAIR DATE --fix  →  PAIR DATE RATE'   (꼬리표 없음, 그 날짜의 정산 기준값)

  휴장일 = 토·일 + 벤더 휴장 목록(공휴일·대체공휴일·연말 휴장 등)   ← 요일 계산으로 재현 불가
  --fix on 영업일 = 일반 조회와 같은 값   /   --fix on 휴장일 = 벤더가 따로 산출한 값 (앞뒤 평균·직전값 아님)

사고 경로
  평가 배치 ─ fxq rate ─ "PAIR DATE RATE ~3" ─ 파서: 앞 3칸만 ─ RATE(=8/14 값) ─ 평가손익 ─ 원장과 차이
                                                    ↑ 꼬리표 소실 지점
```

## 핵심 문장

- `~N`은 오류가 아니라 **"이 값은 N일 전 값의 이월"** 표식이다 — exit 0이라 호출부는 모른다.
- 정산·평가·대사처럼 **그 날짜의 기준값**이 필요한 경로는 `~N`을 보면 같은 날짜를 `--fix`로 재조회한다(또는 처음부터 `--fix`로 조회 — 영업일엔 값이 같다).
- 휴장일 판정은 벤더 달력이다 — 요일·공휴일 표를 직접 만들어 흉내 내지 말고 **꼬리표로 판정**한다.
- `--fix` 값은 벤더 산출값이다 — 직접 계산(평균·직전값)으로 대신할 수 없다.
- 표시(시세판)는 공시값 그대로가 맞다 — `--fix`를 전역으로 붙이면 표시가 바뀐다. 고칠 곳은 **정산용 환율을 고르는 공유 지점** 하나다.
- 응답 파서는 모르는 칸을 버리지 말고 보존해 판정에 쓴다.

# issue/fxq/tilde-quote-requery — 정답

## 정답
<!-- 질문 1:1 대응 -->

1. **세 날 모두 8/14 값이 이월된다.**\
`USDKRW 2026-08-15 1374.31 ~1`, `USDKRW 2026-08-16 1374.31 ~2`, `USDKRW 2026-08-17 1374.31 ~3`.\
`~N`의 N은 "직전 벤더 영업일로부터 며칠 떨어졌나"다 — 8/17은 8/14(금)에서 3일 뒤라 `~3`.\
exit 0이고 stderr도 비어 있다. `--help`(`usage: fxq rate <PAIR> <YYYY-MM-DD> [--fix]`)에는 꼬리표 설명이 없다.
   > **이월 값(`~N`)** — 벤더가 그날 값을 내지 않는 휴장일에 직전 영업일 값을 그대로 돌려주는 것. 그 날짜의 기준값이 아니다.

2. **이월 값을 그날 값으로 썼기 때문이다.**\
평가 배치는 응답 줄에서 통화쌍·날짜·환율 3칸만 읽고 4번째 칸(`~N`)을 버렸다.\
8/15~8/17은 모두 8/14 환율 1374.31로 평가됐지만, 회계 원장은 벤더 정산 기준값(`--fix`: 1383.17 / 1383.16 / 1383.49)으로 평가했다.\
8/14·8/18은 벤더 영업일이라 일반 조회 값과 `--fix` 값이 같아서 맞았다.

3. **벤더 달력이다 — 토·일만이 아니다.**\
토·일 외에 벤더 휴장 목록(공휴일, 대체공휴일, 연말 휴장 등)이 있다. 2026-08-17(월)은 광복절(토)의 대체공휴일이라 휴장이다.\
1차 수정은 `DayOfWeek`가 토·일일 때만 `--fix`를 붙여서 8/17(월)은 여전히 이월 값(`~3`)으로 평가됐다.\
요일·공휴일 표를 사내에서 따로 관리하면 벤더 달력과 언젠가 어긋난다. 판정 근거는 **응답의 꼬리표**다.

4. **영업일엔 같은 값, 휴장일엔 꼬리표 없는 별도 값이 나온다.**\
`fxq rate USDKRW 2026-08-14 --fix` → `USDKRW 2026-08-14 1374.31`(일반 조회와 같음).\
`fxq rate USDKRW 2026-08-17 --fix` → `USDKRW 2026-08-17 1383.49`(꼬리표 없음).\
이 값은 직전 값(1374.31)도, 앞뒤 영업일(1374.31·1392.41) 평균 1383.36도 아니다. 날짜마다 벤더가 산출한 값이라 사내 계산으로 재현되지 않는다.\
그래서 "꼬리표 → 같은 날짜로 `--fix` 재조회"가 유일한 정답 경로다. 정산 전용 경로라면 처음부터 항상 `--fix`로 조회해도 된다(영업일 값이 같으므로).
   > **`--fix`** — 그 날짜의 정산·평가 기준값을 돌려주는 옵션. 휴장일에도 꼬리표 없이 값이 나온다.

5. **표시에는 붙이지 않는다.**\
시세 표시는 "지금 공시 중인 값"을 보여 주는 화면이라 이월 값이 맞는 동작이다(휴장일엔 직전 공시값이 계속 걸려 있다).\
사건 때 공용 fxq 클라이언트 래퍼에 `--fix`를 전역으로 넣자 연휴 동안 앱 시세 화면 값이 바뀌어 고객 문의가 들어왔고, 되돌렸다.\
고칠 곳은 **평가·정산용 환율을 고르는 공유 함수** 한 곳이다. 표시 경로와 캐시를 나눠 둔다.

6. **모르는 칸을 버리는 파서는 벤더의 신호를 지운다.**\
`split` 후 앞 3칸만 쓰는 파서는 꼬리표가 붙어도 똑같은 객체를 만든다 — 이후 모든 층은 이월 여부를 알 길이 없다.\
교정: 파서가 4번째 칸을 읽어 "이월" 플래그를 도메인 객체에 싣고, 정산용 환율 함수가 그 플래그로 `--fix` 재조회를 결정한다.\
예상 밖 칸이 오면 버리지 말고 실패시키거나 기록하는 편이 안전하다.

## 문제 구조 (추상화 코드)

### 변형 A — 꼬리표를 버리고 이월 값으로 평가 (외화지갑 일일 평가)
① 문제 코드
```java
String line = vendor.run("rate", pair, date);          // "USDKRW 2026-08-17 1374.31 ~3"
String[] t = line.split("\\s+");
Quote q = new Quote(t[0], LocalDate.parse(t[1]), new BigDecimal(t[2]));   // t[3] 버림
valuation.add(position.multiply(q.rate()));            // 8/14 값으로 평가
```
② 고친 코드
```java
Quote q = parse(vendor.run("rate", pair, date));        // parse가 t[3] "~N"을 lagged=true로 보존
BigDecimal rate = q.lagged()
        ? parse(vendor.run("rate", pair, date, "--fix")).rate()   // 같은 날짜 재조회
        : q.rate();
valuation.add(position.multiply(rate));
```
무엇이 깨졌나: 벤더가 "이월 값"이라고 표시한 칸을 파서가 지워 휴장일 평가가 직전 영업일 값으로 됐다.\
검증 기록: 2026-08 사건 기록 대조·추상화.

### 변형 B — 휴장일을 요일로 재구현 (1차 수정의 재발)
① 문제 코드
```java
boolean closed = date.getDayOfWeek() == SATURDAY || date.getDayOfWeek() == SUNDAY;
String line = closed ? vendor.run("rate", pair, date, "--fix") : vendor.run("rate", pair, date);
```
② 고친 코드
```java
Quote q = parse(vendor.run("rate", pair, date));
if (q.lagged()) q = parse(vendor.run("rate", pair, date, "--fix"));   // 벤더 꼬리표로 판정
```
무엇이 깨졌나: 대체공휴일(월요일) 같은 벤더 휴장일을 요일 계산이 놓쳤다.\
검증 기록: 2026-08 사건 기록 대조·추상화.

### 변형 C — `--fix`를 전역으로 (표시 경로 회귀)
① 문제 코드
```java
// 공용 클라이언트
String rate(String pair, LocalDate d) { return run("rate", pair, d, "--fix"); }   // 표시도 바뀜
```
② 고친 코드
```java
String rate(String pair, LocalDate d)   { return run("rate", pair, d); }          // 표시: 공시값
String fixing(String pair, LocalDate d) { return run("rate", pair, d, "--fix"); } // 평가·정산 전용
```
무엇이 깨졌나: 평가용 규칙을 공용 경로에 넣어 고객 시세 화면이 바뀌었다.\
검증 기록: 2026-08 사건 기록 대조·추상화.

## 참고 — 벤더 오류 코드 (탐침으로 확인)

| 입력 | 결과 |
|---|---|
| 인자 부족·모르는 하위 명령 | `E11`, exit 2 |
| 날짜 형식 오류(`2026-8-17`) | `E12`, exit 2 |
| 지원 범위 밖 날짜(2031년 등) | `E13`, exit 2 |
| 모르는 통화쌍(소문자 포함) | `E14`, exit 2 |

꼬리표 줄은 오류 코드가 아니다 — exit 0이다.

## 방안 비교

| 방안 | 전제 | 비용 | 실패 모드 | 맞는 조건 |
|---|---|---|---|---|
| 꼬리표 보고 `--fix` 재조회 | 파서가 4번째 칸 보존 | 휴장일만 호출 1회 추가 | 파서가 꼬리표를 버리면 그대로 재발 | 표시·정산이 같은 조회를 공유할 때 |
| 정산 경로는 항상 `--fix` | 정산 전용 호출 경로가 분리돼 있음 | 영업일에도 정산용 호출이 별도로 나감 | 표시 경로에 섞이면 화면 회귀(변형 C) | 정산 경로가 독립적일 때 |
| 사내 달력으로 휴장일 판정 | 사내 달력 = 벤더 달력 | 달력 유지보수 | 대체공휴일·임시 휴장에서 어긋남(변형 B) | 선택하지 않은 방법 |

결론: 판정 근거는 벤더 응답(꼬리표)이고, 값은 벤더(`--fix`)에서 받는다. 두 앞 방안은 같은 결과를 내며, 공유 지점 구조에 맞춰 고른다.

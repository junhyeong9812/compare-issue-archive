# issue/cronhub/misfire-catchup-duplicate-run — 정리 (힌트)

태그: `race-condition` · `contract-drift`

## 전체 흐름

```
01:10 ─────── cronhub 중단 ─────── 04:20 재기동
       02:00  03:00  04:00 놓침
                                   │ misfire 정책 기본 = fire_all
                                   ▼
                     04:20:01 실행 (예정 02:00)
                     04:20:02 실행 (예정 03:00)    ← 세 번 연속, 거의 동시
                     04:20:03 실행 (예정 04:00)

작업 코드: target = today()  (실행 시각 기준)  → 세 실행 모두 같은 대상 → 같은 메일 3통
지급 파일: 은행 쪽이 같은 파일 일련번호 거절  → 우연히 막힘 (사내 방어 아님)

교정: 정책 = fire_once (리포트) / skip (시각 의존 작업)
      작업 = 예정 시각(scheduled_at) 을 파라미터로 받아 대상 결정 + 멱등 키로 중복 차단
```

## 핵심 문장

- `cronhub`의 기본 misfire 정책은 **`fire_all`** — 중단 동안 놓친 실행을 재기동 직후 **전부 연달아** 돌린다.
- 작업이 **실행 시각(now)**으로 대상을 정하면 몰아 실행된 회차가 모두 같은 일을 한다 — 중복 발송.
- 작업은 **예정 시각(scheduled_at)**을 받아 대상을 정하고, 결과물에 **멱등 키**(작업명+대상 기간)를 둔다.
- 하류(은행)의 중복 거절에 기대지 않는다 — 우연한 방어다.
- 정책 선택: 매 회차가 의미 있으면 `fire_all`, 최신 1회면 충분하면 `fire_once`, 시각이 지나면 의미 없는 작업은 `skip`.

# 당직 런북 — payout

## 매일 07:30 확인
1. 스케줄러 알림: `bin/payout run` exit 0이 아니면 `$WORK_DIR/<날짜>`와 로그를 본다. exit 3 = 일부 파일 전송 실패.
2. 전송 실패가 있었으면 원인(스풀·인증서 등)을 정리한 뒤 같은 날짜로 `bin/payout run <날짜>`를 다시 돌린다. 같은 이름은 덮어쓰므로 중복 걱정은 없다.
3. `bin/payout receipts <파트너> <어제> <어제>`로 활성 파트너마다 한 줄씩 확인한다.

## 파트너 문의 대응
- "정산 파일이 안 왔다": receipts 줄이 `-`이면 수신함을 직접 본다(`vendor/bin/xferq ls --to <파트너>`). 2번 절차로 재전송.
- "지급이 안 됐다 / 지급 보류": receipts에서 그 날의 건수·금액이 찍혀 있으면 "파트너 측 적재 가능 상태"로 회신하고, 건수·금액을 그대로 알려 준다.
  정산팀 지급 대사도 이 두 칸을 그대로 옮겨 적는다. (INC-0412 이후 기준)
- 금액 차이 문의: 매입 추출 원본과 `bin/payout manifest <날짜>`의 행 수를 먼저 맞춰 본다.

## 연락처
- 파일 전송 서비스 벤더: 장애 접수 포털(사내 위키 "xferq 장애 접수").
- 정산팀 지급 담당: 사내 메신저 #settle-payout.

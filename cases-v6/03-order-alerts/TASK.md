# 대행사 일시 오류로 실패한 알림 문자를 다음 회차에 다시 보내 주세요

CS팀·운영팀 요청입니다. 주문 알림 서비스는 발송 회차(`POST /dispatch`)마다 쌓인 주문 이벤트(결제 완료·배송 시작·배송 완료)를 고객 문자로 보내고, 회차 리포트(`GET /reports/dispatch/:runId`)를 운영 화면에 띄웁니다.

## 상황
- 이번 달 가을 프로모션 회차에서 리포트에 "실패"가 회차마다 수십 건씩 찍혔습니다. 사유는 대부분 `E-THROTTLE`, `E-CARRIER`입니다.
- 문자 대행사에 물어보니 둘 다 대행사·통신사 쪽 **일시 오류**라 잠시 뒤 다시 보내면 대부분 나간다고 합니다.
- 그런데 지금은 실패한 알림이 그대로 끝나 버립니다. 배송 시작 문자를 못 받았다는 문의가 들어오면 CS팀이 손으로 문자를 다시 보내고 있습니다.
- 수신 번호 오류(`invalid-number`)나 스팸 차단(`E-SPAM`)은 다시 보내도 소용없으니 그대로 두셔도 됩니다.

## 요청
- 일시 오류로 실패한 알림은 다음 발송 회차에서 자동으로 다시 보내 주세요.
- 다시 보낸 알림은 그 회차 리포트에서 "발송"으로 보이면 됩니다.
- 회차 하나는 지금처럼 한 번에 발행되어야 합니다.

환경: Node 18, 사내 메시지 발행 도구 mqpub 3.4.1(`vendor/bin/mqpub`, 스풀 디렉토리는 `MQPUB_SPOOL`). 문자 대행사는 개발 환경에서 모의 게이트웨이(`smsFaults` 설정으로 실패 응답을 흉내 냄)로 대신합니다.

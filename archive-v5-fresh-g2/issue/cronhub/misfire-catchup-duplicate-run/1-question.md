# issue/cronhub/misfire-catchup-duplicate-run — 배치 스케줄러는 재기동 후 놓친 실행을 전부 몰아서 돌린다 — 질문

## 질문
1. (예측) 배치 스케줄러 `cronhub`가 01:10~04:20 동안 내려가 있었다. 매시 정각에 도는 "가맹점 일일 리포트 메일" 작업은 재기동 직후 몇 번 실행되는가? 각 실행이 보는 "현재 시각"은 무엇인가?
2. (왜) 가맹점들이 같은 리포트 메일을 세 통씩 받았다. 리포트 내용은 세 통 모두 같았다. 왜 같은 내용이었나?
3. (경계) 같은 시간에 "가맹점 지급 지시 파일 생성" 작업도 몰아서 돌았지만 실제 이중 지급은 없었다. 무엇이 막아 줬고, 그 방어에 기대도 되는가?
4. (경계) misfire 정책 `fire_all`(기본), `fire_once`, `skip`은 각각 언제 맞는가?
5. (왜) 작업 코드가 "지금 시각"으로 처리 대상 날짜를 정하면 몰아 실행·재실행에서 무엇이 깨지는가?
6. (연결) 스케줄러가 무엇을 하든 작업이 안전하려면 작업 쪽에 무엇이 있어야 하는가?

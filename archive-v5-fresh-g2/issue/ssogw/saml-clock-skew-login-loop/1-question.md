# issue/ssogw/saml-clock-skew-login-loop — 사내 SSO 노드 하나의 시계가 밀려 로그인이 간헐적으로 되돌아왔다 — 질문

## 질문
1. (예측) 사내 SSO 게이트웨이 `ssogw` 노드 4대 중 1대의 시계가 IdP보다 95초 늦다. IdP가 발급한 SAML 어서션의 `NotBefore`는 발급 시각, 허용 오차는 60초다. 이 노드로 들어간 로그인은 어떻게 되는가?
2. (왜) 직원들은 "로그인하면 다시 로그인 화면으로 돌아온다, 몇 번 하면 된다"고 했다. 왜 "몇 번 하면 된다"인가?
3. (경계) 시계가 IdP보다 빠른 경우와 느린 경우, 각각 어느 조건(`NotBefore`·`NotOnOrAfter`)에 먼저 걸리는가?
4. (왜) 노드의 시간 동기화 데몬은 "active"였다. 그런데 왜 시계가 밀렸나?
5. (경계) 허용 오차를 300초로 늘리는 것은 왜 근본 대처가 아닌가?
6. (연결) 간헐적인 인증 실패에서 "특정 노드" 원인을 빨리 가려내려면 무엇을 로그에 남겨야 하는가?

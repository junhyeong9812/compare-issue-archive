# issue/bizmsg/ad-template-night-hold — 정리 (힌트)

태그: `contract-drift` · `silent-failure`

## 전체 흐름

```
사내 예약 큐 ──21:00──▶ bizmsg send --tpl T
                          │
          템플릿 분류 = INFO │ 즉시 전송 ─────────────▶ 고객 21:00 수신
          템플릿 분류 = AD   │ 접수 시각 20:50~08:00 ?
                          │   ├ 예 → st HOLD → 08:00 일괄 전송 ─▶ 고객 08:0x 수신
                          │   └ 아니오 → 즉시 전송
                          │
                          └ 응답: "accepted M..." exit 0  (분류·보류 언급 없음)

분류 근거: 템플릿 심사 결과의 category 값 (이름·문구가 아니라 심사 시 선택·판정)
법적 야간 제한 21:00~08:00 + 벤더 여유 10분 → 20:50 부터 보류
```

## 핵심 문장

- `bizmsg`는 템플릿 분류가 **AD(광고형)**이면 **20:50~08:00** 접수분을 오류 없이 `HOLD`로 두었다가 08:00에 보낸다.
- 분류는 템플릿 이름·문구가 아니라 **템플릿 심사 결과의 category**다 — `bizmsg tpl show <코드>`로 확인한다.
- 법적 야간 광고 제한(21~08시)보다 **10분 앞서** 보류가 시작된다.
- 보류를 피하려고 광고성 내용을 정보형 템플릿으로 보내면 안 된다 — 내용이 정보성일 때만 재심사로 분류를 바꾼다.
- 예약 큐 지연과 가르려면 `status`의 접수 시각(accepted_at)과 상태를 본다 — 접수가 제때고 HOLD면 이 사건이다.

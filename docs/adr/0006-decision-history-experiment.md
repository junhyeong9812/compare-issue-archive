# ADR-0006 — 5차-b 실험: 의사결정 히스토리

- 상태: 제안 (2026-10-09) — 미정 항목은 아래 "열린 결정"
- 선행: ADR-0002(일반 CS 카드는 손해), ADR-0003(모르는 지식 카드는 ÷B 0.42~0.64), ADR-0004(낡은 카드는 손해)

## 맥락

1~4차가 가른 기준은 "모델이 이미 아는 지식이냐"였다. 지금까지 잰 것은 **고장 원인 찾기**(버그 수정)뿐이다.

검증되지 않은 가설: **도메인 규칙과 의사결정 히스토리("왜 이렇게 정했나")가 기록으로서 더 가치 있다.** 이런 지식은 학습 데이터에 있을 수 없다. 코드에는 결과만 남고 이유는 남지 않는다. 그래서 이유를 모르는 에이전트는 합리적으로 보이지만 과거 결정을 깨는 변경을 한다.

## 결정 (초안)

### D1. 과제 형태 — 기능 변경 요청

- 케이스는 버그가 아니라 운영·기획의 **변경 요청**이다.
  - 예: "부분 환불을 즉시 처리되게 해 주세요"
  - 예: "회원번호 검증을 완화해 주세요"
- 코드에는 그 요청과 충돌하는 과거 결정의 결과가 남아 있다. 예: 환불을 D+1 배치로 미룬 구조. 이유는 코드에 직접 적혀 있지 않다.
- 정답은 결정을 지키며 요청을 만족시키는 구현이다. 결정과 요청이 충돌하면, 결정이 허용하는 범위 안에서 구현하고 충돌을 보고한다.
- 결정의 이유는 일반 원리로 유도되지 않는 회사 고유 사정이다. 예: PG 대사 주기, 과거 사고, 계약 조건, 감사 지적.

### D2. 발견 가능성 — 흩어진 단서

3차 D3 원칙을 승계한다. B가 원리적으로 못 풀면 토큰 비교가 아니라 정답률 비교만 남는다.

- 단서를 실제 저장소처럼 흩어 둔다. B도 찾을 수 있지만 비싸게 만든다.
  - 후보: 케이스 안 git 이력(커밋 메시지), 코드 주석 조각, 테스트 이름, 운영 스크립트, CHANGELOG
- 케이스 작성자는 단서만으로 결정을 복원하는 경로를 기록한다(명령 10개 이내 수준).

### D3. 검증

- 보이는 test.sh: 요청 기능만 검사한다. 순진한 구현도 통과한다.
- hidden: 과거 결정이 지키려던 불변식을 검사한다. 순진한 구현은 실패한다.
- 주 지표는 **성공률**(결정 위반율), 보조 지표는 총 토큰 ÷B다.

### D4. 지식 원천 — 결정 아카이브

- `archive-v6/decision/`: 가상 회사의 결정 기록. 형식은 ADR류(맥락·결정·결과)이고, 관련 10장 + 미끼다.
- 인덱스는 경량 한 줄이다. 3차와 같이 결정 내용은 넣지 않고 주제만 적는다.
- L용 요약은 결정 결론 2~3줄이다.

### D5. arm

| arm | 입력 |
|---|---|
| B | 없음(단서는 케이스 안에만) |
| L | 결정 요약 2~3줄 |
| P | 정답 결정 기록 경로 |
| F | 결정 아카이브 먼저 검색 |

### D6. 파일럿 게이트

- 3케이스 × B·L × 1회(Sonnet)로 먼저 돌린다.
- 통과 기준(둘 중 하나):
  - L 성공 + B 실패
  - L 성공 + B 총 토큰 ≥ L × 1.5
- 미달하면 재설계 1회, 그래도 미달이면 사용자가 결정한다.

## 예측과 판정

- 가설이 맞으면: B 성공률이 낮고(결정 위반), L·P·F는 성공률과 토큰 모두 우세하다.
- B가 단서로 싸게 복원하면: 의사결정 기록의 가치는 정답률보다 탐색 비용 쪽이다(3차와 같은 구조).
- 기록이 있어도 위반하면(L 실패): 문제는 기록 형식이 아니라 요청 대 결정의 우선순위 판단이다.

## 열린 결정 (L1 착수 인터뷰에서 확정)

- 결정 유형 구성: 외부 계약·대사 / 과거 사고 재발 방지 / 감사·규제 / 성능·비용 트레이드오프의 비율
- 단서 위치: git 이력 포함 여부(러너 복사·감사 영향 확인 필요)
- 요청과 결정이 충돌할 때의 정답 정의: 결정 우선 + 보고 / 결정 허용 범위 안의 대안 구현
- 언어 구성(3차: Java·Python·TS·Shell), 케이스 수, 미끼 수
- 모델·반복: 3차와 같은 Sonnet·Haiku × 3회 = 240회

## 대안 (기각)

- 실제 회사·사용자 프로젝트의 결정 기록: 일반 원리로 유도되는 결정이 섞여 변수가 오염된다(ADR-0003 대안과 같은 이유).
- 단서 없이 기록에만 있는 결정: B가 원리적으로 못 푼다. 정답률 비교만 남는다(D2).

# ADR-0002: 2차 실험 설계 — 아카이브가 필요한 조건에서 재측정

- 상태: **제안** (사용자 합의 대기)
- 선행: ADR-0001 (1차 원인 1~7)

## 맥락

1차는 측정 조건이 아카이브가 필요한 상황을 만들지 못해 A≈B가 나왔다. 2차는 원인을 하나씩 제거해서 **"카드 내용이 주는 가치"**와 **"카드를 찾는 비용"**을 분리해 잰다.

## 결정

### D1. arm을 셋으로 — 원인 1·7 대응

| arm | 주는 것 | 재는 것 |
|---|---|---|
| **B** | 증상만 | 기준선 |
| **A** | 증상 + 아카이브 경로(스스로 찾기, 1차와 같은 문구) | 실제 운영에 가까운 효과(찾기 비용 포함) |
| **A′** | 증상 + **해당 카드 경로**(3개 파일) | 카드 내용 가치의 상한(찾기 비용 0) |

- A′−B = 카드 내용의 가치, A−A′ = 찾는 비용.
- A′가 B보다 나아지지 않으면 케이스가 여전히 쉽다는 뜻이다. 이 경우 D3 파일럿 게이트로 되돌아간다.

### D2. 케이스를 "탐색이 필요한 저장소"로 재구성 — 원인 2·4 대응

- 같은 10개 카드·같은 사건 유형을 유지한다(1차와 비교 가능).
- 각 케이스를 **작은 실제형 저장소**로 키운다: 파일 15~30개, 600~1,500줄. 계층을 나누고(API/서비스/저장소/유틸), 원인과 증상을 **다른 계층**에 둔다.
- **미끼(decoy)**: 증상과 관련 있어 보이지만 무죄인 코드 경로 2개 이상을 둔다. 비슷한 이름의 함수, 의심스러워 보이지만 맞는 코드 등.
- **재현 테스트는 끝단(E2E)에서 증상만 드러낸다.** 테스트 이름과 메시지가 원인 파일을 가리키지 않게 한다. 기존 단위 테스트 몇 개는 통과 상태로 둬서 노이즈로 쓴다.
- **덜 알려진 변형 우선 — 원인 3 대응**: 같은 카드 안에서 가장 덜 교과서적인 사건(변형)을 고른다. 예: 06은 truncate가 아니라 "같은 temp 이름 충돌·다른 파일시스템 rename" 같은 쪽이다.
- 기존 1차 케이스(`cases/`)는 보존하고 2차는 `cases-v2/`·`oracle-v2/`에 둔다.

### D3. 파일럿 난이도 게이트 — 원인 5 대응

본 실험 전에 케이스마다 **B 1회**를 돌려 다음을 요구한다.

- 도구 호출 ≥ 8 **또는** 총 토큰 ≥ 1차 중앙값의 2배(≥ 180k)
- 그래도 B가 성공해야 한다. 실패해도 허용하되, 10케이스 중 B 실패는 ≤ 3이어야 한다(전부 실패면 비교 불가).

미달 케이스는 재설계한다(최대 1회). 그래도 미달이면 해당 케이스를 제외하고 사유를 기록한다.

### D4. 지표 — 원인 6 대응

- 기존: 총 토큰·비용·턴·도구 호출·성공.
- **추가 — 변동 토큰** = 총 토큰 − (첫 호출 컨텍스트 × 턴 수). 고정비를 걷어낸 과제 고유분이다.
- **추가 — 출력 토큰**과 **첫 수정 시도까지의 턴**: 원인을 얼마나 빨리 짚었는지를 본다.
- **추가 — 카드 열람 여부**(A: 카드 파일을 연 실행 수).
- 1차 지표와 같은 정의를 유지해 1차와 나란히 비교한다.

### D5. 실행 조건 — 1차와 동일

- Sonnet, 격리 HOME `claude -p`, deny + 감사, 상한 $2, 동시 ≤ 5.
- 감사 패턴: A′도 A처럼 아카이브 경로를 허용한다.
- 규모: 10 × 3 arm × 3회 = **90회**, 파일럿 10회 별도. 1차 단가($0.08)의 2~4배로 보면 총 환산 약 $20~30이고, 구독 사용량에서 차감된다.

### D6. 판정·기록 — 1차와 동일 + 확장

- 판정은 hidden 판정 + 변조 검사로 1차와 같다.
- 결과 파일: `results-v2/`(runs.jsonl·raw·summary·analysis).
- summary에 1차 대비 표를 함께 싣는다.

## 대안과 기각 사유

- **Haiku로만 바꾸기**: 케이스가 쉬운 문제(원인 2·4)는 그대로 남고, 모델 변수만 늘어난다. 2차 결과를 본 뒤 3차 후보로 둔다.
- **A의 문구를 "반드시 아카이브를 먼저 보라"로 강제**: 운영 현실(스스로 판단)을 왜곡한다. 강제 열람의 효과는 A′가 대신 잰다.
- **완전히 새 이슈로 케이스 교체**: 1차와 비교할 수 없게 된다.

## 결과(예상되는 해석)

| 관찰 | 해석 |
|---|---|
| A′ < B | 카드 내용에 가치가 있다 |
| A ≈ A′ | 인덱스로 찾는 비용이 작다 → 아카이브가 실용적이다 |
| A ≈ B 이면서 A′ < B | 가치는 있지만 발견되지 않는다 → README 인덱스와 검색성을 개선해야 한다 |
| A′ ≈ B | 이 난이도에서도 모델 사전 지식으로 충분하다 → 3차는 덜 알려진 이슈나 약한 모델로 간다 |

## 개정 — 추가 실험(F) 반영 (2026-10-08 append)

ADR-0001 추가 실험 결과에 따라 아래와 같이 개정한다. 위 원문은 보존한다.

- **D1 개정 — arm**: **B / F(아카이브 우선) / A′(정답 카드 직접 제공)**.
  - "대안과 기각 사유"의 "강제 문구는 현실 왜곡"은 철회한다. 하네스 정책처럼 "먼저 아카이브를 본다"를 두는 것이 실제 운영 조건이다(사용자 지적).
  - 1차 A(선택 안내)는 카드를 열지 않아 B와 같아지므로 제외한다.
- **D4 추가 — 지표**:
  - 정답 카드 적중률(F)
  - 아카이브 읽기 토큰: README·카드를 읽은 tool_result 크기
- **D7 신설 — 인덱스 변수 분리**: 2차는 아카이브를 *지금 형태 그대로* 쓴다. 효과를 섞지 않기 위해서다. 인덱스 경량화(증상 키워드→카드 경로 표, grep 친화)는 2차 결과를 본 뒤 3차 변수로 둔다.
- 규모: 10 × 3 arm × 3 = 90회(변동 없음).

## 결과 — 2차 실험 (2026-10-08 append)

- 파일럿 게이트(D3)는 1/10만 통과했다. B가 1,000줄 규모를 `cat` 1~2회로 소화했기 때문이다. 사용자 결정으로 미달을 기록하고 진행했다.
- 90/90 유효. 성공은 B 28 / F 28 / **P 30**. 총 토큰 중앙값은 B 127k / P 173k(×1.35) / F 238k(×1.87).
- 카드의 가치는 **낯선 문제에서 효율**(10번 P÷B 0.65), **어려운 문제에서 정답률**(05번 B 1/3 → P 3/3)로 나타났다. 아는 문제에서는 오버헤드였다.
- 아카이브 우선(F)은 인덱스 비용 때문에 1·2차 모두 B보다 비쌌고, 정답률 이득도 없었다.
- 상세: `results-v2/summary.md`, `results-v2/analysis.md`. 차기 후보는 on-stuck arm, 경량 인덱스, Haiku다.

## 0. 요구사항 원문 (인터뷰 기록)

- 원문: "ADR-0003 프로젝트 고유 케이스로 진행하자"
- Q/A:
  - 지식 원천 = 가상 프로젝트 + 블랙박스.
  - arm = B·L·P·F.
  - 규모 = 파일럿 3케이스 먼저.
  - 아카이브 = 관련 10 + 미끼 10~20.
  - 블랙박스 = 네이티브 바이너리.
  - 언어 = 혼합.
  - 카드 = 기존 3파일 + 요약.
  - 파일럿 기준 = L 성공 + (B 실패 또는 B ≥ L×1.5).
  - 자율성 = auto(이전 합의 승계).

## 1. 목표·대상 (필수)

`compare-issue-archive`에 3차 케이스(`cases-v3/`·`oracle-v3/`)와 가상 회사 아카이브(`archive-v3/issue/`)를 만든다. 파일럿 3케이스로 게이트를 통과하면, 10케이스 × B·L·P·F × 3회 × Sonnet·Haiku를 실행해 `results-v3/`·`results-v3-haiku/`에 결과를 낸다.

## 2. 경계·불변식 (필수)

- 케이스 계약은 1·2차와 같다: buggy에서 test.sh·hidden.sh 실패, fix.patch + hidden 적용 후 둘 다 통과(verify 3회 결정적).
- 블랙박스는 C 소스를 strip 빌드한 바이너리만 케이스에 둔다. 규칙을 드러내는 문자열이 없다(`strings` 검사). 결정적으로 동작한다. 소스는 oracle에만 둔다.
- 블랙박스 규칙은 탐침으로 발견 가능하다(작성자가 경로 기록, ADR D3).
- arm 차이는 프롬프트 추가분뿐이다. 그 밖의 조건(격리 HOME·$2·deny+감사·판정·동시 ≤5)은 2차와 같다.
- 기존 케이스·결과(`cases*/`·`oracle/`·`oracle-v2/`·`results*/`)는 수정하지 않는다. 러너 변경은 기존 실행과 호환되어야 한다(기본값 유지).

## 3. 기준소스 (필수)

ADR-0003. 케이스 요건은 v2 브리핑(`docs/plans/2026-10-08/experiment-v2/worker-brief-v2.md`)을 승계한다.

## 4. 금지영역 (필수)

- study-note 수정 금지. 기존 케이스·결과 수정 금지.
- 원격 push·발행 없음.

## 5. 검증 방법 (필수)

- 케이스: `CASES_DIR=cases-v3 ORACLE_DIR=oracle-v3 bash scripts/verify-cases.sh` 3회 PASS, 누출 스캔(케이스에 카드 용어·원인 힌트 없음, 바이너리 `strings` 검사), 탐침 발견 경로 기록.
- 러너: `--archive-dir` 추가 후 2차 기본 경로 회귀(arm P·L 프롬프트 생성 동일).
- 파일럿 게이트(ADR D7) 판정 기록.
- 본 실험: 240행 유효(무효는 재실행·보존), 손 검산 1회, 2차 대비 표.

## 6. stakes (필수)

- 판정: **낮음** — 로컬 실험, 재실행으로 복구 가능.

## 7. 자율성

- [x] auto
- [ ] lazy

## 8. load-bearing 가정

1. 탐침으로 발견 가능하면서도 일반 원리로 추론되지 않는 블랙박스 규칙을 만들 수 있다 — 파일럿 B의 탐색 비용으로 실증한다.
2. strip 바이너리의 `strings`·디컴파일이 카드보다 싼 지름길이 되지 않는다 — 파일럿 로그에서 B의 접근 방식을 확인한다.

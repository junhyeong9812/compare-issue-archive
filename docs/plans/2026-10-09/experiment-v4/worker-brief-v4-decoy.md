# 4차 규모 실험 — 미끼 카드 워커 공통 브리핑

## 목표

3차 가상 회사 "한빛페이" 아카이브는 22장이었다(관련 10, 미끼 12). 4차는 아카이브를 **100장과 300장**으로 키워, 에이전트가 아카이브를 먼저 찾는 조건(F)의 검색 비용이 규모에 따라 얼마나 느는지 잰다.

늘어나는 278장은 모두 **미끼 카드**다. 같은 회사의 다른 벤더·사내 시스템에서 일어난 과거 사건이다. 에이전트는 인덱스 README(증상 한 줄)를 보고 카드를 고르므로, 미끼가 그럴듯해야 실제 아카이브의 검색 비용이 재현된다.

필독:
1. `docs/adr/0004-stale-cards-and-archive-scale.md` (D4)
2. `archive-v3/issue/README.md` (인덱스 형식)
3. 3차 미끼 카드 2장 (형식·문체 기준):
   - `archive-v3/issue/vanrelay/partial-cancel-vat-zero/`
   - `archive-v3/issue/filegw/relay-cert-reload-retry-expire/`
4. 3차 관련 카드 10장의 인덱스 줄(README)과 각 카드의 2-summary.md (겹치면 안 되는 규칙 확인용)

## 만들 것

- 위치: `archive-v4-300/issue/<도구>/<slug>/`. 메인이 archive-v3 22장을 미리 복사해 두었다. 기존 22장은 건드리지 않는다.
- 카드 하나 = `1-question.md`·`2-summary.md`·`3-answer.md`·`metadata.md`. 형식은 3차 미끼 카드와 같다.
- 분량: 카드 폴더당 합계 2.5~5KB. 3차 미끼(약 7.6KB)보다 짧게 써도 된다. 대신 사건·증상·원인·대처가 구체적이어야 한다.
- 담당 영역과 장 수는 개별 지시에 따른다.
- 각 카드는 서로 다른 사건이다. 같은 도구에 카드 여러 장을 두어도 되지만, 규칙은 서로 달라야 한다.

### 미끼 품질

- **절반 정도는 증상이 관련 카드 10장과 비슷하게** 쓴다. 예시 증상:
  - 접수는 정상인데 상대가 못 받음
  - 일부만 누락
  - 반영이 늦음
  - 대사 차액
- 원인은 반드시 다른 규칙이어야 한다.
- 관련 카드 10장의 규칙과 같거나 같은 계열인 원인은 금지다(같은 규칙이 다른 도구에 있어도 금지):
  - 바이트 길이 상한 보류
  - 배치 내 키 앞부분 중복 제거
  - 휴장일 이월 표식
  - 이름 `_` 개수
  - 배치 앞 N줄만 처리
  - 같은 줄 중복 환불
  - 예약 시각 경계
  - 수량 0 무시
  - set 후 mark 전 옛 값
  - 앞 0 제거
- 나머지 절반은 무관한 장애로 쓴다(인증·인프라·배포·성능 등).
- 실제 사내 아카이브처럼 쓴다: 날짜(2023~2026), 서비스명, 수치. "미끼" "실험" 같은 단어는 카드 본문에 쓰지 않는다.
- metadata는 3차 미끼 형식을 따른다(`초안 … 한빛페이 가상 아카이브 — 실험 v4`).

### 인덱스 줄 제출

카드마다 인덱스 한 줄을 `docs/plans/2026-10-09/experiment-v4/decoy-index-<워커ID>.tsv`에 쓴다. 열은 탭으로 구분한다.

```
<도구 (한글 설명)>\t<그때 겪은 증상 한 줄>\t`<도구>/<slug>/`\t<100|300>
```

- 넷째 열은 그 카드가 들어갈 가장 작은 아카이브다.
  - 100: 100장 아카이브에도 들어가는 카드
  - 300: 300장 아카이브에만 들어가는 카드
- 100 표시 장 수는 개별 지시를 따른다. 100 표시 카드도 증상 비슷한 것과 무관한 것을 섞는다.
- 증상 줄에는 규칙·대처를 쓰지 않는다. 3차 인덱스와 같은 형식이다.

## 확인

- 담당 카드 수, 각 폴더의 4파일 존재, 폴더당 바이트.
- 도구명 충돌: 담당 외 영역의 도구 이름을 쓰지 않는다. `ls archive-v4-300/issue`로 다른 워커가 이미 만든 도구명을 확인한다.
- 금지 규칙 누출: 카드 본문에 관련 카드 10장의 규칙 핵심어(예: `48`, `16바이트`, `_ 4개`, `앞 12줄`, `mark`, `@MBR`)가 원인으로 등장하지 않는지 grep한다.

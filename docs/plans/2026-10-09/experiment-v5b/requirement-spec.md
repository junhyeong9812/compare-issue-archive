## 0. 요구사항 원문 (인터뷰 기록)

- 원문: "둘 다 하나씩 adr로 처리하자" → "진행하자"(5차-a 뒤 5차-b)
- Q/A:
  - 정답 정의 = **결정 범위 안 대안 구현**. 요청 목적은 달성하되, 결정이 지키는 불변식을 깨지 않는다. hidden이 기계 채점한다.
  - 단서 위치 = **파일만**(주석 조각·테스트 이름·운영 스크립트·CHANGELOG·docs 메모). git 이력은 넣지 않는다.
  - 규모 = **10케이스 × B·L·P·F × 3회 × Sonnet·Haiku = 240회**(+ 파일럿).
  - 구성 = **4유형 균등**(외부 계약·대사 3, 과거 사고 재발 방지 3, 감사·규제 2, 성능·비용 2) + 3차 언어(Java·Python·TS·Shell 혼합), 미끼 결정 기록 12장(총 22장).
  - 코드베이스 = **3·4차 코드베이스 사본 재사용**(cases-v4 10개 서비스, 버그 고친 상태 위에 결정의 결과를 심는다).
  - 동시 실행 = **같은 케이스는 동시에 돌리지 않는다**(러너 스케줄 변경).
  - 파일럿 = **초안대로**: 3케이스 × B·L × 1회(Sonnet). 통과 = L 성공 + B 실패, 또는 L 성공 + B 총 토큰 ≥ L × 1.5. 미달이면 재설계 1회, 그래도 미달이면 사용자 결정.
  - 자율성 = auto(확인 필요).

## 1. 목표·대상 (필수)

"도메인 규칙·의사결정 히스토리 기록이 에이전트에게 가치가 있는가"를 잰다. 주 지표는 성공률(결정 위반율), 보조 지표는 총 토큰 ÷B다.

1. 러너 `scripts/run_experiment.py`:
   - `--prompt-set {bug,decision}`(기본 bug). decision이면 기본 프롬프트를 "변경 요청이 들어왔다. TASK.md를 읽고 요청을 구현하라…"로 바꾸고, L·P·F 안내 문구의 "과거 실전 이슈의 원인과 해결책"을 "과거 의사결정 기록(맥락·결정·이유)"으로 바꾼다. 완료 기준·수정 금지·요약 지시는 같다.
   - 같은 케이스의 실행이 동시에 돌지 않게 한다. 케이스별 잠금을 두고, 작업 순서를 rep → arm → case로 섞는다. arm 교대 규칙은 유지한다.
2. 데이터(워커 Opus 5명, 케이스 2개씩. 메인은 브리핑·검수):
   - `cases-v6/NN-*`: cases-v4 사본에 oracle-v4 fix.patch를 적용한 상태에서 출발한다.
     - 과거 결정의 결과를 코드에 심는다. 이유는 코드에 직접 적지 않는다.
     - 단서는 파일 2~4곳에 흩어 둔다.
     - 새 TASK.md(변경 요청)와 test.sh(요청 기능만 검사)를 둔다.
   - `oracle-v6/NN-*`:
     - `card.txt`: 결정 경로·결정·불변식·요청·순진한 구현·대안 구현·단서 위치와 복원 경로(명령 10개 이내)
     - `summary.txt`: L용 결론 2~3줄. 케이스 코드명 없음
     - `fix.patch`: 대안 구현
     - `naive.patch`: 순진한 구현
     - `hidden/`
   - `archive-v6/issue/`: 결정 기록 22장(관련 10 + 미끼 12). 형식은 기존 4파일이다(1-question = 맥락, 2-summary = 결정, 3-answer = 이유·결과·대안, metadata). README 인덱스는 주제 한 줄이고 결정 내용은 넣지 않는다.
3. 실행:
   - 파일럿 Sonnet 3케이스 × B·L × 1 → 게이트.
   - 통과하면 본 실험 240회. 결과는 `results-v5b`, `results-v5b-haiku`.
4. 분석: 성공률, ÷B(이번 B 기준), 결정 유형별 결과, 실패 형태(순진한 구현 / 그 밖), 정답 기록 열람. 산출은 analysis, ADR-0006 결과 append, 커밋.

## 2. 경계·불변식 (필수)

- 러너는 `--prompt-set` 기본값(bug)에서 3~5차와 프롬프트가 바이트 단위로 같다(stash 비교).
- 스케줄 변경은 실행 순서와 동시성만 바꾼다. 행 형식·판정·감사는 그대로다.
- 각 케이스는 다음을 만족해야 한다.
  - 순진한 구현(naive.patch)은 test.sh를 통과하고 hidden에서 실패한다.
  - 대안 구현(fix.patch)은 둘 다 통과한다.
  - 수정 전 원본은 test.sh에서 실패한다(요청 미구현).
- 결정의 이유는 일반 원리로 유도되지 않는 회사 고유 사정이다(계약 조건·과거 사고·감사 지적·비용 계약 등). 일반 모범 사례만으로 맞힐 수 있는 결정은 쓰지 않는다.
- 단서만으로 결정을 복원하는 경로가 실재한다(B도 원리적으로 풀 수 있다, ADR-0006 D2).
- 요약·인덱스에 케이스 코드명(파일·함수·변수명)을 쓰지 않는다.
- 아카이브 접근 금지·감사·$2 예산·동시 ≤5 같은 실행 조건은 3~5차와 같다.
- 기존 케이스·결과·아카이브·oracle(`cases`~`cases-v4`·`oracle*`·`archive-v3·v4*·v5*`·`results*`)은 수정하지 않는다.

## 3. 기준소스 (필수)

ADR-0006, ADR-0003(D3 발견 가능성 원칙·카드 형식), cases-v4·oracle-v4(출발 코드·fix.patch).

## 4. 금지영역 (필수)

- study-note 읽기·수정 금지(워커 포함).
- 기존 케이스·결과·아카이브 수정 금지.
- push·외부 발행 금지(사용자 확인 후만).

## 5. 검증 방법 (필수)

- 러너:
  - 기본 프롬프트 회귀(stash cmp, v3·v4·v5a 설정).
  - decision 세트 출력 확인.
  - 스케줄: 모의 run_one으로 같은 케이스 동시 실행 0 확인.
- 케이스(메인이 10개 전부 직접 실행):
  - 원본은 test.sh 실패.
  - naive.patch는 test.sh 통과·hidden 실패.
  - fix.patch는 둘 다 통과.
  - card.txt의 단서 복원 경로 명령을 실제 실행해 결정이 드러나는지 본다.
  - 요약·인덱스 누출 grep.
- 실행:
  - 파일럿 게이트.
  - 유효 행 확인. 무효는 원래 행을 보존하고 재실행.
  - 손 검산 1회. 실패는 보존 폴더·hidden stderr로 분류.

## 8. load-bearing 가정

1. 기존 코드베이스 위에 "이유가 코드에 없는 결정"을 심고, B가 단서로 복원은 하되 비싸게 만들 수 있다. 파일럿 게이트가 바로 실증하고, 미달이면 재설계한다.
2. 순진한 구현이 test.sh를 통과하고 hidden에서 실패하는 구조를 10케이스 모두 만들 수 있다. 케이스 검수에서 확인한다.

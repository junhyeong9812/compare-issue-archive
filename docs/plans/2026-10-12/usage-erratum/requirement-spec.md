## 1. 목표·대상 (필수)

- **대상:** `compare-issue-archive`, 새 브랜치 `docs/usage-erratum`(main에서 분기)
- **산출물:**
  - `docs/erratum-usage.md`: 원인, 3건, 셀·차수 단위 영향 재계산
  - README 결론 바로 아래에 정정 절(3~5줄 + 링크)
- **끝의 정의:** 정정 문서와 README 절이 main에 병합·푸시된다(푸시·병합은 확인 후).

## 2. 경계·불변식 (필수)

- 원 결과(`runs.jsonl`·`summary.md`·`analysis.md`·ADR)는 바꾸지 않는다. 정정값은 정정 문서에만 쓴다.
- 영향 재계산은 summarize와 같은 규칙(유효 행, 4필드 합, 중앙값 ÷B)으로 한다. 세 행만 실제값으로 바꾼 사본으로 다시 계산한다.
- 결론 문장(README 1~5)을 바꿔야 할 만큼 영향이 크면 문서에 명시하고 사용자에게 보고한다. 결론 문장 자체는 바꾸지 않는다.

## 3. 기준소스 (필수)

- `results-v3`·`results-v4-stale`(B 기준은 `results-v4-baseline`)·`results-v5b`의 `runs.jsonl`과 `raw/` 로그

## 4. 금지영역 (필수)

- 원 결과 파일, 케이스·oracle·archive는 수정하지 않는다.
- study-note는 읽지도 수정하지도 않는다. main에서 직접 작업하지 않는다.
- push·병합은 확인 후에만 한다.

## 5. 검증 방법 (필수)

- 3건의 집계·실제 값을 원시 로그에서 다시 계산해 표와 대조한다.
- 영향을 받은 셀의 ÷B를 정정 전·후로 계산한다. 차수 요약값(README 표 수치)도 같은 방식으로 다시 계산해 원래 값이 재현되는지 먼저 확인한다(재현 실패 시 사유 기록).

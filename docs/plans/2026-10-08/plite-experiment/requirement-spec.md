## 0. 요구사항 원문 (인터뷰 기록)

- 원문: "아카이브된 문서를 es나 별도 로컬 llm이 문제에 대해 찾아주면 그 값을 보고 찾는 방식이라면? 탐색 비용을 mcp화를 한다면" → 제안(MCP 구축 전 상한을 P-lite로 측정) → "한번 해보자"
- Q/A:
  - 요약 수준 = **카드 결론만**(채택 사건의 원인 패턴 + 고치는 원칙, 케이스 파일명·식별자·위치 없음).
  - B 기준 = **2차 B 재사용**(`results-v2`·`results-v2-haiku`의 B 30행씩).
  - 모델 = **Sonnet + Haiku**.
  - 자율성 = auto.

## 1. 목표·대상 (필수)

"검색이 완벽하고 결과를 2~3줄로 요약해 주는 MCP"의 **상한**을 MCP 없이 잰다. v2 케이스 10개에 arm **L(P-lite)** — 프롬프트에 정답 카드의 결론 요약 2~3줄을 붙인다 — 을 Sonnet·Haiku 각 3회(총 60회) 돌려 같은 모델의 2차 B·P·F와 비교한다. 판정 질문: L이 B보다 토큰이 적거나 정답률이 높은가? 그렇다면 MCP 구축 가치가 있고, 아니면 이 케이스들에서는 없다.

## 2. 경계·불변식 (필수)

- arm 차이는 프롬프트의 추가 단락뿐이다. 그 밖의 조건(격리 HOME·$2 상한·deny+감사·판정·동시 ≤5)은 2차와 같다.
- 요약은 `oracle-v2/NN/summary.txt`에 둔다. 카드 3-answer.md(채택 사건)에서 옮긴 **일반 결론**만 쓴다. 케이스 코드의 파일명·클래스·함수·변수명은 넣지 않는다(누출 스캔으로 확인). 실제 MCP가 카드에서 돌려줄 수 있는 범위를 넘지 않는다.
- L arm에는 아카이브 경로를 주지 않는다. 아카이브 접근은 B와 같이 차단·감사한다.
- 결과는 `results-v2-plite/`(Sonnet)·`results-v2-plite-haiku/`(Haiku)에 둔다. 기존 결과·케이스는 수정하지 않는다(oracle-v2에 summary.txt 추가만).

## 3. 기준소스 (필수)

ADR-0002와 2차 결과(`results-v2/`·`results-v2-haiku/`). 요약 원문은 study-note `issue/` 카드(읽기만 — 사본 `/tmp/cia-lib/issue`).

## 4. 금지영역 (필수)

- study-note 수정 금지. `cases*/`·기존 `results*/` 수정 금지.
- 원격 push·발행 없음.

## 5. 검증 방법 (필수)

- 요약 10개: 케이스 식별자 누출 스캔 0건(케이스 소스의 식별자 목록과 대조), 카드 원문 대응 문장 확인.
- 러너: arm L 프롬프트 스모크(프롬프트 출력 확인), B 감사 규칙이 L에도 적용되는지 확인.
- 실험: 60행 유효(무효는 재실행·보존), 요약 손 검산 1회, 같은 모델의 B·P·F 대비 표.

## 6. stakes (필수)

- 판정: **낮음** — 로컬 실험, 재실행으로 복구 가능.

## 8. load-bearing 가정

1. 2차 B를 재사용해도 비교가 성립한다(같은 케이스·조건, 시점 차이만 존재) — 한계로 기록.
2. 요약 2~3줄이 "이상적 MCP 결과"를 대표한다 — 카드 결론만 쓰고 케이스 힌트는 넣지 않는다.

## 0. 요구사항 원문 (인터뷰 기록)

- 원문: "1차 실패 원인분석과 1차 요구사항은 adr1로 작성 후 위 1차 실험을 adr2로 설계후 진행해보자" → (추가 실험 F 후) ADR-0002 개정(B/F/A′) 제시 → "진행하자"
- Q/A(이전 합의 승계): 격리 HOME `claude -p`·Sonnet·$2 상한·deny+로그 감사·3회 반복·실패도 기록·동시 ≤5, 자율성 auto.

## 1. 목표·대상 (필수)

`compare-issue-archive`에 **케이스 v2 10개**(`cases-v2/`·`oracle-v2/`)를 만들고, 파일럿 난이도 게이트를 통과시킨 뒤 **B / F / A′ × 3회 = 90회**를 실행해 `results-v2/`에 1차와 나란히 비교한 결과를 낸다.

## 2. 경계·불변식 (필수)

- 케이스 v2: 1차와 **같은 카드 10개**, 카드에 실제로 적힌 사건(가능하면 1차와 다른, 덜 교과서적인 변형). 케이스당 파일 15~30개·600~1,500줄. 계층을 나누고 **원인과 증상은 다른 계층**, 무죄 미끼 2개 이상, 재현 테스트는 끝단에서 증상만 드러냄(테스트 이름·메시지가 원인 파일을 가리키지 않음), 통과하는 기존 테스트를 노이즈로 둔다.
- 케이스 계약은 1차와 동일: buggy에서 test.sh·hidden.sh 실패, fix.patch + hidden 적용 후 둘 다 통과(`verify-cases.sh`로 결정적 3회). `cases-v2/`에 원인 힌트·카드 용어 없음.
- 실험 조건: arm 차이는 프롬프트의 아카이브 안내 단락뿐이다. B=없음, F=1차 추가 실험과 같은 문구, A′=정답 카드 경로 + "먼저 읽어라". 그 밖의 조건은 1차와 동일.
- 아카이브는 지금 형태 그대로 쓴다(ADR-0002 D7 — 인덱스 개선은 변수로 섞지 않는다).
- 1차 산출물(`cases/`·`oracle/`·`results/`)은 수정하지 않는다.

## 3. 기준소스 (필수)

ADR-0002(원문 + 개정). 카드는 study-note `issue/`(아카이브 사본 `/tmp/cia-lib/issue` — 1차와 같은 사본, `results/archive-source.txt`).

## 4. 금지영역 (필수)

- study-note 수정 금지. `cases/`·`oracle/`·`results/`(1차) 수정 금지.
- 원격 push·발행 없음.

## 5. 검증 방법 (필수)

- 케이스: `CASES_DIR=cases-v2 ORACLE_DIR=oracle-v2 bash scripts/verify-cases.sh` 3회 10/10 PASS, 누출 스캔 0건, 케이스별 파일 수·줄 수 표.
- **파일럿 게이트(D3)**: 케이스마다 B 1회 → 도구 호출 ≥8 또는 총 토큰 ≥180k. 미달하면 재설계 1회, 그래도 미달이면 제외하고 사유를 기록. B 실패는 10개 중 ≤3.
- 본 실험: 90행 유효(무효는 재실행·보존), 요약 손 검산 1회, 1차 대비 표.

## 6. stakes (필수)

- 판정: **낮음** — 로컬 실험, 재실행으로 복구 가능. 집계·감사 fail-open 검사는 1차와 같이 유지한다.

## 7. 자율성

## 8. load-bearing 가정

1. 케이스를 키우고 원인·증상을 떨어뜨리면 B의 탐색 비용이 의미 있게 커진다 — 파일럿 게이트로 실증한다.
2. A′ 프롬프트의 카드 경로가 정답 카드를 가리킨다 — oracle-v2 card.txt에서 경로를 읽어 존재를 확인한다.

issue/stockpush/zero-qty-noop
카드: archive-v3/issue/stockpush/zero-qty-noop/ (가상 회사 한빛페이 아카이브, 실행 시 /tmp/cia-lib3/issue 로 복사)
채택 근거: 카드의 규칙 = "stockpush push는 QTY 0 줄을 exit 0·줄 수 포함 그대로 '변경 없음'으로 무시한다. 0으로 내리려면 QTY에 '-'를 보낸다(qty 0·st 2)".
  카드 사건은 창고 이전 기간의 일괄 판매 중지(전 상품을 0으로 전송 → 마켓 주문이 계속 들어와 출고 불가 취소·패널티, 마켓 운영팀 통보로 발견)이고,
  이번 케이스는 포인트몰 일상 동기화에서 품절(출고·예약·실사로 판매 가능 0)된 상품이 마켓에 판매 중으로 남는 것이다.
  같은 블랙박스 규칙·같은 대처(0이면 '-' 전송 + list/show 대사), 다른 서비스·다른 증상.
근본 원인: hbstock/market/feed.py feed_line — 판매 가능 수량 0을 그대로 "0"으로 쓴다. 벤더는 0 줄을 무시해 예전 수량이 판매 중으로 남는다.
올바른 해결: 수량이 0이면 QTY에 "-"를 쓴다(fix.patch: feed.py SOLD_OUT = "-" + feed_line 분기).
증상 파일: hbstock/services/listing.py(마켓 목록·상품 상세·대사 리포트) · tests/test_market_sync.py(E2E). 원인 파일: hbstock/market/feed.py
  (경로: api/handlers.run_sync → services/sync.run → market/feed.build_feed → feed_line → market/client.push → vendor/bin/stockpush).
미끼:
  1) services/sync.py 의 "공지 수량이 안 바뀐 상품은 건너뜀"(last_sent) — 0을 건너뛰는 코드처럼 보이지만 품절 상품은 수량이 바뀌어 전송됨, 무죄. 항상 전체 전송으로 바꿔도 실패.
  2) market/feed.py market_qty 의 CS 보관분(market_safety_stock=1)·0 하한 — 수상한 계산처럼 보이지만 정책대로, 무죄. 0으로 바꾸면 둘 다 실패.
  3) market/feed.py build_feed 의 `if line` 필터 — 파이썬 truthiness 함정처럼 보이지만 문자열 줄이라 0이 걸러지지 않음, 무죄.
  4) market/client.py push 의 줄 수 확인 · rows 의 필드 수/숫자 필터 — 무죄.
  5) util/cache.py TTLCache / 목록 캐시 — 동기화 후 무효화됨, 무죄.
hidden: 다른 카탈로그(시작 수량 0인 예약 상품·CS 보관분만 남는 1개 상품 포함)로 3~4회 동기화하며 출고·예약·실사로 품절 → 입고·예약 취소로 복귀 → 다시 품절,
  전체 재동기화 후 품절, 샘플 카탈로그의 다른 하루를 vendor/bin/stockpush list 로 마켓을 직접 조회해 상품마다 수량 = 판매 가능 수량,
  상태 = 1(양수)/2(0), 목록 API = 마켓 값, 대사 0건을 검사.
  우회 확인: 목록·상세·대사를 로컬 수량으로 덮는 끝단 땜질(test 통과/hidden 실패), 벤더 없이 로컬로 목록 재구현(test 통과/hidden 실패),
  CS 보관분 0 미끼·항상 전체 전송 미끼·캐시/필터 미끼(둘 다 실패), 0 대신 -1 전송(E15, 둘 다 실패), 0 대신 1 전송(둘 다 실패).

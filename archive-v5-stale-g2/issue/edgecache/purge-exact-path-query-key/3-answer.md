# issue/edgecache/purge-exact-path-query-key — 정답

태그: `contract-drift` · `single-source-of-truth`

## 정답
<!-- 질문 1:1 대응 -->

1. **보지 못한다.** 캐시 키에는 쿼리 문자열이 포함되므로 `/terms`와 `/terms?v=app5.2`는 다른 항목이다.\
`purge /terms`는 정확히 `/terms` 키 하나를 지우고 `purged 1`을 돌려준다. 웹뷰 항목은 TTL이 끝날 때까지 남는다.
   > **캐시 키** — CDN이 "같은 요청"을 판정하는 값. 여기서는 호스트+경로+쿼리 전체 문자열이다.

2. **앱 버전마다 쿼리 값이 달라 버전마다 캐시 항목이 따로 있었기 때문이다.**\
최근 며칠 사이 처음 요청된 버전(이번 개정 이후 첫 요청)은 원본에서 새로 받아 새 약관을 봤다. 개정 전에 이미 캐시된 버전은 옛 약관을 봤다.

3. **키는 `host + path + query`, `purge <path>`는 키 정확 일치 1건 삭제다.**\
접두 일치 삭제는 `purge --prefix`로 따로 있다. 벤더 콘솔 도움말에는 "URL 단위 퍼지"라고만 적혀 있다.

4. **캐시 TTL(7일)이 끝날 때까지 보인다.** 기다리면 해결되지만, 약관 개정은 시행일에 맞춰 보여야 해서 기다릴 수 없었다.\
이번 사건은 시행 다음 날 고객 문의로 발견돼 `--prefix` 퍼지로 정리했다.

5. **내용 해시를 URL에 넣는 버저닝**이 낫다 — 내용이 바뀌면 URL이 바뀌므로 퍼지가 필요 없다.\
목록 페이지(HTML)만 짧은 TTL로 두고, 약관 본문은 `/terms/<해시>.html`처럼 바뀌지 않는 URL로 길게 캐시한다.\
쿼리가 내용에 영향을 주지 않는다면 그 경로에서는 캐시 키에서 쿼리를 무시하는 설정도 된다.

6. **실제 사용 URL마다 요청해 응답 헤더를 본다.** `x-cache: MISS` 또는 `Age: 0`이면 새로 받아 온 것이다.\
`purged N`의 N은 지운 키 개수일 뿐 "그 경로의 모든 변형"이 아니다 — 버전 수만큼 나와야 할 때 1이면 남은 항목이 있다는 신호다.

## 문제 구조 (추상화 코드)

### 변형 A — 정확 일치 퍼지
① 문제 코드
```sh
edgecache purge /terms                # 쿼리 붙은 변형은 남음
```
② 고친 코드
```sh
edgecache purge --prefix /terms       # /terms, /terms?v=... 모두
for u in /terms "/terms?v=app5.1" "/terms?v=app5.2"; do
  curl -sI "https://$HOST$u" | grep -iE '^(x-cache|age):'
done
```
무엇이 깨졌나: 퍼지 대상과 실제 캐시 항목의 단위(경로 대 경로+쿼리)가 달랐다.

### 변형 B — 같은 URL로 내용이 바뀌는 정적 자원
① 문제 코드
```html
<a href="/terms?v=app5.2">약관</a>           <!-- 내용이 바뀌어도 URL 그대로 -->
```
② 고친 코드
```html
<a href="/terms/3f9a1c.html">약관</a>        <!-- 내용 해시 URL, 개정 시 링크만 교체 -->
```
무엇이 깨졌나: 캐시 무효화를 퍼지 한 번에 의존했다.

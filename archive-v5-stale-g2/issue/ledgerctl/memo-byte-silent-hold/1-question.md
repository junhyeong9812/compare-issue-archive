# issue/ledgerctl/memo-byte-silent-hold — 원장 CLI는 긴 메모를 거부하지 않고 숨긴다 — 질문

## 질문
1. (예측) `ledgerctl post ... --memo "<한글 22자>"`는 exit 0과 영수 번호 `R…`를 돌려준다. 같은 기간으로 `ledgerctl list`를 돌리면 이 전표가 나오는가? `ledgerctl show <영수번호>`는 무엇을 보여 주는가?
2. (경계) 메모가 ASCII 64자일 때와 65자일 때, 한글 21자일 때와 22자일 때 각각 어떻게 되는가? 경계는 글자 수인가 바이트 수인가, 그리고 정확히 몇인가?
3. (왜) 환불 배치는 메모를 글자 수로 검증하고 있었고 실행 로그·종료 코드·영수 번호까지 모두 정상이었다. 그런데 왜 환불 대사에서 일부 건만 빠졌고, 왜 영문 메모 건은 한 번도 빠지지 않았나?
4. (경계) 메모를 줄이려고 UTF-8 바이트열을 64바이트에서 그냥 잘라 넘기면 무엇이 일어나는가? 올바른 자르기는 무엇을 지켜야 하는가?
5. (왜) 이미 보류된 전표를 같은 참조 번호로 다시 post하면 보류 건은 어떻게 되는가? 대사·재처리 때 무엇을 조심해야 하는가?
6. (연결) "영수 번호를 받았다 = 원장에 기장됐다"로 보면 안 되는 이유는 무엇이고, 배치가 기장 완료를 판정하려면 무엇을 확인해야 하는가?

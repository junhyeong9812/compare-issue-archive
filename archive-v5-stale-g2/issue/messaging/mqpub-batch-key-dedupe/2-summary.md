# issue/messaging/mqpub-batch-key-dedupe — 정리 (힌트)

> 유효: mqpub 2.6.2 — 확인: `mqpub --version`

mqpub 2.6.x 기준.

## 전체 흐름

```
발행 서비스                         mqpub publish (한 배치)                     소비자
  키 = ...M00012345.20240801  ─┐
  키 = ...M00078345.20240801  ─┼─▶ 배치 안에서 키 끝 12바이트 비교
  키 = ...M00090345.20240801  ─┘     "345.20240801" == "345.20240801"
                                       → 첫 메시지만 저장, 나머지 조용히 버림
                                     stdout: accepted 3 batch 7   (요청 건수 그대로)
                                     exit 0, stderr 없음
                                                                         ──▶ 1건만 읽음
  stat: messages +1  (accepted 와 불일치 — 유일한 단서)

규칙
  범위   : publish 1회(=배치 1개) 안에서만. 배치가 다르면 같은 키도 둘 다 저장.
  비교   : 키의 끝 12바이트. 12바이트보다 짧은 키는 키 전체로 비교.
  남는 것: 배치 안에서 먼저 나온 메시지.
  신호   : 없음 — exit 0, accepted = 요청 건수, 벤더 문서·--help 에 언급 없음.

교정
  키 = <논리 키> ":" <전체 논리 키의 결정적 해시 12자>
     → 끝 12바이트가 메시지마다 다르고, 같은 알림은 늘 같은 키(소비자 중복 방지 유지)
     → 배치는 그대로 1회(순서·원자성 유지)
```

## 핵심 문장

- mqpub은 한 배치 안에서 **키의 끝 12바이트**가 같은 메시지를 첫 것만 남기고 버린다 — 오류도, 경고도 없다.
- `accepted N`은 **요청 건수**다 — 저장 건수가 아니다. 저장 확인은 `stat`의 messages 증가분이나 `consume`으로 한다.
- 공통 꼬리(일자·고정 접미)로 끝나는 키는 업무 식별자의 끝 몇 자리만 비교 범위에 남아, 끝자리가 같은 다른 메시지와 서로 덮인다.
- 교정은 **키 끝 12바이트 안에서 메시지가 구별되게** 만드는 것 — 전체 키의 결정적 해시를 맨 끝에 둔다.
- 배치를 쪼개는 것·난수 키는 각각 회차 원자성과 소비자 중복 방지를 깨뜨려 선택하지 않았다.

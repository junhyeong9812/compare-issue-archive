# issue/xferq/name-underscore-silent-park — 정리 (힌트)

> 유효: xferq 2.4.3 — 확인: `xferq --version`

태그: `silent-failure` · `contract-drift`

xferq 2.4.x 기준.

## 전체 흐름

```
배치 ──send --as NAME──▶ xferq ──▶ spool
                           │
   마지막 '_' 필드 ≥ 3 글자 │ st 2 (상대 수신함)  ──▶ ls / pull 에 나온다 → 상대가 받는다
   마지막 '_' 필드 ≤ 2 글자 │ st 6 (묶임)         ──▶ ls / pull 에 안 나온다 → 상대는 모른다
                           │
                           └─ 두 경우 모두: stdout "T0000xxxx", exit 0, stderr 없음
   (마지막 '_' 필드 = 마지막 '_' 뒤부터 확장자 앞까지)

이름 예                                   마지막 필드   결과
  HBP_RECON_K01_20240814.dat               20240814      st 2 (첫 전송)
  HBP_RECON_K01_20240814_R1.dat            R1 (2자)      st 6 (재전송 — 묶임)
  HBPRECONK0120240814ABCDEFGHIJKLMNOP.dat  ('_' 없음)    st 2 (길이 무관)
  A_B_.dat                                 (빈 필드)     st 6 (빈 필드도 짧은 필드)
  HBP_RECON_K01_20240814_R01.dat           R01 (3자)     st 2 (덧붙임을 3자 이상으로)

잘못된 교정: 길이 탓으로 보고 이름을 줄임(HBP_RECON_K01_240814_R1.dat) → 마지막 필드가 R1 그대로라 여전히 st 6, 날짜 형식이 바뀌어 상대 적재기도 못 고른다
올바른 교정: 합의 형식(필드 구분 '_')은 유지, 덧붙이는 표시(재전송·분할 번호 등)는 0을 채워 3자 이상으로 → R1 → R01, 1 → 001
발견 방법:   status <접수번호> 의 마지막 칸 (2=수신함, 6=묶임) · 보낸 이름 vs ls --to <상대> 대조
```

## 핵심 문장

- `xferq send`는 원격 이름의 **마지막 `_` 필드(확장자 앞)가 2자 이하**이면 오류 없이 exit 0·접수 번호를 주고, 전송을 **st 6(묶임)**으로 남긴다 — 상대 수신함(`ls`·`pull`)에 나타나지 않는다.
- 기준은 **이름 길이가 아니라 마지막 필드의 글자 수**다 — 빈 필드(`A_B_.dat`)도 묶인다. `_`가 없는 이름은 해당하지 않는다.
- 대처는 **합의 형식은 그대로 두고, 덧붙이는 부분을 0으로 채워 3자 이상**으로 만드는 것이다(`_R01`, `_001`).
- 접수 번호는 "접수"일 뿐 "전달"이 아니다 — 전달은 `status`의 st 2 또는 `ls --to <상대>`에 이름이 나오는지로 판정한다.
- 묶인 전송은 저절로 풀리지 않는다 — 올바른 이름으로 다시 보내면 새 전송이 생기고 묶인 건은 그대로 남는다(정리는 벤더 창구).

# issue/mtragent/series-cap-new-merchant-blank — 정답

태그: `silent-failure` · `resource-bounding`

## 정답
<!-- 질문 1:1 대응 -->

1. **만들어지지 않는다.** 에이전트는 시리즈 수가 상한에 닿으면 새 라벨 조합의 기록을 버린다.\
애플리케이션의 `inc()` 호출은 정상 반환하고 예외도 없다. 기존 시리즈는 계속 수집된다.
   > **시리즈(time series)** — 메트릭 이름 + 라벨 값 조합 하나. 라벨 값의 가짓수만큼 늘어난다(카디널리티).

2. **상한에 닿은 뒤에 처음 등장한 라벨 값이기 때문이다.** 기존 가맹점은 이미 시리즈가 있어 계속 기록됐다.\
`result` 라벨까지 곱해져 가맹점 약 3,300곳에서 이미 상한에 닿아 있었다.\
신규 가맹점의 승인 실패율 경보는 "데이터 없음"이라 평가 대상에서 빠졌다 — 그 가맹점은 연동 설정 오류로 첫날 승인 실패율이 40%였는데 경보가 없었다.

3. **에이전트 자체 메트릭 `mtragent_dropped_series_total`에만 남는다.** 에이전트 로그에는 아무것도 없다.\
이 메트릭은 수집되고 있었지만 아무 대시보드·경보에도 걸려 있지 않았다.

4. **메모리와 수집 서버 비용이 시리즈 수에 비례해 늘고, 가맹점이 늘면 다시 닿는다.**\
상한을 올리는 것은 시점을 미룰 뿐이다. 수집 서버 쪽 쿼리 비용·저장 비용도 함께 늘어난다.

5. **이벤트(로그·메시지)로 내보내 집계 테이블로 푼다.**\
승인 결과 이벤트에 가맹점 ID를 담아 보내고, 분 단위 집계 작업이 가맹점별 실패율을 계산한다. 경보도 그 집계에서 낸다.\
메트릭 라벨에는 결과·카드사·채널처럼 가짓수가 작고 고정된 값만 둔다.

6. **비어 있음은 "일이 없었다"와 "기록이 버려졌다"를 구별하지 못한다.**\
버림 카운터(`dropped_series_total > 0`)에 경보를 걸고, 주요 대시보드에는 "데이터 없음"을 0과 다르게 표시한다.\
신규 가맹점 입점 체크리스트에 "대시보드 데이터 확인"을 넣었다.

## 문제 구조 (추상화 코드)

### 변형 A — 고카디널리티 라벨
① 문제 코드
```java
counter("pay_approve_total",
        "merchant_id", tx.merchantId(),          // 가맹점 수만큼 시리즈
        "result", tx.result()).increment();
```
② 고친 코드
```java
counter("pay_approve_total",
        "result", tx.result(),
        "acquirer", tx.acquirer()).increment();  // 유한 집합만
events.publish(new ApproveEvent(tx.merchantId(), tx.result(), tx.at()));  // 가맹점별은 이벤트로
```
무엇이 깨졌나: 무한히 늘어나는 값을 상한이 있는 자원(시리즈)에 넣었다 — 상한 도달 후 손실은 조용했다.

### 변형 B — 버림 신호 미감시
① 문제 코드
```yaml
alerts: []                                       # mtragent_dropped_series_total 미사용
```
② 고친 코드
```yaml
alerts:
  - expr: increase(mtragent_dropped_series_total[10m]) > 0
    for: 0m
```
무엇이 깨졌나: 유일한 손실 신호가 수집만 되고 읽히지 않았다.

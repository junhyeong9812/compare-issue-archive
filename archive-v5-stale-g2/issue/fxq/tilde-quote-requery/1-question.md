# issue/fxq/tilde-quote-requery — 환율 CLI의 `~N` 꼬리표는 "그날 값이 아니다"라는 뜻이다 — 질문

> 복습 안내: 질문에 먼저 답해 보고 2-summary(힌트) → 3-answer(정답) 순으로 확인한다.\

## 질문
1. (예측) `fxq rate USDKRW 2025-08-14`(목)는 `USDKRW 2025-08-14 1367.45`를 낸다. 같은 명령을 `2025-08-15`(금)·`08-16`(토)·`08-17`(일)로 돌리면 각각 무엇이 나오는가? 줄 끝의 `~1`·`~2`·`~3`은 무엇을 세는가?
2. (왜) 외화지갑 일일 평가 리포트는 매일 exit 0으로 끝났고 값도 "그럴듯한 환율"이었다. 그런데 왜 8/15~8/17 평가손익만 회계 원장과 어긋났고, 8/14·8/18은 맞았나?
3. (경계) `~N`이 붙는 날은 어떻게 정해지나? 토·일만인가? `DayOfWeek`로 주말만 골라 낸 1차 수정은 왜 8/15(금)에서 또 틀렸나?
4. (예측) `--src N`(usage: `quote source 0..3`)의 0·1·2·3은 영업일과 꼬리표 붙은 날에 각각 무엇을 내나? 평가·정산에 쓸 값은 몇 번이고, 왜 "꼬리표가 안 붙는 소스"면 아무거나 되는 게 아닌가?
5. (경계) 2번 소스 값을 "앞뒤 영업일 평균"이나 "1번과 3번의 평균"으로 직접 계산해 대신할 수 있나?
6. (경계) 앱의 환전 시세 표시 화면도 같은 `fxq rate`를 쓴다. 표시 경로에도 `--src 2`를 붙여야 하나? 정산·평가와 표시는 무엇이 다른가?
7. (연결) 응답 줄을 `split` 후 앞 3칸만 읽는 파서는 왜 이 사고를 못 막았나? 벤더 출력의 "모르는 칸"을 어떻게 다뤄야 하나?
